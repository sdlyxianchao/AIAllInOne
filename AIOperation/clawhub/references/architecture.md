# Platform Architecture Reference

> Generic description, not bound to any specific server IP / hostname / password. All credentials are in `.env` in the deployment directory.

## 1. Deployment Flavors and Directory Layout

The project root maintains three deployment flavors simultaneously, each containing complete orchestration files and documentation:

| Flavor | Directory | Orchestration | Description |
|---|---|---|---|
| Windows single-host | `windows/` | `windows/docker-compose.yml` | Docker Desktop + WSL2, PowerShell scripts, includes a separate Dify compose |
| Linux single-host | `linux/` | `linux/docker-compose.yml` | bash scripts (`health-check.sh`, etc.) |
| Pure Docker orchestration | `docker/` | `docker/docker-compose.yml` | Platform-agnostic generic orchestration |

Inside each deployment directory:
- `scripts/` — Ops scripts (backup / restore / health-check / setup-autostart / ghost series)
- `monitoring/` — Prometheus / Alertmanager / Grafana / Loki / Promtail configuration
- `admin-portal/` — AI Admin Center (`server.js` backend + `public/index.html` frontend)
- `mcp-gateway/` — MCP tool gateway (`gateway.js` + `mcp-servers.json` + `skills/`)
- `dify/` (Windows only) — Dify standalone compose and configuration
- `*-deploy-guide*.md/html` — Deployment guides (include port tables, data flows, license review)
- `*-checklist*.html` — Deployment progress checklists
- `.env` / `.env.windows` — All credentials (**scripts and docs do not hardcode passwords**)

## 2. Core Service List (compose definitions)

| Service | Role | Data |
|---|---|---|
| `keycloak` + `keycloak-db` | Unified authentication SSO / OIDC, AD/LDAP federation | PostgreSQL |
| `new-api` + `new-api-db` + `new-api-redis` | Model gateway: channels / API keys / quotas / audit / cost | MySQL + Redis |
| `litellm` + `litellm-db` + `litellm-redis` | LLM proxy: redaction (Presidio integration), semantic cache | MySQL + Redis |
| `presidio-analyzer` / `presidio-anonymizer` | PII detection and redaction | Stateless |
| `ghost` | Enterprise portal (includes a custom Corp Portal theme) | SQLite |
| `mailhog` | Email testing (development) | None |
| `gitea` + `gitea-runner` | Code hosting + CI/Actions Runner | SQLite |
| `update-server` | DSH Desktop installer hosting and auto-update | Static files + version.txt |
| `admin-session-redis` | Admin Center session storage | Redis |
| `admin-portal` | Unified management portal (AI Admin Center) | None (calls each product's API) |
| `mcp-gateway` | MCP tool gateway (built-in tools + aggregated business MCP + skill marketplace) | JSON config |
| `cadvisor` / `prometheus` / `alertmanager` / `grafana` | Monitoring and alerting | Prometheus TSDB |
| `langfuse` series (postgres/redis/minio/clickhouse/worker) | LLM call observability | PostgreSQL + ClickHouse + MinIO |
| `loki` + `promtail` | Unified log aggregation | Loki storage |

> Dify (AI application platform) is a **standalone compose** (`windows/dify/`); its model providers point to NewAPI and SSO goes through Keycloak.

## 3. Data and State Locations

| Data | Location |
|---|---|
| Business databases | NewAPI → MySQL; Dify → PostgreSQL; Keycloak → PostgreSQL; Langfuse → ClickHouse; LiteLLM → MySQL |
| File-based data | Ghost / Gitea → SQLite files; MinIO (Langfuse objects); Update Server installers |
| Configuration | `.env`, `litellm-config.yaml`, `mcp-servers.json`, `monitoring/*.yml`, compose files |
| Backups | `backups/` in the parent of the deployment directory (`backup_<timestamp>/` directories, auto-retained for N days) |
| Reports | `backups/reports/` (historical reports generated by AI Admin Center) |

## 4. Ops Script List

| Script | Purpose |
|---|---|
| `scripts/backup.ps1` | Full backup: NewAPI MySQL (mysqldump), Dify PostgreSQL (pg_dump), Ghost/Gitea SQLite (copied after WAL checkpoint), config files; auto-cleanup retaining N days |
| `scripts/restore.ps1` | Restore databases and config files from a specified backup directory |
| `scripts/health-check.ps1` (Windows) / `health-check.sh` (Linux) | One-command health check: Docker readiness, container status, HTTP endpoints, internal health, full LLM chain, AD authentication chain, MCP+Skill, DSH Desktop/Dify prerequisites, disk space; produces a 9-stage report |
| `scripts/setup-autostart.ps1` | Register a startup self-check scheduled task (runs the health check after login with a delay) |
| `scripts/ghost-setup.ps1` / `ghost-theme-setup.ps1` / `ghost-activate-theme.js` | Ghost initialization, theme installation and activation |
| `scripts/ghost-content-import.ps1` / `.js` | Import portal sample content (requires the publish URL and language) |
| `scripts/setup-hyperv-dc-network.ps1` | Hyper-V internal switch + domain controller VM network configuration (AD scenario) |
| `publish.ps1` (project root) | Version release: sync + redact + build + commit + push GitHub/Gitee (can tag) |

## 5. Management Entry Point (AI Admin Center)

- Frontend: `admin-portal/public/index.html` (single-file app, includes 9-language i18n and light/dark themes)
- Backend: `admin-portal/server.js` (Express; port / mounted volumes defined by compose; all APIs prefixed with `/api`)
- Authentication: Keycloak OIDC (the `ai-platform-admin` role grants management functions)
- Internal product admins uniformly use `ai_all_in_one_admin` (local admin of each product + Keycloak SSO)

## 6. Documentation Map

- Deployment guides: `<flavor>/*-deploy-guide-v2.md` (or .html / .en.html), include port tables, data flows, license review, AD integration
