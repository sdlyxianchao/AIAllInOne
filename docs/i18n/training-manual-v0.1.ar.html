دليل تدريب AI AllInOne

v0.1 · للمسؤولين والمستخدمين · يغطي «المقدمة ← الإعداد ← إدارة كل أداة ← دليل المستخدم».

📌 هذه هي النسخة v0.1. المنافذ والحسابات تعكس النشر الحالي (مثال IP 192.168.31.117 — استبدله بعنوان IP الخاص بشبكتك الداخلية). الأسرار موجودة في ملف credentials.html المحلي لدى المسؤول.

الفصل الأولمقدمة

1.1 ما هي المنصة

«AI AllInOne» هي منصة ذكاء اصطناعي مؤسسية منشورة على الشبكة الداخلية. تركّز قدرات النماذج اللغوية الكبيرة بحيث يستخدم الموظفون كل شيء بحساب واحد. تنسّق أكثر من اثني عشر منتجاً مفتوح المصدر عبر Docker، مع Keycloak لتوفير الهوية الموحّدة.

  • دخول موحّد: حساب واحد (يمكن ربطه بـ AD) لجميع المنتجات؛
  • بوابة نماذج موحّدة: كل الاستدعاءات تمر عبر NewAPI + LiteLLM مع تدقيق وفوترة وإخفاء تلقائي؛
  • إخفاء PII: إخفاء الهواتف/الهويات/البريد قبل الوصول للنموذج؛
  • تطبيقات ذكاء اصطناعي: Dify لبناء الوكلاء والأسئلة والأجوبة وسير العمل؛
  • الملاحظة والعمليات: مراقبة وتنبيهات وتتبع LLM وسجلات موحّدة ونسخ احتياطي واستعادة واختبارات توفر وتقارير.

1.4 الحساب الموحّد والدخول الموحّد

  • حساب المسؤول الموحّد: ai_all_in_one_admin (كلمة المرور في credentials.html)؛
  • مرتبط بـ AD (LDAP) عبر Keycloak، مع حساب محلي كاحتياط؛
  • Grafana وLangfuse وNewAPI ومركز إدارة AI تستخدم SSO الخاص بـ Keycloak — بعضها بتسجيل دخول تلقائي؛
  • يستخدم الموظفون الحساب الموحّد (أو AD) لـ DeepChat / Dify.
📌 إذا فشل SSO بخطأ unknown_error، فغالباً السبب هو توقف خدمة IP Helper (iphlpsvc) مما يكسر إعادة توجيه منفذ AD (389). كمسؤول: Start-Service iphlpsvc + أعد إضافة قواعد netsh interface portproxy.

الفصل الثانيالإعداد

2.1 ما قبل النشر

  1. تثبيت Docker Desktop (Windows) أو Docker Engine (Linux/عبر الإنترنت) وتشغيله.
  2. تجهيز الشبكة: الوصول إلى سجلات الصور (Docker Hub / quay.io — وإلا فاضبط مرآة مثل DaoCloud) وإلى GitHub؛ حدّد عنوان IP المطلوب كشفه.
  3. (اختياري) تجهيز AD: وحدة تحكم نطاق قابلة للوصول، مع bind DN وكلمة مرور bind وbase DN الخاص بـ LDAP.
  4. تجهيز مفاتيح API للنماذج: DeepSeek / OpenAI / Claude، مفتاح واحد على الأقل.

2.3 Keycloak

Keycloak هو مركز المصادقة، حالياً في وضع الإنتاج (start + PostgreSQL):

  • Realm: enterprise-ai؛
  • الدور: ai-platform-admin؛
  • عملاء OIDC: AI-all-in-one-admin-portal, grafana, langfuse, newapi (كلها confidential)؛
  • الارتباط بـ LDAP: vendor=AD، bind DN بالاسم الشائع الذي يحتوي مسافات (CN=ai all in one admin,CN=Users,DC=chxia,DC=lab).
📌 استخدم scripts/keycloak-realm-init.ps1 لإنشاء realm + العملاء + الدور + ارتباط LDAP دفعة واحدة. المعرّف الداخلي للـ realm هو UUID.

2.4 قنوات LLM

السلسلة: العميل → NewAPI (3000) → LiteLLM (4001) → النموذج الخارجي.

  1. في NewAPI «القنوات»، أنشئ قناة تشير إلى LiteLLM: Base URL http://IP:4001/v1، مع LITELLM_MASTER_KEY؛
  2. اضبط قائمة النماذج في litellm-config.yaml؛
  3. أصدر مفاتيح API (sk-) في NewAPI «الرموز».

2.6 إخفاء PII

طبقتان على وكيل LiteLLM، مع default_on:

  • تعبيرات LiteLLM النمطية: إخفاء الهواتف والهويات والبطاقات والبريد ورموز الائتمان وجوازات السفر وIP + حجب الكلمات الحساسة؛
  • Presidio: كشف الأسماء/البريد/البطاقات (analyzer: 5002, anonymizer: 5001).
⚠️ النطاق: الاستدعاءات المارة عبر LiteLLM فقط؛ لا يخفي البيانات المخزنة مسبقاً في قواعد أخرى.

2.7 المراقبة / السجلات / التنبيهات

  • المراقبة: Prometheus (9091) + Grafana (3030)؛
  • التنبيهات: Alertmanager (9093) → webhook (افتراضياً إلى مركز إدارة AI)؛
  • السجلات: Promtail يجمع → Loki (3110)، صفحة «السجلات الموحّدة»؛
  • التدوير: x-logging عام (10MB × 3).

2.8 النسخ الاحتياطي والاستعادة

scripts/backup.ps1 يعمل يومياً عند 02:00: NewAPI MySQL، Dify PG، SQLite لـ Ghost/Gitea/Grafana، Keycloak (تصدير realm بصيغة JSON)، Langfuse PG، ملفات الإعداد. الاستعادة عبر restore.ps1 أو صفحة «النسخ الاحتياطي والاستعادة».

📌 يجب نسخ Keycloak عبر realm export/import (JSON)، وليس pg_dump وحده. انظر 3.13.

الفصل الثالثالإدارة (دليل لكل أداة)

يغطي كل قسم «كيفية الدخول وماذا تفعل والمهام اليومية». المدخل الموصى به: مركز إدارة AI (:10086).

3.1 Keycloak

المدخل: http://IP:9090 → وحدة التحكم، المستخدم ai_all_in_one_admin.

  • إدارة المستخدمين وإعادة تعيين كلمات المرور ومنح دور ai-platform-admin؛
  • إدارة عملاء OIDC؛
  • عرض/ضبط ارتباط LDAP؛
  • عرض الجلسات وتسجيل الخروج القسري.

3.2 NewAPI

المدخل: http://IP:3000، الحساب الموحّد.

  • القنوات: إدارة القنوات الصاعدة (نحو LiteLLM)؛
  • الرموز: إصدار/تعطيل المفاتيح والحصص والانتهاء؛
  • السجلات: المستخدم/النموذج/الرموز/الحصة/التكلفة/IP لكل استدعاء؛
  • المستخدمون: الشحن ورفع الحدود والحظر.
📌 تسجيل عنوان IP للعميل يعتمد على إعداد «تسجيل سجل IP» (معطّل افتراضياً). فعّله من الإعدادات الشخصية.

3.3 LiteLLM

المدخل: http://IP:4001. الإعداد في litellm-config.yaml.

  • إضافة/إزالة النماذج والمفاتيح؛
  • ضبط حراس PII (التعبيرات النمطية + Presidio)؛
  • إعداد الإبلاغ إلى Langfuse (success_callback).

3.4 Dify

المدخل: http://IP (المنفذ 80)، الحساب الموحّد (البريد admin@company.com).

  • «الاستوديو» — إنشاء التطبيقات (مساعد / وكيل / سير عمل)؛
  • «المعرفة» — رفع المستندات والأسئلة والأجوبة؛
  • إعداد موفّري النماذج (يمكن الإشارة إلى NewAPI/LiteLLM الداخلي)؛
  • إدارة الأعضاء والأذونات والنشر.
📌 Dify هو compose رسمي منفصل (dify/docker/)؛ صِنه من ذلك الدليل.

3.5 Ghost

المدخل: المحتوى http://IP:8090؛ الإدارة http://IP:8090/ghost/.

  • نشر الإعلانات والأخبار؛
  • صيانة الصفحة الرئيسية والتنقل والقالب؛
  • رفع مثبّتات DeepChat وغيرها؛
  • الأعضاء والاشتراكات.

3.6 Gitea

المدخل: http://IP:3002، SSH 2222.

  • إنشاء المستودعات والمنظمات والفرق؛
  • إدارة مشغّلات Actions (deepchat-sync)؛
  • مراجعة الكود والمشكلات والإصدارات.

3.7 MCP Gateway

المدخل: http://IP:3100. الإعداد mcp-gateway/mcp-servers.json.

  • إدارة خوادم MCP / سوق المهارات (skills/)؛
  • إضافة/إزالة اتصالات MCP لـ DeepChat / Dify.

3.8 خادم تحديث DeepChat

المدخل: http://IP:8091؛ البيانات في deepchat-updates/.

  • وضع المثبّتات الجديدة وتحديث version.txt؛
  • سحب تلقائي للإصدارات الرسمية عبر Gitea Actions (deepchat-sync)؛
  • صيانة sync-config.json.
📌 «انتهاء مهلة الاتصال بالنموذج» في DeepChat = غالباً وكيل نظام متوقف (ECONNREFUSED 127.0.0.1:33210). اضبط «بدون وكيل / مباشر» في الإعدادات → الشبكة/الوكيل.

3.9 مركز إدارة AI

المدخل: http://IP:10086، SSO عبر Keycloak. هو بوابة الإدارة الموحّدة:

3.10 المراقبة (Prometheus / Grafana)

المدخل: Grafana http://IP:3030؛ Prometheus http://IP:9091.

  • متابعة CPU/الذاكرة/الشبكة في Grafana؛
  • التحقق من الأهداف والقواعد في Prometheus؛
  • التنبيهات عبر Alertmanager (9093) webhook.

3.11 ملاحظة LLM (Langfuse)

المدخل: http://IP:3010، SSO تلقائي.

⚠️ إذا «لم ترَ بيانات» بعد SSO، فحساب SSO ليس في المنظمة ai-all-in-one. أضف مستخدم SSO إلى المنظمة (دور ADMIN) عبر SQL.

3.12 السجلات الموحّدة (Loki)

المدخل: صفحة «السجلات الموحّدة»، أو Loki http://IP:3110.

📌 تسميات Loki هي container / project / service — لا يوجد job. الاستعلام {container=~".+"}.

3.13 النسخ الاحتياطي والاستعادة

المدخل: صفحة «النسخ الاحتياطي والاستعادة»، أو backup.ps1 / restore.ps1.

⚠️ مآزق حرجة (تم التحقق منها):
  • Keycloak: استخدم realm export/import (JSON)؛ pg_dump يفقد ارتباط الدور الافتراضي؛
  • SQLite المستعاد ملكه root → chown إلى uid الصحيح (grafana=472, gitea=1000)؛
  • pg_dump: أضف --clean --if-exists.

الفصل الرابعدليل المستخدم

4.1 البدء

الخيار أ: DeepChat (للمحادثة اليومية)

  1. افتح http://IP:8090/downloads/ وثبّت العميل؛
  2. DeepChat → الإعدادات → خدمة النموذج → «موفّر مخصص / متوافق مع OpenAI»:
    API Base URL: http://IP:3000/v1
    API Key: خدمة ذاتية من NewAPI (انظر 4.2)
    النموذج: deepseek-chat
  3. احفظ وابدأ المحادثة.

الخيار ب: Dify (بناء التطبيقات / قاعدة المعرفة)

  1. افتح http://IP، الحساب الموحّد؛
  2. «الاستوديو» → إنشاء تطبيق؛
  3. اكتب الموجهات وأرفق قاعدة المعرفة وانشر.

4.2 طلب مفتاح API

  1. افتح NewAPI http://IP:3000؛
  2. «مفاتيح API» → إنشاء رمز؛
  3. انسخ المفتاح sk- إلى DeepChat / Dify.
📌 الحصة محدودة افتراضياً؛ تواصل مع مسؤول لرفعها.

4.3 قواعد أمان البيانات

المنصة تخفي الهواتف والهويات والبطاقات والبريد تلقائياً، لكن التزم:

❌ لا تُرسل أبداً

  • الأسرار الداخلية/السرية (كود غير منشور، أسعار، قوائم عملاء، عقود)؛
  • الخصوصية الشخصية (هويات، بطاقات، كلمات مرور، صحة)؛
  • كود المصدر / التصاميم غير المنشورة.

✅ استخدام آمن

  • مواد عامة ومعرفة عامة وكتابة وترجمة وتلخيص؛
  • بيانات عمل مُخفاة (بعد إزالة الحقول الحساسة).
المستوىنموذج خارجي؟ملاحظات
عام✅ مسموحمنشور بالفعل
داخلي عادي⚠️ بعد الإخفاءمسموح بعد إزالة الحقول الحساسة
داخلي سرّي / شخصي❌ ممنوعلا تُرسل أبداً
القاعدة: «هل ستكون مشكلة لو رآها طرف خارجي؟» إن نعم → لا تُرسلها.

4.5 مدونة السلوك
