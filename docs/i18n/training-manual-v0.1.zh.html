第一章简介

1.1 平台是什么

「AI AllInOne」是一套部署在公司内网的企业 AI 平台，把大模型能力统一收口，员工一个账号即可使用。它把十几个开源产品用 Docker 编排成一个整体，由 Keycloak 提供统一身份认证。

核心能力：

  • 统一登录：一个账号（可对接公司 AD 域账号）登录所有产品；
  • 统一模型网关：所有模型调用经 NewAPI + LiteLLM 收口，自动审计、计费、脱敏；
  • PII 脱敏：手机号/身份证/邮箱等敏感信息在发给大模型前自动打码；
  • AI 应用：Dify 可视化搭建智能体、知识库问答、工作流；
  • 可观测与运维：监控告警、LLM 调用追踪、统一日志、备份恢复、可用性测试、报告生成。

1.4 统一账号与 SSO

平台采用「一个账号登录所有产品」策略：

  • 统一管理员账号：ai_all_in_one_admin（密码见 credentials.html，不在此列出）；
  • 该账号通过 Keycloak 联合到公司 AD 域控（LDAP），也可用本地账号兜底；
  • Grafana、Langfuse、NewAPI、AI 管理中心等均已接入 Keycloak SSO，部分支持自动登录（点链接直进，无需再点「用 Keycloak 登录」按钮）；
  • 员工日常使用 DeepChat / Dify 时，用统一账号（或 AD 域账号）登录。
📌 若 SSO 登录报 unknown_error，通常是宿主机 IP Helper 服务（iphlpsvc）未运行导致 AD 端口转发（389）失效，而非 Keycloak 配置问题。以管理员身份运行：Start-Service iphlpsvc + 重挂 netsh interface portproxy 规则。

第二章配置

2.1 部署前准备

  1. 安装 Docker Desktop（Windows）或 Docker Engine（Linux/线上），并启动。
  2. 准备网络：确保能访问 Docker 镜像仓库（Docker Hub / quay.io，不通则配 DaoCloud 等镜像加速）和 GitHub；确定对外服务的内网 IP。
  3. （可选）准备 AD 域控：如需对接公司域账号，需域控可达，并准备 bind DN、bind 密码、LDAP base DN 等。
  4. 准备模型 API Key：DeepSeek / OpenAI / Claude 等，至少一个。

2.2 环境变量与密钥

核心配置集中在 .env（模板为 .env.example）。关键变量：

变量作用
KEYCLOAK_ADMIN / KEYCLOAK_ADMIN_PASSWORDKeycloak 管理员账号
KEYCLOAK_DB_PASSWORDKeycloak PostgreSQL 密码
NEWAPI_DB_PASSWORD / NEWAPI_SESSION_SECRET / NEWAPI_CRYPTO_SECRETNewAPI 数据库与会话密钥
LITELLM_MASTER_KEYNewAPI 连 LiteLLM 的主密钥
DEEPSEEK_API_KEY 等外部模型密钥
GRAFANA_OAUTH_CLIENT_SECRETGrafana SSO 客户端密钥
LANGFUSE_KEYCLOAK_CLIENT_SECRETLangfuse SSO 客户端密钥
LANGFUSE_PUBLIC_KEY / SECRET_KEYLangfuse 项目密钥（LiteLLM 上报用）
ALERT_WEBHOOK_URL告警通知 webhook（钉钉/企微/飞书或 AI 管理中心）
✅ 一键部署脚本 bootstrap.ps1 会自动替换 IP、生成随机密钥、起容器、初始化 Keycloak、配 NewAPI 渠道、注册备份任务。推荐新机部署优先用它。

2.3 Keycloak 认证配置

Keycloak 是整个平台的认证中枢。当前为生产模式（start + PostgreSQL）。需要配置：

  • Realm：enterprise-ai；
  • 角色：ai-platform-admin（管理员角色）；
  • OIDC Client：AI-all-in-one-admin-portal、grafana、langfuse、newapi（均为 confidential）；
  • LDAP 联邦：vendor=AD，指向域控，bind DN 用带空格的 CN（CN=ai all in one admin,CN=Users,DC=chxia,DC=lab）。
📌 可用 scripts/keycloak-realm-init.ps1 一键建 realm + 客户端 + 角色 + LDAP 联邦（替代手工点 UI）。注意：Keycloak realm 的内部 id 是 UUID，脚本里 LDAP 组件的 parentId 要用真实 id。

2.4 LLM 渠道配置

链路：客户端 → NewAPI（3000）→ LiteLLM（4001）→ 外部模型。

  1. 在 NewAPI 后台「渠道」页新建渠道，指向 LiteLLM：Base URL http://IP:4001/v1，填入 LITELLM_MASTER_KEY；
  2. 在 litellm-config.yaml 中配置模型列表（deepseek-chat 等）与对应 API Key；
  3. NewAPI「令牌」页为员工/应用发放 API Key（sk- 开头）。

2.5 SSO 单点登录

产品方式说明
AI 管理中心OIDC (keycloak-connect)登录自动跳 Keycloak
GrafanaOAuth2 generic OIDCGF_AUTH_OAUTH_AUTO_LOGIN=true 自动登录
LangfuseKeycloak provider入口 /auth/sso-initiate?provider=KEYCLOAK
NewAPIOIDC登录页「一键登录」

2.6 PII 脱敏配置

双保险，均挂在 LiteLLM 代理上，default_on 全量生效：

  • LiteLLM 内置正则：脱敏中文手机号、身份证、银行卡、邮箱、统一信用代码、护照、IP + 敏感词拦截；
  • Presidio：识别英文人名/邮箱/信用卡等（analyzer: 5002，anonymizer: 5001）。
⚠️ 边界：只对「经 LiteLLM 的模型调用」生效，不脱敏其他产品数据库里已存的数据。

2.7 监控 / 日志 / 告警

  • 监控：Prometheus（9091）抓 cadvisor + 各 exporter；Grafana（3030）展示大盘；
  • 告警：Alertmanager（9093）→ webhook（默认发到 AI 管理中心的告警接收端点，可改钉钉/企微/飞书）；
  • 日志：Promtail 采集所有容器日志 → Loki（3110），AI 管理中心「统一日志」页查询；
  • 日志轮转：compose 全局 x-logging（单容器 10MB × 3 份），防止日志无限增长。

2.8 备份与恢复

备份脚本 scripts/backup.ps1 每日 02:00 计划任务运行，覆盖：NewAPI MySQL、Dify PG、Ghost/Gitea/Grafana SQLite、Keycloak（realm export JSON）、Langfuse PG、配置文件。恢复用 scripts/restore.ps1 或 AI 管理中心「备份与恢复」页。

📌 Keycloak 必须用 realm export/import（JSON） 备份，不能只用 pg_dump（会丢 default role 关联）。详见第三章 3.13。

第三章管理（各工具使用说明）

本章逐节介绍每个管理工具「怎么进、能干什么、日常做什么」。统一入口建议用 AI 管理中心（:10086），左侧菜单已内嵌大部分产品。

3.1 Keycloak 管理

入口：http://IP:9090 → Administration Console → 用 ai_all_in_one_admin 登录。

日常做什么：

  • 管理用户、重置密码、分配 ai-platform-admin 角色；
  • 管理 OIDC 客户端（新增产品接 SSO 时在此建 client）；
  • 查看/调整 LDAP 联邦（对接 AD 域账号）；
  • 查看登录会话、强制下线。

3.2 NewAPI 管理

入口：http://IP:3000，用统一账号登录。

日常做什么：

  • 渠道：管理上游模型渠道（指向 LiteLLM），增删模型；
  • 令牌：为员工/应用发放、禁用、设额度、设过期时间的 API Key；
  • 日志：查每次调用的用户/模型/token/额度/成本/来源 IP；
  • 用户：充值额度、提额、封禁。
📌 客户端 IP 记录依赖用户的「记录 IP 日志」设置（默认关闭）。如需按 IP 统计，请在「个人设置」开启，或由管理员统一开启。

3.3 LiteLLM 管理

入口：http://IP:4001（调试用 /v1/models）。配置在 litellm-config.yaml。

日常做什么：

  • 增删模型与对应 API Key；
  • 调整 PII 脱敏 guardrail（正则 + Presidio）；
  • 配置 Langfuse 上报（success_callback）。

3.4 Dify 管理

入口：http://IP（80 端口），用统一账号（邮箱 admin@company.com）登录。

日常做什么：

  • 「工作室」创建应用（聊天助手 / Agent / 工作流）；
  • 「知识库」上传文档、建知识库问答；
  • 模型供应商接入（可指向内部 NewAPI/LiteLLM）；
  • 成员与权限管理、应用发布。
📌 Dify 是独立的官方 compose（dify/docker/），升级/维护时需在 dify/docker 目录单独操作，不在主 compose 里。

3.5 Ghost 管理

入口：内容页 http://IP:8090；后台 http://IP:8090/ghost/。

日常做什么：

  • 发布公告、新闻（Posts）；
  • 维护首页、导航、主题（Attila）；
  • 上传 DeepChat 安装包等下载资源；
  • 成员与订阅（如需）。

3.6 Gitea 管理

入口：http://IP:3002，SSH 端口 2222。

日常做什么：

  • 创建内部代码仓库、组织、团队；
  • 管理 Actions Runner（deepchat-sync 等自动化工作流）；
  • 代码审查、Issue、发布（Release）管理。

3.7 MCP Gateway 管理

入口：http://IP:3100。配置在 mcp-gateway/mcp-servers.json。

日常做什么：

  • 管理 MCP 服务器 / Skill 市场（skills/ 目录）；
  • 增删 MCP 服务连接，供 DeepChat / Dify 调用。

3.8 DeepChat 更新服务器

入口：http://IP:8091（下载页）；数据在 deepchat-updates/。

日常做什么：

  • 放置新版本 DeepChat 安装包（.exe/.dmg），更新 version.txt；
  • 通过 Gitea Actions（deepchat-sync）自动拉取 DeepChat 官方版本；
  • 维护 sync-config.json（版本源、保留份数、市场 URL）。
📌 DeepChat 客户端报「模型连接超时」，通常是客户端走了挂掉的系统代理（ECONNREFUSED 127.0.0.1:33210）。让用户在 DeepChat「设置 → 网络/代理」改为「不使用代理/直连」。

3.9 AI 管理中心

入口：http://IP:10086，用统一账号（Keycloak SSO）登录。

这是统一管理门户，左侧菜单已分组：

分组功能
总览仪表板产品健康、业务指标（调用/成本）、可用性测试汇总

3.10 监控告警（Prometheus / Grafana）

入口：Grafana http://IP:3030（SSO 自动登录）；Prometheus http://IP:9091。

日常做什么：

  • Grafana 大盘看容器 CPU/内存/网络；
  • Prometheus 查 targets 状态、告警规则；
  • 告警经 Alertmanager（9093）发 webhook（默认发 AI 管理中心，可改钉钉/企微/飞书）。

3.11 LLM 可观测（Langfuse）

入口：http://IP:3010，SSO 自动登录。

日常做什么：查看每次模型调用的 prompt、响应、延迟、token、成本，用于质量分析与故障定位。

⚠️ 若用 Keycloak SSO 登录后「看不到数据」，是 SSO 账号未加入组织 ai-all-in-one。需执行 SQL 把 SSO 用户加入组织（ADMIN 角色），详见部署文档踩坑记录。

3.12 统一日志（Loki）

入口：AI 管理中心「统一日志」页（更便捷），或 Loki http://IP:3110。

日常做什么：按容器 + 关键字 + 时间范围检索所有容器日志，排查问题。

📌 Loki 的 label 是 container / project / service，没有 job。查询用 {container=~".+"} 而非 {job="docker"}。

3.13 备份与恢复

入口：AI 管理中心「备份与恢复」页（一键备份/恢复/看状态），或命令行 scripts/backup.ps1 / restore.ps1。

覆盖范围：NewAPI MySQL、Dify PG、Ghost/Gitea/Grafana SQLite、Keycloak（realm JSON）、Langfuse PG、配置文件。

⚠️ 关键坑（演练已验证）：
  • Keycloak 必须用 realm export/import（JSON），pg_dump 还原会丢 default role 关联导致起不来；
  • SQLite 文件还原后属主是 root，需 chown 到对应 uid（grafana=472、gitea=1000）否则报 readonly；
  • pg_dump 需带 --clean --if-exists，否则还原冲突。

第四章普通用户使用说明

4.1 快速上手

方式 A：用 DeepChat（推荐，日常对话）

  1. 打开下载中心 http://IP:8090/downloads/，下载对应系统安装包并安装；
  2. DeepChat → 设置 → 模型服务 → 添加「自定义 Provider / OpenAI 兼容」：
    API Base URL：http://IP:3000/v1
    API Key：NewAPI 后台「API 密钥」页自助申请（见 4.2）
    模型：deepseek-chat
  3. 保存后即可对话。

方式 B：用 Dify（搭建应用 / 知识库）

  1. 浏览器打开 http://IP，用统一账号登录；
  2. 「工作室」→ 创建应用（聊天助手 / Agent / 工作流）；
  3. 编排页面写提示词、接知识库，发布使用。

4.2 API Key 申请

  1. 打开 NewAPI http://IP:3000，用统一账号登录（或 OIDC 一键登录）；
  2. 「API 密钥」→ 新建令牌；
  3. 复制 sk- 开头的 Key，填入 DeepChat / Dify 等客户端。
📌 默认额度有限，不足请联系管理员申请提额。

4.3 数据安全规范

平台已自动对手机号、身份证、银行卡、邮箱等敏感信息脱敏，并对敏感词拦截，但请自觉遵守：

❌ 严禁发送到 AI 的数据

  • 内部机密 / 商业机密（未公开的产品代码、定价、客户名单、合同条款等）；
  • 个人隐私（身份证、银行卡、密码、健康信息、他人隐私）；
  • 源代码 / 未公开技术方案。

✅ 可以放心使用

  • 公开资料、通用知识、文档撰写、翻译、总结；
  • 脱敏后的业务数据（去掉具体人名/号码/敏感字段后）。
数据等级能否上外部大模型说明
公开数据✅ 可以已公开的资料、通用信息
内部普通数据⚠️ 脱敏后可用去掉敏感字段后可使用
内部机密 / 个人隐私❌ 禁止严禁发送
判断原则：「这段内容如果被外人看到会不会有问题？」会 → 别发。

4.4 常见问题

问题解决
登录不上某个产品确认用内网 IP（非 localhost）且用统一账号，仍不行联系管理员
提示额度不足NewAPI 后台查余额；额度用完联系管理员充值/提额
发送内容被拦截命中了敏感词或含敏感信息，按 4.3 规范调整后重试
DeepChat 报连接超时设置 → 网络/代理 → 改为「不使用代理/直连」
模型回复质量差换用不同模型，或优化提问（提供上下文、明确要求）
AI 的回答能信吗不能全信，重要结论务必人工核实（AI 可能幻觉）

4.5 行为准则

  • 不用于违法违规用途，不生成违法、有害、侵权内容；
  • 不绕过平台安全限制，不批量刷额度；
  • 对外发送 AI 生成内容时，核实事实并遵守公司信息发布规范。

有问题联系平台管理员。
