v0.1 · 관리자와 일반 사용자 대상 · 「소개 → 구성 → 도구별 관리 → 사용자 가이드」를 다룹니다.

📌 본 매뉴얼은 v0.1 초판입니다. 포트와 계정은 현재 배포 환경 기준입니다(예시 IP 192.168.31.117을 실제 인트라넷 IP로 바꾸세요). 비밀번호 등 시크릿은 관리자 로컬 credentials.html에 있으며 본 매뉴얼에 기재하지 않습니다.

제1장소개

1.1 플랫폼이란

「AI AllInOne」은 사내 인트라넷에 배포하는 기업용 AI 플랫폼입니다. 대형 모델 기능을 한곳으로 모아 직원이 하나의 계정으로 사용할 수 있습니다. 10여 개 오픈소스 제품을 Docker로 오케스트레이션하며 Keycloak이 통합 인증을 제공합니다.

  • 통합 로그인: 계정 하나(회사 AD 연동 가능)로 모든 제품 로그인;
  • 통합 모델 게이트웨이: 모든 모델 호출이 NewAPI + LiteLLM 경유, 감사·과금·마스킹 자동화;
  • PII 마스킹: 전화번호/신분증/이메일을 모델 전송 전 자동 마스킹;
  • AI 앱: Dify로 에이전트·지식베이스 Q&A·워크플로 구축;
  • 옵저버빌리티와 운영: 모니터링·알림, LLM 추적, 통합 로그, 백업·복원, 가용성 테스트, 보고서 생성.

1.4 통합 계정과 SSO

  • 통합 관리자 계정: ai_all_in_one_admin (비밀번호는 credentials.html);
  • Keycloak을 통해 회사 AD(LDAP)에 연동, 로컬 계정으로 폴백;
  • Grafana, Langfuse, NewAPI, AI 관리 센터는 Keycloak SSO 사용, 일부는 자동 로그인;
  • 직원은 DeepChat / Dify에서 통합 계정(또는 AD 계정) 사용.
📌 SSO 로그인 시 unknown_error가 나면 대부분 호스트의 IP Helper 서비스(iphlpsvc) 미실행으로 AD 포트 포워딩(389)이 깨진 것입니다. 관리자로 Start-Service iphlpsvc + netsh interface portproxy 규칙을 다시 추가하세요.

제2장구성

2.1 배포 전 준비

  1. Docker Desktop(Windows) 또는 Docker Engine(Linux/온라인) 설치 및 시작.
  2. 네트워크 준비: Docker 이미지 레지스트리(Docker Hub / quay.io, 안 되면 DaoCloud 등 미러)와 GitHub 접근 확보, 노출할 인트라넷 IP 결정.
  3. (선택) AD 준비: 도메인 컨트롤러 접근 가능, bind DN·bind 비밀번호·LDAP base DN 준비.
  4. 모델 API 키 준비: DeepSeek / OpenAI / Claude 등 최소 1개.

2.2 환경 변수와 시크릿

설정은 .env에 집중(템플릿 .env.example). 주요 변수:

변수역할
KEYCLOAK_ADMIN / KEYCLOAK_ADMIN_PASSWORDKeycloak 관리자 계정
KEYCLOAK_DB_PASSWORDKeycloak PostgreSQL 비밀번호
NEWAPI_DB_PASSWORD / NEWAPI_SESSION_SECRET / NEWAPI_CRYPTO_SECRETNewAPI DB 및 세션 키
LITELLM_MASTER_KEYNewAPI → LiteLLM 마스터 키
DEEPSEEK_API_KEY 등외부 모델 키

LANGFUSE_PUBLIC_KEY / SECRET_KEYLangfuse 프로젝트 키

✅ 원클릭 배포 스크립트 bootstrap.ps1이 IP 치환·시크릿 생성·컨테이너 시작·Keycloak 초기화·NewAPI 채널 설정·백업 작업 등록을 자동 수행합니다. 신규 배포 시 우선 사용하세요.

2.3 Keycloak

Keycloak은 인증의 중심이며 현재 프로덕션 모드(start + PostgreSQL)입니다:

  • Realm: enterprise-ai;
  • 역할: ai-platform-admin;
  • OIDC 클라이언트: AI-all-in-one-admin-portal, grafana, langfuse, newapi (모두 confidential);
  • LDAP 연동: vendor=AD, bind DN은 공백 포함 CN(CN=ai all in one admin,CN=Users,DC=chxia,DC=lab).
📌 scripts/keycloak-realm-init.ps1로 realm + 클라이언트 + 역할 + LDAP 연동을 일괄 생성할 수 있습니다. realm 내부 id는 UUID이며 LDAP 컴포넌트의 parentId에 사용합니다.

2.4 LLM 채널

경로: 클라이언트 → NewAPI(3000) → LiteLLM(4001) → 외부 모델.

  1. NewAPI 「채널」에서 LiteLLM을 가리키는 채널 생성: Base URL http://IP:4001/v1, LITELLM_MASTER_KEY 입력;
  2. litellm-config.yaml에 모델 목록 설정;
  3. NewAPI 「토큰」에서 API 키(sk-) 발급.

2.5 SSO

제품방식비고

2.6 PII 마스킹

LiteLLM 프록시 위 2중, default_on 전체 적용:

  • LiteLLM 내장 정규식: 전화번호·신분증·은행카드·이메일·신용코드·여권·IP 마스킹 + 민감어 차단;
  • Presidio: 인명/이메일/카드 감지(analyzer: 5002, anonymizer: 5001).
⚠️ 범위: LiteLLM 경유 모델 호출에만 적용, 타 제품 DB의 기존 데이터는 마스킹하지 않습니다.

2.7 모니터링 / 로그 / 알림

  • 모니터링: Prometheus(9091) + Grafana(3030);
  • 알림: Alertmanager(9093) → webhook(기본 AI 관리 센터);
  • 로그: Promtail 수집 → Loki(3110), 「통합 로그」페이지;
  • 로그 로테이션: 전역 x-logging(10MB × 3).

2.8 백업과 복원

scripts/backup.ps1이 매일 02:00 실행: NewAPI MySQL, Dify PG, Ghost/Gitea/Grafana SQLite, Keycloak(realm export JSON), Langfuse PG, 설정 파일. 복원은 restore.ps1 또는 「백업과 복원」페이지.

📌 Keycloak은 realm export/import(JSON)로 백업해야 합니다(pg_dump 단독 불가). 3.13 참조.

제3장관리 (도구별 안내)

각 절에서 「진입 방법·할 수 있는 일·일상 업무」를 설명합니다. 권장 통합 진입점은 AI 관리 센터(:10086).

3.1 Keycloak

진입: http://IP:9090 → 콘솔, ai_all_in_one_admin 로그인.

  • 사용자 관리, 비밀번호 재설정, ai-platform-admin 역할 부여;
  • OIDC 클라이언트 관리;
  • LDAP 연동 확인·조정;
  • 세션 확인, 강제 로그아웃.

3.2 NewAPI

진입: http://IP:3000, 통합 계정.

  • 채널: 상위 모델 채널 관리;
  • 토큰: 키 발급/비활성화, 할당량, 만료;
  • 로그: 호출별 사용자/모델/토큰/할당량/비용/출처 IP;
  • 사용자: 충전, 한도 상향, 차단.
📌 클라이언트 IP 기록은 사용자의 「IP 로그 기록」 설정에 의존(기본 꺼짐). 「개인 설정」에서 활성화.

3.3 LiteLLM

진입: http://IP:4001. 설정은 litellm-config.yaml.

  • 모델 및 키 추가/삭제;
  • PII 가드레일 조정(정규식 + Presidio);
  • Langfuse 리포트 설정(success_callback).

3.4 Dify

진입: http://IP(80 포트), 통합 계정(이메일 admin@company.com).

  • 「스튜디오」에서 앱 생성(챗 어시스턴트 / 에이전트 / 워크플로);
  • 「지식」에서 문서 업로드·Q&A;
  • 모델 프로바이더 설정(내부 NewAPI/LiteLLM 지정 가능);
  • 멤버·권한 관리, 앱 게시.
📌 Dify는 별도 공식 compose(dify/docker/)입니다. 업그레이드/유지보수는 해당 디렉터리에서 수행.

3.5 Ghost

진입: 콘텐츠 http://IP:8090, 관리 http://IP:8090/ghost/.

  • 공지·뉴스 게시;
  • 홈페이지·내비게이션·테마 유지;
  • DeepChat 설치 프로그램 등 업로드;
  • 멤버·구독.

3.6 Gitea

진입: http://IP:3002, SSH 2222.

  • 리포지토리·조직·팀 생성;
  • Actions 러너 관리(deepchat-sync);
  • 코드 리뷰, 이슈, 릴리스.

3.7 MCP Gateway

진입: http://IP:3100. 설정 mcp-gateway/mcp-servers.json.

  • MCP 서버 / 스킬 마켓 관리(skills/);
  • DeepChat / Dify용 MCP 연결 추가/삭제.

3.8 DeepChat 업데이트 서버

진입: http://IP:8091, 데이터는 deepchat-updates/.

  • 신버전 설치 프로그램 배치, version.txt 갱신;
  • Gitea Actions(deepchat-sync)로 공식 버전 자동 수집;
  • sync-config.json 유지.
📌 DeepChat 「모델 연결 타임아웃」은 대부분 죽은 시스템 프록시(ECONNREFUSED 127.0.0.1:33210) 경유입니다. 「설정 → 네트워크/프록시」를 「프록시 없음 / 직접 연결」로 변경하세요.

3.10 모니터링 (Prometheus / Grafana)

진입: Grafana http://IP:3030, Prometheus http://IP:9091.

  • Grafana에서 CPU/메모리/네트워크 확인;
  • Prometheus에서 타깃·알림 규칙 확인;
  • 알림은 Alertmanager(9093) webhook 경유.

3.11 LLM 옵저버빌리티 (Langfuse)

진입: http://IP:3010, SSO 자동 로그인.

⚠️ SSO 로그인 후 「데이터가 안 보이면」 SSO 계정이 조직 ai-all-in-one에 없습니다. SQL로 SSO 사용자를 조직(ADMIN 역할)에 추가하세요.

3.12 통합 로그 (Loki)

진입: 「통합 로그」페이지, 또는 Loki http://IP:3110.

📌 Loki 라벨은 container / project / service이며 job은 없습니다. 쿼리는 {container=~".+"}.

3.13 백업과 복원

진입: 「백업과 복원」페이지, 또는 backup.ps1 / restore.ps1.

⚠️ 중요 주의(검증됨):
  • Keycloak은 realm export/import(JSON) 사용(pg_dump는 기본 역할 연결 손실);
  • SQLite 복원 후 root 소유 → 올바른 uid로 chown(grafana=472, gitea=1000);
  • pg_dump에 --clean --if-exists 추가.

제4장일반 사용자 가이드

4.1 시작하기

방법 A: DeepChat (일상 대화에 권장)

  1. http://IP:8090/downloads/에서 클라이언트 설치;
  2. DeepChat → 설정 → 모델 서비스 → 「사용자 지정 Provider / OpenAI 호환」:
    API Base URL: http://IP:3000/v1
    API Key: NewAPI에서 셀프 신청(4.2 참조)
    모델: deepseek-chat
  3. 저장 후 대화 시작.

방법 B: Dify (앱 / 지식베이스 구축)

  1. http://IP 열고 통합 계정 로그인;
  2. 「스튜디오」→ 앱 생성;
  3. 프롬프트 작성, 지식베이스 연결, 게시.

4.2 API 키 신청

  1. NewAPI http://IP:3000 열기;
  2. 「API 키」→ 토큰 생성;
  3. sk- 키를 DeepChat / Dify에 입력.
📌 기본 할당량은 제한적입니다. 부족 시 관리자에게 신청.

4.3 데이터 보안 규칙

플랫폼이 전화번호·신분증·은행카드·이메일을 자동 마스킹하지만 다음을 준수하세요:

❌ 전송 금지

✅ 안전하게 사용 가능
