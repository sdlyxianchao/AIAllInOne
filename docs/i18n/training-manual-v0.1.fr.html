Chapitre 1Introduction

1.1 Qu'est-ce que la plateforme

« AI AllInOne » est une plateforme d'IA d'entreprise déployée sur l'intranet. Elle centralise les capacités LLM pour que les employés puissent tout utiliser avec un seul compte. Elle orchestre plus d'une douzaine de produits open source avec Docker, Keycloak fournissant l'identité unifiée.

Capacités principales :

  • Connexion unifiée : un compte (optionnellement fédéré à l'AD) pour tous les produits ;
  • Passerelle modèle unifiée : tous les appels passent par NewAPI + LiteLLM, avec audit, facturation et masquage automatiques ;
  • Masquage PII : téléphones/identifiants/e-mails masqués avant d'atteindre le modèle ;
  • Apps IA : Dify pour créer agents, Q&A sur base de connaissances et workflows ;
  • Observabilité & ops : supervision/alertes, traçage LLM, logs unifiés, sauvegarde/restauration, tests de disponibilité, génération de rapports.

1.4 Compte unifié & SSO

  • Compte admin unifié : ai_all_in_one_admin (mot de passe dans credentials.html) ;
  • Fédéré à l'AD (LDAP) via Keycloak, avec compte local en secours ;
  • Grafana, Langfuse, NewAPI et l'AI Admin Center utilisent le SSO Keycloak — certains en connexion auto ;
  • Les employés utilisent le compte unifié (ou AD) pour DeepChat / Dify.
📌 Si le SSO échoue avec unknown_error, c'est souvent le service IP Helper (iphlpsvc) arrêté qui casse le transfert de port AD (389). En admin : Start-Service iphlpsvc + ré-ajoutez les règles netsh interface portproxy.

Chapitre 2Configuration

2.1 Pré-déploiement

  1. Installer Docker Desktop (Windows) ou Docker Engine (Linux/online), et le démarrer.
  2. Préparer le réseau : accès aux registres d'images (Docker Hub / quay.io — sinon configurer un miroir type DaoCloud) et à GitHub ; décider de l'IP intranet à exposer.
  3. (Optionnel) Préparer l'AD : contrôleur de domaine joignable, bind DN, mot de passe bind, base DN LDAP.
  4. Préparer les clés API de modèles : DeepSeek / OpenAI / Claude, au moins une.

2.2 Variables d'env & secrets

2.3 Keycloak

Keycloak est le hub d'auth, actuellement en mode production (start + PostgreSQL). Configurez :

  • Realm : enterprise-ai ;
  • Rôle : ai-platform-admin ;
  • Clients OIDC : AI-all-in-one-admin-portal, grafana, langfuse, newapi (confidentiels) ;
  • Fédération LDAP : vendor=AD, bind DN avec le CN à espaces (CN=ai all in one admin,CN=Users,DC=chxia,DC=lab).
📌 Utilisez scripts/keycloak-realm-init.ps1 pour créer realm + clients + rôle + fédération LDAP en une fois. L'id interne du realm est un UUID, à utiliser comme parentId LDAP.

2.4 Canaux LLM

Chaîne : client → NewAPI (3000) → LiteLLM (4001) → modèle externe.

  1. Dans NewAPI « Canaux », pointez un canal vers LiteLLM : Base URL http://IP:4001/v1, avec LITELLM_MASTER_KEY ;
  2. Configurez la liste des modèles (deepseek-chat, etc.) dans litellm-config.yaml ;
  3. Émettez des clés API (sk-) dans NewAPI « Jetons ».

2.6 Masquage PII

Deux couches, sur le proxy LiteLLM, avec default_on :

  • Regex LiteLLM : masque téléphones, identifiants, cartes bancaires, e-mails, codes de crédit, passeports, IP + blocage de mots sensibles ;
  • Presidio : détecte noms/e-mails/cartes (analyzer : 5002, anonymizer : 5001).
⚠️ Portée : uniquement les appels passant par LiteLLM ; ne masque pas les données déjà stockées ailleurs.

2.7 Supervision / logs / alertes

  • Supervision : Prometheus (9091) scrape cadvisor + exporters ; Grafana (3030) ;
  • Alertes : Alertmanager (9093) → webhook (par défaut vers AI Admin Center) ;
  • Logs : Promtail collecte → Loki (3110), page « Logs unifiés » ;
  • Rotation : x-logging global (10 Mo × 3).

2.8 Sauvegarde & restauration

scripts/backup.ps1 s'exécute à 02:00 : NewAPI MySQL, Dify PG, SQLite Ghost/Gitea/Grafana, Keycloak (export realm JSON), Langfuse PG, fichiers de config. Restauration via restore.ps1 ou la page « Sauvegarde & restauration ».

📌 Keycloak doit être sauvegardé via realm export/import (JSON), pas pg_dump seul. Voir 3.13.

Chapitre 3Administration (guide par outil)

Chaque section couvre « comment entrer, quoi faire, tâches quotidiennes ». Entrée recommandée : AI Admin Center (:10086).

3.1 Keycloak

Entrée : http://IP:9090 → console, connexion ai_all_in_one_admin.

  • Gérer utilisateurs, réinitialiser mots de passe, attribuer le rôle ai-platform-admin ;
  • Gérer les clients OIDC ;
  • Voir/ajuster la fédération LDAP ;
  • Voir les sessions et forcer la déconnexion.

3.2 NewAPI

Entrée : http://IP:3000, compte unifié.

  • Canaux : gérer les canaux amont (vers LiteLLM) ;
  • Jetons : émettre/désactiver des clés, quotas, expiration ;
  • Logs : utilisateur/modèle/tokens/quota/coût/IP source par appel ;
  • Utilisateurs : recharger, augmenter les limites, bannir.
📌 L'enregistrement de l'IP client dépend du réglage « Enregistrer le journal IP » (désactivé par défaut). Activez-le dans les Paramètres personnels.

3.3 LiteLLM

Entrée : http://IP:4001. Config dans litellm-config.yaml.

  • Ajouter/supprimer modèles et clés ;
  • Ajuster les guardrails PII (regex + Presidio) ;
  • Configurer le reporting Langfuse (success_callback).

3.4 Dify

Entrée : http://IP (port 80), compte unifié (e-mail admin@company.com).

  • « Studio » — créer des apps (assistant / agent / workflow) ;
  • « Connaissances » — importer des documents, Q&A ;
  • Configuration des fournisseurs de modèles ;
  • Gestion des membres et publication.
📌 Dify est un compose officiel séparé (dify/docker/) ; maintenez-le depuis ce répertoire.

3.5 Ghost

Entrée : contenu http://IP:8090 ; admin http://IP:8090/ghost/.

  • Publier annonces et actualités ;
  • Maintenir la page d'accueil, la navigation, le thème ;
  • Importer les installeurs DeepChat ;
  • Membres et abonnements.

3.6 Gitea

Entrée : http://IP:3002, SSH 2222.

  • Créer dépôts, organisations, équipes ;
  • Gérer les runners Actions (deepchat-sync) ;
  • Revue de code, issues, releases.

3.7 MCP Gateway

Entrée : http://IP:3100. Config mcp-gateway/mcp-servers.json.

  • Gérer serveurs MCP / marché Skill (skills/) ;
  • Ajouter/supprimer des connexions MCP pour DeepChat / Dify.

3.8 Serveur de mise à jour DeepChat

Entrée : http://IP:8091 ; données dans deepchat-updates/.

  • Déposer les nouveaux installeurs (.exe/.dmg) et mettre à jour version.txt ;
  • Récupération auto des versions officielles via Gitea Actions (deepchat-sync) ;
  • Maintenir sync-config.json.
📌 « Délai de connexion au modèle » dans DeepChat = souvent un proxy système mort (ECONNREFUSED 127.0.0.1:33210). Réglez « Pas de proxy / Direct » dans Paramètres → Réseau/Proxy.

3.10 Supervision (Prometheus / Grafana)

Entrée : Grafana http://IP:3030 ; Prometheus http://IP:9091.

  • Suivre CPU/mémoire/réseau dans Grafana ;
  • Vérifier les cibles et règles dans Prometheus ;
  • Alertes via Alertmanager (9093) webhook.

3.11 Observabilité LLM (Langfuse)

Entrée : http://IP:3010, SSO auto.

Tâches : inspecter prompt, réponse, latence, tokens, coût de chaque appel.

⚠️ Si « aucune donnée » après connexion SSO, le compte SSO n'est pas dans l'org ai-all-in-one. Ajoutez l'utilisateur SSO à l'org (rôle ADMIN) en SQL.

3.12 Logs unifiés (Loki)

Entrée : page « Logs unifiés » (plus simple), ou Loki http://IP:3110.

📌 Les labels Loki sont container / project / service — pas de job. Requête {container=~".+"}.

3.13 Sauvegarde & restauration

Entrée : page « Sauvegarde & restauration » ou backup.ps1 / restore.ps1.

⚠️ Pièges (vérifiés) :
  • Keycloak : utiliser realm export/import (JSON) ; pg_dump perd l'association du rôle par défaut ;
  • SQLite restauré en root → chown vers le bon uid (grafana=472, gitea=1000) ;
  • pg_dump : ajouter --clean --if-exists.

Chapitre 4Guide utilisateur

4.1 Démarrage

Option A : DeepChat (chat quotidien)

  1. Ouvrir http://IP:8090/downloads/ et installer le client ;
  2. DeepChat → Paramètres → Service modèle → « Provider personnalisé / compatible OpenAI » :
    API Base URL : http://IP:3000/v1
    API Key : auto-service dans NewAPI (voir 4.2)
    Modèle : deepseek-chat
  3. Enregistrer et discuter.

Option B : Dify (apps / base de connaissances)

  1. Ouvrir http://IP, connexion compte unifié ;
  2. « Studio » → créer une app ;
  3. Écrire les prompts, attacher la base de connaissances, publier.

4.2 Demande de clé API

  1. Ouvrir NewAPI http://IP:3000 ;
  2. « Clés API » → créer un jeton ;
  3. Copier la clé sk- dans DeepChat / Dify.
📌 Quota limité par défaut ; contactez un admin pour l'augmenter.

4.3 Règles de sécurité des données

La plateforme masque automatiquement téléphones, identifiants, cartes bancaires, e-mails, mais veuillez respecter :

❌ Ne jamais envoyer

  • Secrets internes/confidentiels (code non publié, prix, listes clients, contrats) ;
  • Vie privée (identifiants, cartes, mots de passe, santé) ;
  • Code source / conceptions non publiées.

✅ Sans risque

  • Matériel public, connaissances générales, rédaction, traduction, résumé ;
  • Données métier masquées (après retrait des champs sensibles).
NiveauModèle externe ?Notes
Public✅ OKDéjà public
Interne ordinaire⚠️ après masquageOK une fois les champs sensibles retirés
Interne confidentiel / personnel❌ InterditNe jamais envoyer
Règle : « Serait-ce un problème si un tiers voyait ceci ? » Si oui → ne pas envoyer.

4.5 Code de conduite

  • Pas d'usage illégal ou nuisible ; pas de contenu illégal, nuisible ou contrefait ;
  • Ne pas contourner la sécurité ni épuiser le quota en masse ;
  • Vérifier les faits avant de partager du contenu généré en externe.

Contactez l'admin de la plateforme pour toute question.
