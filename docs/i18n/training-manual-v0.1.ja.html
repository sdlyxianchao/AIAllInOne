AI AllInOne トレーニングマニュアル

v0.1 · 管理者・一般ユーザー向け · 「はじめに → 設定 → ツール別管理 → ユーザーガイド」をカバー。

📌 これは v0.1 初版です。ポートとアカウントは現在のデプロイ環境に準拠します（例の IP 192.168.31.117 は実際のイントラネット IP に置き換えてください）。シークレットは管理者ローカルの credentials.html にあり、本マニュアルには記載しません。

第1章はじめに

1.1 プラットフォームとは

「AI AllInOne」は社内イントラネットにデプロイするエンタープライズ AI プラットフォームです。大規模モデルの能力を一元化し、従業員は1 つのアカウントですべてを利用できます。十数個のオープンソース製品を Docker でオーケストレーションし、Keycloak が統合認証を提供します。

  • 統合ログイン：1 アカウント（社内 AD 連携可）で全製品にログイン；
  • 統合モデルゲートウェイ：全モデル呼び出しは NewAPI + LiteLLM 経由、監査・課金・マスキングを自動化；
  • PII マスキング：電話番号/ID/メールなどをモデル送信前に自動マスク；
  • AI アプリ：Dify でエージェント・ナレッジベース Q&A・ワークフローを構築；
  • 可観測性と運用：監視アラート、LLM トレース、統合ログ、バックアップ/リストア、可用性テスト、レポート生成。

1.4 統合アカウントと SSO

  • 統合管理者アカウント：ai_all_in_one_admin（パスワードは credentials.html）；
  • Keycloak 経由で社内 AD（LDAP）にフェデレーション、ローカルアカウントでフォールバック；
  • Grafana、Langfuse、NewAPI、AI 管理センターは Keycloak SSO を利用、一部は自動ログイン対応；
  • 従業員は DeepChat / Dify で統合アカウント（または AD アカウント）を使用。
📌 SSO が unknown_error になる場合、多くはホストの IP Helper サービス（iphlpsvc）停止により AD ポート転送（389）が壊れています。管理者として Start-Service iphlpsvc + netsh interface portproxy ルールを再追加してください。

第2章設定

2.1 デプロイ前の準備

  1. Docker Desktop（Windows）または Docker Engine（Linux/オンライン）をインストールして起動。
  2. ネットワーク準備：Docker イメージレジストリ（Docker Hub / quay.io、不通なら DaoCloud 等のミラー）と GitHub へのアクセスを確保。公開するイントラネット IP を決定。
  3. （任意）AD 準備：ドメインコントローラーに到達可能で、bind DN・bind パスワード・LDAP base DN を用意。
  4. モデル API キー準備：DeepSeek / OpenAI / Claude など、最低 1 つ。

2.2 環境変数とシークレット

設定は .env（テンプレート .env.example）に集約。主要な変数：

変数役割
KEYCLOAK_ADMIN / KEYCLOAK_ADMIN_PASSWORDKeycloak 管理者アカウント
KEYCLOAK_DB_PASSWORDKeycloak PostgreSQL パスワード
NEWAPI_DB_PASSWORD / NEWAPI_SESSION_SECRET / NEWAPI_CRYPTO_SECRETNewAPI DB とセッションキー
LITELLM_MASTER_KEYNewAPI → LiteLLM マスターキー

✅ ワンクリックデプロイスクリプト bootstrap.ps1 が IP 置換・シークレット生成・コンテナ起動・Keycloak 初期化・NewAPI チャネル設定・バックアップタスク登録を自動実行します。新規デプロイではこれを優先してください。

2.3 Keycloak

Keycloak は認証の中枢で、現在本番モード（start + PostgreSQL）です：

  • Realm：enterprise-ai；
  • ロール：ai-platform-admin；
  • OIDC クライアント：AI-all-in-one-admin-portal、grafana、langfuse、newapi（すべて confidential）；
  • LDAP フェデレーション：vendor=AD、bind DN はスペース入り CN（CN=ai all in one admin,CN=Users,DC=chxia,DC=lab）。
📌 scripts/keycloak-realm-init.ps1 で realm + クライアント + ロール + LDAP フェデレーションを一括作成できます。realm の内部 id は UUID で、LDAP コンポーネントの parentId に使います。

2.4 LLM チャネル

経路：クライアント → NewAPI（3000）→ LiteLLM（4001）→ 外部モデル。

  1. NewAPI「チャネル」で LiteLLM を指すチャネルを作成：Base URL http://IP:4001/v1、LITELLM_MASTER_KEY を入力；
  2. litellm-config.yaml にモデルリストを設定；
  3. NewAPI「トークン」で API キー（sk-）を発行。

2.6 PII マスキング

LiteLLM プロキシ上に 2 層、default_on で全量有効：

  • LiteLLM 内蔵正規表現：電話番号・ID・銀行カード・メール・クレジットコード・パスポート・IP をマスク + センシティブワード遮断；
  • Presidio：人名/メール/カードを検出（analyzer: 5002、anonymizer: 5001）。
⚠️ 対象範囲：LiteLLM 経由のモデル呼び出しのみ。他製品 DB に既存のデータはマスクしません。

2.7 監視 / ログ / アラート

  • 監視：Prometheus（9091）+ Grafana（3030）；
  • アラート：Alertmanager（9093）→ webhook（既定は AI 管理センター）；
  • ログ：Promtail 収集 → Loki（3110）、「統合ログ」ページ；
  • ログローテーション：グローバル x-logging（10MB × 3）。

2.8 バックアップとリストア

scripts/backup.ps1 が毎日 02:00 に実行：NewAPI MySQL、Dify PG、Ghost/Gitea/Grafana SQLite、Keycloak（realm export JSON）、Langfuse PG、設定ファイル。リストアは restore.ps1 または「バックアップとリストア」ページ。

📌 Keycloak は realm export/import（JSON） でバックアップする必要があります（pg_dump 単独は不可）。3.13 参照。

第3章管理（ツール別ガイド）

各節で「入り方・できること・日常業務」を説明。推奨の統合入口は AI 管理センター（:10086）。

3.1 Keycloak

入口：http://IP:9090 → コンソール、ai_all_in_one_admin でログイン。

  • ユーザー管理、パスワードリセット、ai-platform-admin ロール付与；
  • OIDC クライアント管理；
  • LDAP フェデレーションの確認・調整；
  • セッション確認、強制ログアウト。

3.2 NewAPI

入口：http://IP:3000、統合アカウント。

  • チャネル：上流モデルチャネル管理；
  • トークン：キー発行/無効化、クォータ、有効期限；
  • ログ：呼び出しごとのユーザー/モデル/token/クォータ/コスト/送信元 IP；
  • ユーザー：チャージ、上限引き上げ、BAN。
📌 クライアント IP 記録はユーザーの「IP ログ記録」設定依存（既定オフ）。「個人設定」で有効化。

3.3 LiteLLM

入口：http://IP:4001。設定は litellm-config.yaml。

  • モデルとキーの追加/削除；
  • PII ガードレール調整（正規表現 + Presidio）；
  • Langfuse レポート設定（success_callback）。

3.4 Dify

入口：http://IP（80 ポート）、統合アカウント（メール admin@company.com）。

  • 「スタジオ」でアプリ作成（チャットアシスタント / エージェント / ワークフロー）；
  • 「ナレッジ」でドキュメントアップロード・Q&A；
  • モデルプロバイダー設定（内部 NewAPI/LiteLLM を指定可）；
  • メンバー・権限管理、アプリ公開。
📌 Dify は別の公式 compose（dify/docker/）です。アップグレード/保守はそのディレクトリで行います。

3.5 Ghost

入口：コンテンツ http://IP:8090、管理 http://IP:8090/ghost/。

  • お知らせ・ニュース公開；
  • トップページ・ナビ・テーマ維持；
  • DeepChat インストーラー等のアップロード；
  • メンバー・購読。

3.6 Gitea

入口：http://IP:3002、SSH 2222。

  • リポジトリ・組織・チーム作成；
  • Actions ランナー管理（deepchat-sync）；
  • コードレビュー、Issue、リリース。

3.7 MCP Gateway

入口：http://IP:3100。設定 mcp-gateway/mcp-servers.json。

  • MCP サーバー / Skill マーケット管理（skills/）；
  • DeepChat / Dify 向け MCP 接続の追加/削除。

3.8 DeepChat 更新サーバー

入口：http://IP:8091、データは deepchat-updates/。

  • 新バージョンのインストーラー配置、version.txt 更新；
  • Gitea Actions（deepchat-sync）で公式版を自動取得；
  • sync-config.json の維持。
📌 DeepChat の「モデル接続タイムアウト」は、多くが停止したシステムプロキシ（ECONNREFUSED 127.0.0.1:33210）経由です。「設定 → ネットワーク/プロキシ」を「プロキシなし / 直接」に変更してください。

3.10 監視（Prometheus / Grafana）

入口：Grafana http://IP:3030、Prometheus http://IP:9091。

  • Grafana で CPU/メモリ/ネットワーク確認；
  • Prometheus でターゲット・アラートルール確認；
  • アラートは Alertmanager（9093）webhook 経由。

3.11 LLM 可観測性（Langfuse）

入口：http://IP:3010、SSO 自動ログイン。

⚠️ SSO ログイン後に「データが見えない」場合、SSO アカウントが組織 ai-all-in-one に未参加です。SQL で SSO ユーザーを組織（ADMIN ロール）に追加してください。

3.12 統合ログ（Loki）

入口：「統合ログ」ページ、または Loki http://IP:3110。

📌 Loki のラベルは container / project / service で、job はありません。クエリは {container=~".+"}。

3.13 バックアップとリストア

入口：「バックアップとリストア」ページ、または backup.ps1 / restore.ps1。

⚠️ 重要な注意（検証済み）：
  • Keycloak は realm export/import（JSON） を使う（pg_dump はデフォルトロール関連を失う）；
  • SQLite 復元後は root 所有 → 正しい uid に chown（grafana=472、gitea=1000）；
  • pg_dump には --clean --if-exists を付与。

第4章一般ユーザー向けガイド

4.1 はじめ方

方法 A：DeepChat（日常会話に推奨）

  1. http://IP:8090/downloads/ でクライアントをインストール；
  2. DeepChat → 設定 → モデルサービス →「カスタム Provider / OpenAI 互換」：
    API Base URL：http://IP:3000/v1
    API Key：NewAPI で自己申請（4.2 参照）
    モデル：deepseek-chat
  3. 保存して会話開始。

方法 B：Dify（アプリ / ナレッジベース構築）

  1. http://IP を開き統合アカウントでログイン；
  2. 「スタジオ」→ アプリ作成；
  3. プロンプト記述、ナレッジベース接続、公開。

4.2 API キーの申請

  1. NewAPI http://IP:3000 を開く；
  2. 「API キー」→ トークン作成；
  3. sk- キーを DeepChat / Dify に入力。
📌 既定クォータは限定的。不足時は管理者に申請。

4.3 データ安全ルール

プラットフォームは電話番号・ID・銀行カード・メールを自動マスクしますが、以下を遵守してください：

❌ 送信禁止

  • 内部機密 / 商業機密（未公開コード、価格、顧客リスト、契約条項）；
  • 個人情報（ID、カード、パスワード、健康情報）；
  • ソースコード / 未公開技術案。

✅ 安全に利用可

  • 公開資料、一般知識、文書作成、翻訳、要約；
  • マスク済み業務データ（機密フィールド除去後）。
データレベル外部モデルへ？備考
公開✅ OK既に公開
社内一般⚠️ マスク後機密フィールド除去後に可
社内機密 / 個人❌ 禁止送信禁止
判断基準：「第三者が見たら問題か？」はい → 送信しない。

4.4 よくある質問

問題解決
ログインできないイントラネット IP（localhost でない）+ 統合アカウントを使用
「クォータ不足」NewAPI で残高確認、管理者に申請
コンテンツ遮断センシティブワード/情報が含まれる（4.3 参照）
DeepChat タイムアウト設定 → ネットワーク/プロキシ →「プロキシなし / 直接」
品質が低いモデル変更、またはプロンプト改善
AI を信頼できる？完全には不可 — 重要な事実/数値/コードは手動確認

4.5 行動規範

  • 違法・有害な利用をしない、違法・有害・権利侵害コンテンツを生成しない；
  • セキュリティ制限を迂回しない、クォータを大量消費しない；
  • 生成コンテンツを外部共有する際は事実確認と社内公開ルールを遵守。

ご不明な点はプラットフォーム管理者へ。
