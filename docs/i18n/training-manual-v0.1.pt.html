Manual de treinamento AI AllInOne

v0.1 · Para administradores e usuários · Cobre «Introdução → Configuração → administração por ferramenta → guia do usuário».

📌 Esta é a versão v0.1. Portas e contas refletem a implantação atual (IP de exemplo 192.168.31.117 — substitua pelo seu IP de intranet). Segredos ficam no credentials.html local do administrador.

Capítulo 1Introdução

1.1 O que é a plataforma

«AI AllInOne» é uma plataforma de IA empresarial implantada na intranet. Ela centraliza os recursos de LLM para que os funcionários usem tudo com uma única conta. Orquestra mais de uma dúzia de produtos open source com Docker, com o Keycloak fornecendo a identidade unificada.

  • Login unificado: uma conta (opcionalmente federada ao AD) para todos os produtos;
  • Gateway de modelos unificado: todas as chamadas passam por NewAPI + LiteLLM com auditoria, cobrança e mascaramento automáticos;
  • Mascaramento de PII: telefones/documentos/e-mails são mascarados antes de chegar ao modelo;
  • Aplicativos de IA: Dify para criar agentes, Q&A sobre base de conhecimento e fluxos;
  • Observabilidade e operações: monitoramento/alertas, rastreamento de LLM, logs unificados, backup/restauração, testes de disponibilidade, relatórios.

1.4 Conta unificada e SSO

  • Conta admin unificada: ai_all_in_one_admin (senha no credentials.html);
  • Federada ao AD (LDAP) via Keycloak, com conta local de reserva;
  • Grafana, Langfuse, NewAPI e o AI Admin Center usam SSO do Keycloak — alguns com login automático;
  • Os funcionários usam a conta unificada (ou AD) para DeepChat / Dify.
📌 Se o SSO falhar com unknown_error, geralmente é o serviço IP Helper (iphlpsvc) parado, quebrando o encaminhamento de porta AD (389). Como admin: Start-Service iphlpsvc + readicione as regras netsh interface portproxy.

Capítulo 2Configuração

2.1 Pré-implantação

  1. Instalar o Docker Desktop (Windows) ou Docker Engine (Linux/online), e iniciá-lo.
  2. Preparar a rede: acesso a registros de imagens (Docker Hub / quay.io — se não, configurar um espelho tipo DaoCloud) e ao GitHub; decidir o IP a expor.
  3. (Opcional) Preparar o AD: controlador de domínio acessível, bind DN, senha de bind, base DN LDAP.
  4. Preparar chaves API de modelos: DeepSeek / OpenAI / Claude, pelo menos uma.

2.2 Variáveis e segredos

A configuração fica no .env (modelo: .env.example). Variáveis-chave:

✅ O script bootstrap.ps1 substitui o IP, gera segredos, inicia contêineres, inicializa o Keycloak, configura canais NewAPI e registra a tarefa de backup. Prefira-o.

2.3 Keycloak

O Keycloak é o centro de auth, atualmente em modo produção (start + PostgreSQL):

  • Realm: enterprise-ai;
  • Função: ai-platform-admin;
  • Clientes OIDC: AI-all-in-one-admin-portal, grafana, langfuse, newapi (confidenciais);
  • Federação LDAP: vendor=AD, bind DN com o CN com espaços (CN=ai all in one admin,CN=Users,DC=chxia,DC=lab).
📌 Use scripts/keycloak-realm-init.ps1 para criar realm + clientes + função + federação LDAP de uma vez. O id interno do realm é um UUID.

2.4 Canais LLM

Cadeia: cliente → NewAPI (3000) → LiteLLM (4001) → modelo externo.

  1. No NewAPI «Canais», aponte um canal para o LiteLLM: Base URL http://IP:4001/v1, com LITELLM_MASTER_KEY;
  2. Configure a lista de modelos no litellm-config.yaml;
  3. Emita chaves API (sk-) no NewAPI «Tokens».

2.6 Mascaramento de PII

Duas camadas, sobre o proxy LiteLLM, com default_on:

  • Regex LiteLLM: mascara telefones, documentos, cartões, e-mails, códigos de crédito, passaportes, IP + bloqueio de palavras sensíveis;
  • Presidio: detecta nomes/e-mails/cartões (analyzer: 5002, anonymizer: 5001).
⚠️ Escopo: apenas chamadas que passam pelo LiteLLM; não mascara dados já armazenados em outras bases.

2.7 Monitoramento / logs / alertas

  • Monitoramento: Prometheus (9091) + Grafana (3030);
  • Alertas: Alertmanager (9093) → webhook (padrão para o AI Admin Center);
  • Logs: Promtail coleta → Loki (3110), página «Logs unificados»;
  • Rotação: x-logging global (10 MB × 3).

2.8 Backup e restauração

scripts/backup.ps1 roda às 02:00: NewAPI MySQL, Dify PG, SQLite Ghost/Gitea/Grafana, Keycloak (export realm JSON), Langfuse PG, arquivos de config. Restauração via restore.ps1 ou a página «Backup e restauração».

📌 O Keycloak deve ser copiado via realm export/import (JSON), não apenas pg_dump. Ver 3.13.

Capítulo 3Administração (guia por ferramenta)

Cada seção cobre «como entrar, o que fazer, tarefas diárias». Entrada recomendada: AI Admin Center (:10086).

3.1 Keycloak

Entrada: http://IP:9090 → console, usuário ai_all_in_one_admin.

  • Gerenciar usuários, redefinir senhas, atribuir a função ai-platform-admin;
  • Gerenciar clientes OIDC;
  • Ver/ajustar a federação LDAP;
  • Ver sessões e forçar logout.

3.2 NewAPI

Entrada: http://IP:3000, conta unificada.

  • Canais: gerenciar canais ascendentes (para o LiteLLM);
  • Tokens: emitir/desabilitar chaves, cotas, expiração;
  • Logs: usuário/modelo/tokens/cota/custo/IP por chamada;
  • Usuários: recarregar, aumentar limites, banir.
📌 O registro de IP depende do ajuste «Registrar log de IP» (desativado por padrão). Ative-o nas Configurações pessoais.

3.3 LiteLLM

Entrada: http://IP:4001. Config no litellm-config.yaml.

  • Adicionar/remover modelos e chaves;
  • Ajustar guardrails PII (regex + Presidio);
  • Configurar o reporte ao Langfuse (success_callback).

3.4 Dify

Entrada: http://IP (porta 80), conta unificada (e-mail admin@company.com).

  • «Studio» — criar apps (assistente / agente / fluxo);
  • «Conhecimento» — enviar documentos, Q&A;
  • Configuração de provedores de modelos;
  • Gestão de membros e publicação.
📌 O Dify é um compose oficial separado (dify/docker/); mantenha-o nesse diretório.

3.5 Ghost

Entrada: conteúdo http://IP:8090; admin http://IP:8090/ghost/.

  • Publicar anúncios e notícias;
  • Manter capa, navegação, tema;
  • Enviar instaladores DeepChat;
  • Membros e assinaturas.

3.6 Gitea

Entrada: http://IP:3002, SSH 2222.

  • Criar repositórios, organizações, equipes;
  • Gerenciar runners Actions (deepchat-sync);
  • Revisão de código, issues, releases.

3.7 MCP Gateway

Entrada: http://IP:3100. Config mcp-gateway/mcp-servers.json.

  • Gerenciar servidores MCP / mercado Skill (skills/);
  • Adicionar/remover conexões MCP para DeepChat / Dify.

3.8 Servidor de atualização DeepChat

Entrada: http://IP:8091; dados em deepchat-updates/.

  • Colocar novos instaladores (.exe/.dmg) e atualizar version.txt;
  • Auto-download de versões oficiais via Gitea Actions (deepchat-sync);
  • Manter sync-config.json.
📌 «Tempo de conexão esgotado» no DeepChat = geralmente um proxy de sistema caído (ECONNREFUSED 127.0.0.1:33210). Configure «Sem proxy / Direto» em Configurações → Rede/Proxy.

3.9 AI Admin Center

3.10 Monitoramento (Prometheus / Grafana)

Entrada: Grafana http://IP:3030; Prometheus http://IP:9091.

  • Acompanhar CPU/memória/rede no Grafana;
  • Verificar targets e regras no Prometheus;
  • Alertas via Alertmanager (9093) webhook.

3.11 Observabilidade LLM (Langfuse)

Entrada: http://IP:3010, SSO automático.

⚠️ Se «não vê dados» após o SSO, a conta SSO não está na org ai-all-in-one. Adicione o usuário SSO à org (função ADMIN) por SQL.

3.12 Logs unificados (Loki)

Entrada: página «Logs unificados», ou Loki http://IP:3110.

📌 As etiquetas do Loki são container / project / service — não há job. Consulte {container=~".+"}.

3.13 Backup e restauração

Entrada: página «Backup e restauração» ou backup.ps1 / restore.ps1.

⚠️ Armadilhas (verificadas):
  • Keycloak: usar realm export/import (JSON); pg_dump perde a associação da função padrão;
  • SQLite restaurado fica como root → chown para o uid correto (grafana=472, gitea=1000);
  • pg_dump: adicionar --clean --if-exists.

Capítulo 4Guia do usuário

4.1 Primeiros passos

Opção A: DeepChat (chat diário)

  1. Abrir http://IP:8090/downloads/ e instalar o cliente;
  2. DeepChat → Configurações → Serviço de modelo → «Provedor personalizado / compatível com OpenAI»:
    API Base URL: http://IP:3000/v1
    API Key: autoatendimento no NewAPI (ver 4.2)
    Modelo: deepseek-chat
  3. Salvar e conversar.

Opção B: Dify (apps / base de conhecimento)

  1. Abrir http://IP, conta unificada;
  2. «Studio» → criar uma app;
  3. Escrever prompts, anexar base de conhecimento, publicar.

4.2 Solicitação de chave API

  1. Abrir o NewAPI http://IP:3000;
  2. «Chaves API» → criar token;
  3. Copiar a chave sk- no DeepChat / Dify.
📌 Cota limitada por padrão; contate um admin para aumentá-la.

4.3 Regras de segurança de dados

A plataforma mascara telefones, documentos, cartões, e-mails, mas respeite:

❌ Nunca enviar

  • Segredos internos/confidenciais (código não publicado, preços, listas de clientes, contratos);
  • Privacidade pessoal (documentos, cartões, senhas, saúde);
  • Código-fonte / projetos não publicados.

✅ Sem risco

  • Material público, conhecimento geral, redação, tradução, resumo;
  • Dados de negócio mascarados (após remover campos sensíveis).
NívelModelo externo?Notas
Público✅ OKJá público
Interno comum⚠️ após mascaramentoOK após remover campos sensíveis
Interno confidencial / pessoal❌ ProibidoNunca enviar
Regra: «Seria um problema se um terceiro visse isto?» Se sim → não enviar.

Qualidade medíocreTrocar de modelo ou melhorar o prompt

4.5 Código de conduta

  • Sem uso ilegal ou danoso; sem conteúdo ilegal, danoso ou infrator;
  • Não contornar a segurança nem esgotar a cota em massa;
  • Verificar os fatos antes de compartilhar conteúdo gerado externamente.

Contate o administrador da plataforma se tiver dúvidas.
