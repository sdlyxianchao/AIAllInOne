Manual de formación AI AllInOne

v0.1 · Para administradores y usuarios · Cubre «Introducción → Configuración → administración por herramienta → guía de usuario».

📌 Esta es la versión v0.1. Puertos y cuentas reflejan el despliegue actual (IP de ejemplo 192.168.31.117 — reemplázala por tu IP de intranet). Los secretos están en el credentials.html local del administrador.

Capítulo 1Introducción

1.1 Qué es la plataforma

«AI AllInOne» es una plataforma de IA empresarial desplegada en la intranet. Centraliza las capacidades LLM para que los empleados usen todo con una sola cuenta. Orquesta más de una docena de productos de código abierto con Docker, con Keycloak proporcionando la identidad unificada.

  • Inicio de sesión unificado: una cuenta (opcionalmente federada a AD) para todos los productos;
  • Pasarela de modelos unificada: todas las llamadas pasan por NewAPI + LiteLLM con auditoría, facturación y redacción automáticas;
  • Redacción PII: teléfonos/identificaciones/correos se enmascaran antes de llegar al modelo;
  • Aplicaciones de IA: Dify para crear agentes, Q&A sobre base de conocimiento y flujos;
  • Observabilidad y operaciones: monitorización/alertas, trazado LLM, logs unificados, copias/restauración, pruebas de disponibilidad, informes.

1.4 Cuenta unificada y SSO

  • Cuenta admin unificada: ai_all_in_one_admin (contraseña en credentials.html);
  • Federada al AD (LDAP) vía Keycloak, con cuenta local de respaldo;
  • Grafana, Langfuse, NewAPI y el AI Admin Center usan SSO de Keycloak — algunos con inicio automático;
  • Los empleados usan la cuenta unificada (o AD) para DeepChat / Dify.
📌 Si el SSO falla con unknown_error, suele ser el servicio IP Helper (iphlpsvc) detenido, que rompe el reenvío de puerto AD (389). Como admin: Start-Service iphlpsvc + reañade las reglas netsh interface portproxy.

Capítulo 2Configuración

2.1 Pre-despliegue

  1. Instalar Docker Desktop (Windows) o Docker Engine (Linux/online), e iniciarlo.
  2. Preparar la red: acceso a registros de imágenes (Docker Hub / quay.io — si no, configurar un espejo tipo DaoCloud) y a GitHub; decidir la IP a exponer.
  3. (Opcional) Preparar AD: controlador de dominio accesible, bind DN, contraseña bind, base DN LDAP.
  4. Preparar claves API de modelos: DeepSeek / OpenAI / Claude, al menos una.

2.2 Variables y secretos

✅ El script bootstrap.ps1 reemplaza la IP, genera secretos, inicia contenedores, inicializa Keycloak, configura canales NewAPI y registra la tarea de copia. Prefiérelo.

2.3 Keycloak

Keycloak es el centro de auth, actualmente en modo producción (start + PostgreSQL):

  • Realm: enterprise-ai;
  • Rol: ai-platform-admin;
  • Clientes OIDC: AI-all-in-one-admin-portal, grafana, langfuse, newapi (confidenciales);
  • Federación LDAP: vendor=AD, bind DN con el CN con espacios (CN=ai all in one admin,CN=Users,DC=chxia,DC=lab).
📌 Usa scripts/keycloak-realm-init.ps1 para crear realm + clientes + rol + federación LDAP de una vez. El id interno del realm es un UUID.

2.4 Canales LLM

Cadena: cliente → NewAPI (3000) → LiteLLM (4001) → modelo externo.

  1. En NewAPI «Canales», apunta un canal a LiteLLM: Base URL http://IP:4001/v1, con LITELLM_MASTER_KEY;
  2. Configura la lista de modelos en litellm-config.yaml;
  3. Emite claves API (sk-) en NewAPI «Tokens».

2.6 Redacción PII

Dos capas, sobre el proxy LiteLLM, con default_on:

  • Regex LiteLLM: enmascara teléfonos, identificaciones, tarjetas, correos, códigos de crédito, pasaportes, IP + bloqueo de palabras sensibles;
  • Presidio: detecta nombres/correos/tarjetas (analyzer: 5002, anonymizer: 5001).
⚠️ Alcance: solo llamadas que pasan por LiteLLM; no redacta datos ya almacenados en otras bases.

2.7 Monitorización / logs / alertas

  • Monitorización: Prometheus (9091) + Grafana (3030);
  • Alertas: Alertmanager (9093) → webhook (por defecto al AI Admin Center);
  • Logs: Promtail recopila → Loki (3110), página «Logs unificados»;
  • Rotación: x-logging global (10 MB × 3).

2.8 Copias y restauración

scripts/backup.ps1 se ejecuta a las 02:00: NewAPI MySQL, Dify PG, SQLite Ghost/Gitea/Grafana, Keycloak (export realm JSON), Langfuse PG, archivos de config. Restauración vía restore.ps1 o la página «Copias y restauración».

📌 Keycloak debe respaldarse vía realm export/import (JSON), no solo pg_dump. Ver 3.13.

Capítulo 3Administración (guía por herramienta)

Cada sección cubre «cómo entrar, qué hacer, tareas diarias». Entrada recomendada: AI Admin Center (:10086).

3.1 Keycloak

Entrada: http://IP:9090 → consola, usuario ai_all_in_one_admin.

  • Gestionar usuarios, restablecer contraseñas, asignar el rol ai-platform-admin;
  • Gestionar clientes OIDC;
  • Ver/ajustar la federación LDAP;
  • Ver sesiones y forzar cierre.

3.2 NewAPI

Entrada: http://IP:3000, cuenta unificada.

  • Canales: gestionar canales ascendentes (hacia LiteLLM);
  • Tokens: emitir/deshabilitar claves, cuotas, caducidad;
  • Logs: usuario/modelo/tokens/cuota/coste/IP por llamada;
  • Usuarios: recargar, subir límites, banear.
📌 El registro de IP depende del ajuste «Registrar log de IP» (desactivado por defecto). Actívalo en Configuración personal.

3.3 LiteLLM

Entrada: http://IP:4001. Config en litellm-config.yaml.

  • Añadir/quitar modelos y claves;
  • Ajustar guardrails PII (regex + Presidio);
  • Configurar el reporte a Langfuse (success_callback).

3.4 Dify

Entrada: http://IP (puerto 80), cuenta unificada (correo admin@company.com).

  • «Studio» — crear apps (asistente / agente / flujo);
  • «Conocimiento» — subir documentos, Q&A;
  • Configuración de proveedores de modelos;
  • Gestión de miembros y publicación.
📌 Dify es un compose oficial separado (dify/docker/); mantenlo desde ese directorio.

3.5 Ghost

Entrada: contenido http://IP:8090; admin http://IP:8090/ghost/.

  • Publicar anuncios y noticias;
  • Mantener portada, navegación, tema;
  • Subir instaladores DeepChat;
  • Miembros y suscripciones.

3.6 Gitea

Entrada: http://IP:3002, SSH 2222.

  • Crear repos, organizaciones, equipos;
  • Gestionar runners Actions (deepchat-sync);
  • Revisión de código, issues, releases.

3.7 MCP Gateway

Entrada: http://IP:3100. Config mcp-gateway/mcp-servers.json.

  • Gestionar servidores MCP / mercado Skill (skills/);
  • Añadir/quitar conexiones MCP para DeepChat / Dify.

3.8 Servidor de actualización DeepChat

Entrada: http://IP:8091; datos en deepchat-updates/.

  • Colocar nuevos instaladores (.exe/.dmg) y actualizar version.txt;
  • Auto-descarga de versiones oficiales vía Gitea Actions (deepchat-sync);
  • Mantener sync-config.json.
📌 «Tiempo de conexión agotado» en DeepChat = suele ser un proxy de sistema caído (ECONNREFUSED 127.0.0.1:33210). Configura «Sin proxy / Directo» en Configuración → Red/Proxy.

3.10 Monitorización (Prometheus / Grafana)

Entrada: Grafana http://IP:3030; Prometheus http://IP:9091.

  • Seguir CPU/memoria/red en Grafana;
  • Verificar targets y reglas en Prometheus;
  • Alertas vía Alertmanager (9093) webhook.

3.11 Observabilidad LLM (Langfuse)

Entrada: http://IP:3010, SSO automático.

⚠️ Si «no ves datos» tras el SSO, la cuenta SSO no está en la org ai-all-in-one. Añade el usuario SSO a la org (rol ADMIN) por SQL.

3.12 Logs unificados (Loki)

Entrada: página «Logs unificados», o Loki http://IP:3110.

📌 Las etiquetas de Loki son container / project / service — no hay job. Consulta {container=~".+"}.

3.13 Copias y restauración

Entrada: página «Copias y restauración» o backup.ps1 / restore.ps1.

⚠️ Errores (verificados):
  • Keycloak: usar realm export/import (JSON); pg_dump pierde la asociación del rol por defecto;
  • SQLite restaurado queda en root → chown al uid correcto (grafana=472, gitea=1000);
  • pg_dump: añadir --clean --if-exists.

Capítulo 4Guía de usuario

4.1 Primeros pasos

Opción A: DeepChat (chat diario)

  1. Abrir http://IP:8090/downloads/ e instalar el cliente;
  2. DeepChat → Configuración → Servicio de modelo → «Proveedor personalizado / compatible con OpenAI»:
    API Base URL: http://IP:3000/v1
    API Key: autoservicio en NewAPI (ver 4.2)
    Modelo: deepseek-chat
  3. Guardar y chatear.

Opción B: Dify (apps / base de conocimiento)

  1. Abrir http://IP, cuenta unificada;
  2. «Studio» → crear una app;
  3. Escribir prompts, adjuntar base de conocimiento, publicar.

4.2 Solicitud de clave API

  1. Abrir NewAPI http://IP:3000;
  2. «Claves API» → crear token;
  3. Copiar la clave sk- en DeepChat / Dify.
📌 Cuota limitada por defecto; contacta a un admin para subirla.

4.3 Normas de seguridad de datos

La plataforma enmascara teléfonos, identificaciones, tarjetas, correos, pero respeta:

❌ Nunca enviar

  • Secretos internos/confidenciales (código no publicado, precios, listas de clientes, contratos);
  • Privacidad personal (identificaciones, tarjetas, contraseñas, salud);
  • Código fuente / diseños no publicados.

✅ Sin riesgo

  • Material público, conocimiento general, redacción, traducción, resumen;
  • Datos de negocio redactados (tras quitar campos sensibles).
NivelModelo externo?Notas
Público✅ OKYa público
Interno ordinario⚠️ tras redacciónOK tras quitar campos sensibles
Interno confidencial / personal❌ ProhibidoNunca enviar
Regla: «¿Sería un problema si un tercero viera esto?» Si sí → no enviar.

4.5 Código de conducta

  • Sin uso ilegal o dañino; sin contenido ilegal, dañino o infractor;
  • No eludir la seguridad ni agotar la cuota en masa;
  • Verificar los hechos antes de compartir contenido generado externamente.

Contacta al administrador de la plataforma si tienes dudas.
