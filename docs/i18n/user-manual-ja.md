## 1. プラットフォームを知る

> 📌 補足：本マニュアルの `IP` は会社イントラネットサーバーのアドレスを指します（例：`192.168.31.117`。実際は管理者の公表に従ってください）。すべてのアドレスは**イントラネット IP** を使い、`localhost` や `127.0.0.1` は使いません。
### 1.1 プラットフォームとは
「AI AllInOne」は会社イントラネットにデプロイされた企業 AI プラットフォームで、大規模モデル（DeepSeek、GPT、Claude など）の能力をイントラネットに一元化し、従業員は**1 つのアカウント**で利用できます。背後にあるサーバー、モデル、キーを気にする必要はありません——3 つの入口を覚えるだけです。
### 1.2 プラットフォームで何ができるか
| やりたいこと | 使うツール | どこで開くか |
| --- | --- | --- |
| ChatGPT のように日常会話、文書作成、翻訳、コード修正 | 💬 DeepChat | デスクトップクライアント（まずポータルからダウンロード・インストール） |
| 会社が用意した AI アプリ（カスタマーサポートQ&A、承認アシスタントなど）を使う | 🤖 Dify | ブラウザ `http://IP` |
| ドキュメントをアップロードして「ナレッジベースQ&A」（社内資料を質問） | 🤖 Dify | ブラウザ `http://IP` |
| 会社のニュース、お知らせ、ソフトウェアダウンロードを見る | 📰 ポータル（Hub） | ブラウザ `http://IP:8090` |
| 自分で API Key を申請してサードパーティツールに接続 | 🔑 NewAPI | ブラウザ `http://IP:3000` |
### 1.3 3 つの入口の選び方
> ✅ **一言で覚える**：**チャット/執筆/翻訳 → DeepChat**；**会社のアプリ/ナレッジベース → Dify**；**探し物/お知らせ閲覧/ソフトダウンロード → ポータル Hub**。3 つとも同じアカウントでログインします。
ログイン方式：すべての製品は **Keycloak 統合アカウント**を利用します（一部は会社の AD ドメインアカウント、つまり PC 起動時のアカウントに対応）。「ログイン」をクリックすると自動で統合ログインページに遷移し、一度アカウントを入力すれば、以降の各製品で再ログインは不要です。
### 1.4 本マニュアルの使い方
- **初心者**：第 2~4 章を順に読み、まず DeepChat をインストールして使い始めましょう；
- **サードパーティツールに接続したい**：第 5 章で Key を申請；
- **疑問がある**：まず第 7 章 FAQ を確認し、それから管理者に問い合わせ；
- **必読**：第 6 章データセキュリティ、第 8 章行動規範。全員が遵守してください。

## 2. AI All In One Hub（ポータル）

### 2.1 ポータルとは
Ghost**AI All In One Hub** は会社の企業ポータル（オープンソースの Ghost を基に構築）で、アドレスは `http://IP:8090`。AI プラットフォームへ入る**出発点**です。
### 2.2 ニュース / お知らせの閲覧
1. ブラウザで `http://IP:8090` を開く；
2. ホームが最新のニュース・お知らせリストで、タイトルをクリックして全文を読む。
### 2.3 ダウンロードセンター（DeepChat のインストール）
1. ポータル上部の「**ダウンロードセンター**」メニューをクリック、または直接 `http://IP:8090/downloads/` を開く；
2. OS に合わせて **Windows** / **macOS** インストーラを選び、**DeepChat** をダウンロード；
3. インストール：Windows は .exe をダブルクリックしてウィザードに従う。macOS は .dmg を開いて「アプリケーション」にドラッグ。
> ✅ ダウンロードページ上部の「初回はまずスキルマネージャーをインストール」は上級ユーザー向けのスキルパッケージです。一般ユーザーは無視して構いません。
### 2.4 Dify / ヘルプへの遷移
- ポータルメニュー「**AI ワークベンチ**」をクリック → 直接 Dify（AI アプリケーションプラットフォーム）へ遷移；
- 「**ヘルプドキュメント**」をクリック → 会社が整理したヘルプ記事を閲覧。
> 📖 公式ドキュメント：ポータルは Ghost が提供します。公式ドキュメント https://ghost.org/docs/

## 3. ツール1：DeepChat

### 3.1 ダウンロードとインストール
1. ポータルのダウンロードセンター `http://IP:8090/downloads/` を開く；
2. OS に合わせてインストーラをダウンロードしてインストール；
3. DeepChat を起動。
### 3.2 モデルの設定（会社ゲートウェイへの接続）
初回利用時は DeepChat にモデルの場所を教える必要があります。会社はモデルをゲートウェイ **NewAPI** に一元化しており、3 つの値だけ入力すれば済みます：
1DeepChat を開く → 左下の **設定（⚙️）** → **モデルサービス / モデルプロバイダー**。
2「**カスタム Provider**」または「**OpenAI 互換**」を追加。
3以下の 3 項目を入力：
| フィールド | 入力内容 |
| --- | --- |
| API Base URL | `http://IP:3000/v1` |
| API Key | NewAPI で申請した `sk-` キー（第 5 章参照） |
| モデル | `deepseek-chat`（会社のデフォルト。その他公開済みモデルも選択可） |
4保存。
> ⚠️ **重要**：API Base URL は必ず**イントラネット IP**（`http://IP:3000/v1`）を使い、`localhost` は使わないでください。使うと会社サーバーに接続できません。
### 3.3 対話を始める
1. 「**+ 新規対話**」をクリック；
2. 入力欄に入力して Enter で送信；
3. 返信が届けば経路は正常です。
### 💡 **試してみる**：「お客様への催促メールを書いてください。口調は柔らかく」と送信して AI の回答を見てみましょう。さらに「次の文章を英語に翻訳して：……」。DeepChat は複数ターン対話に対応し、追質問や AI への修正依頼ができます。

    3.4 よく使う機能とテクニック
| 機能 | 使い方 |
| --- | --- |
| 複数モデル切り替え | 対話上部で別モデルを選択（会社が複数公開している場合） |
| ファイル読み書き / MCP ツール | 設定 → MCP で会社のツール（例：ファイルシステム）を有効化し、AI にローカルファイルを読ませる |
| ダーク/ライトテーマ | 設定 → 外観 |
| ネットワークプロキシ問題 | 「接続タイムアウト」が出たら → 設定 → ネットワーク/プロキシ → 「プロキシ不使用/直接接続」に変更 |
### 3.5 質問のコツ
> ✅ **具体的であるほど良い**——背景を伝え、要件を明確にし、例を示すと、AI の回答品質が上がります。
- 💡 良い例：「あなたはベテランコピーライターです。CTO 読者向けに、200 字の製品紹介を書いてください。スタイルはプロフェッショナルで抑制的」——「紹介文を書いて」よりはるかに優れています。
    
      **役割を与える**：「あなたは財務の専門家です。……を手伝って」；
- **制約を与える**：「100 字以内で / 表形式で / 3 ステップで」；
- **例を示す**：「この形式を参考に書き直して……」；
- **段階的に追質問**：不満なら「もう少し直して」「別の口調で」。
> 📖 公式ドキュメント：DeepChat クイックスタート https://deepchatai.cn/docs/guide/getting-started/ · オープンソースリポジトリ https://github.com/ThinkInAIXYZ/deepchat

## 4. ツール2：Dify

### 4.1 Dify へのログイン
1. ブラウザで `http://IP` を開く（80 ポート、ポート番号なし。ポータルの「AI ワークベンチ」からも入れます）；
2. 統合アカウントでログイン（初回は管理者によるアカウント開設が必要な場合があります）。
### 4.2 既存のチャットアプリを利用
管理者があらかじめいくつかのアプリを用意しています（例：「会社制度Q&A」「カスタマーサポートアシスタント」）。一般ユーザーは直接「使う」だけで済みます：
1. ログイン後「**スタジオ / アプリ**」リストへ；
2. 使いたいアプリを見つけ、「**実行 / プレビュー**」（右上の再生ボタン）をクリック；
3. 開いた対話ページで直接質問。
### 4.3 ナレッジベースQ&A
社内ドキュメントを AI に「与えて」回答させたい場合、Dify の**ナレッジベース**を使います（管理者の権限付与が必要）：
1. 「**ナレッジベース**」→「ナレッジベース作成」；
2. ドキュメントをアップロード（Word / PDF / Markdown / ウェブリンクなど対応）；
3. システムが自動でセグメント化・インデックス作成；
4. アプリでこのナレッジベースを「参照」すると、AI があなたのドキュメントに基づいて回答できます。
> 📌 ナレッジベースの内容は AI が回答に使用します。第 6 章のデータセキュリティ規程を遵守し、**機密資料はアップロードしないでください**。
### 4.4 自分で簡単なアプリを作る（応用）
1. スタジオ → 空のアプリ作成 → 「チャットアシスタント」を選択；
2. 「プロンプト」を書いて AI に役割を伝える（例：「あなたは会社の勤怠制度のQ&Aアシスタントです」）；
3. ナレッジベース追加 → モデル選択 → プレビューテスト → 公開。
> 📖 公式ドキュメント：Dify 公式ドキュメント https://docs.dify.ai

## 5. API Key の申請

会社の AI 能力を**サードパーティツール**（自分のスクリプト、OpenAI インターフェース対応の他のソフト）に接続する場合、API Key（`sk-` で始まるキー）が必要です。
### 5.1 NewAPI へのログイン
1. ブラウザで `http://IP:3000` を開く；
2. 統合アカウントでログイン（または「ワンクリックログイン / OIDC」でドメインアカウントを使用）。
### 5.2 新規トークンの作成
1. 左メニュー「**API キー / トークン**」；
2. 「**新規トークン**」をクリックし、名前を付け（例：`私のスクリプト`）、クォータ、有効期限を設定可能；
3. 保存後に生成された `sk-xxxx` 文字列をコピー。**一度しか表示されないため、必ずすぐに保存**。
### 5.3 クライアントへの記入
- **API Base URL**：`http://IP:3000/v1`
- **API Key**：先ほどコピーした `sk-xxxx`
### 5.4 よくある使い方の例
> 💡 curl でテスト：  
> 
>     `curl http://IP:3000/v1/chat/completions -H "Authorization: Bearer sk-xxxx" -H "Content-Type: application/json" -d '{"model":"deepseek-chat","messages":[{"role":"user","content":"こんにちは"}]}'`
> 
>     ⚠️ クォータを使い切ると「残高不足」と表示されます。管理者に引き上げを申請してください。Key はあなたのアカウントパスワードに相当し、**他人に渡さない、コードリポジトリにコミットしない**。
> 📖 公式ドキュメント：NewAPI 公式ドキュメント https://docs.newapi.pro · 公式サイト https://www.newapi.ai

## 6. データセキュリティ規程

プラットフォームは**携帯番号、身分証番号、銀行カード番号、メール**などの機密情報を自動で**マスキング**し（大規模モデル送信前に自動で伏字化）、機密語をブロックします。ただし、以下の一線は自覚して守ってください。
### 6.1 送ってよいもの、送ってはいけないもの
#### ❌ AI への送信を厳禁
- 内部機密 / 商業機密（未公開の製品コード、価格、顧客リスト、契約条項）；
- 個人プライバシー（身分証番号、銀行カード番号、パスワード、健康情報、他者のプライバシー）；
- ソースコード / 未公開の技術方案。
#### ✅ 安心して利用できるもの
- 公開資料、一般知識、文書作成、翻訳、要約；
- マスキング後の業務データ（具体的な人名/番号/機密フィールドを除去したもの）。
### 6.2 データ分類クイックリファレンス
| データ等級 | 外部大規模モデルへ送信可か | 説明 |
| --- | --- | --- |
| 公開データ | ✅ 可 | 公開済みの資料、一般情報 |
| 内部一般データ | ⚠️ マスキング後に可 | 機密フィールドを除去すれば利用可 |
| 内部機密 / 個人プライバシー | ❌ 禁止 | 送信厳禁 |
> > 判断基準：**「この内容が外部の人の目に触れたら問題があるか？」**ある → 送らない。
### 6.3 3 つの典型的なシーン
| シーン | どうするか |
| --- | --- |
| 週報作成で顧客名が関わる | 「ある顧客」「A 顧客」で実際の顧客名を代替 |
| AI にデータ表を分析させる | 先に氏名、電話、身分証番号などの列を削除し、集計データのみ残す |
| 契約条項の翻訳 | 先に金額、相手方名称などの機密情報を削除、または「甲/乙」で代替 |

## 7. よくある質問 FAQ

### 7.1 ログイン / アクセス編
| 問題 | 解決策 |
| --- | --- |
| ある製品にログインできない？ | イントラネット IP（localhost ではない）で統合アカウントを使用していることを確認。それでもだめなら管理者に連絡 |
| ログインページが開かない / ずっと読み込み中？ | 会社イントラネット（WiFi/有線）に接続していることを確認。アドレスは `http://IP` で localhost ではない |
| 統合アカウントのパスワードを忘れた？ | 管理者にリセットを依頼（またはドメインアカウントで回復） |
### 7.2 利用編
| 問題 | 解決策 |
| --- | --- |
| クォータ不足と表示？ | NewAPI 管理画面で残高確認。使い切ったら管理者にチャージ/引き上げを依頼 |
| 送信内容がブロックされた？ | 機密語または機密情報にヒット。第 6 章の規程に従って調整して再試行 |
| DeepChat が接続タイムアウト？ | 設定 → ネットワーク/プロキシ → 「プロキシ不使用/直接接続」に変更 |
| モデルの回答品質が悪い？ | 別モデルに切り替えるか、質問を改善（文脈提示、要件明確化、例示） |
| DeepChat のダウンロード場所を忘れた？ | ポータルのダウンロードセンター `http://IP:8090/downloads/` |
| Dify でアプリ作成がずっと読み込み中？ | 通常はネットワーク/WebSocket 問題。管理者に連絡。ブラウザ Ctrl+F5 で強制リロード |
### 7.3 認識編
| 問題 | 解決策 |
| --- | --- |
| AI の回答は信じられる？ | 全面的には信じられません。AI は間違うことがあります（ハルシネーション）。重要な事実、数字、コードは必ず人手で検証してください |
| AI は私の話を覚えている？ | 現在の対話コンテキストは複数ターンの回答のために保持されます。機密情報を入力しないでください（第 6 章参照） |

## 8. 行動規範

### 8.1 利用規範
- 違法・規約違反の用途に使わない。違法、有害、権利侵害のコンテンツを生成しない；
- プラットフォームの安全制限を回避しない。クォータを大量に消費しない；
- AI 生成コンテンツを外部に送信する際は、事実を検証し会社の情報公開規程を遵守する；
- 自分の API Key を適切に保管し、他人に貸与しない、コードリポジトリにコミットしない；
- 異常（アカウント異常、コンテンツ異常）を発見したら速やかに管理者へ報告する。
### 8.2 一言でまとめ
> ✅ AI を上手に活用して効率化しましょう。ただし**機密は送らない、事実は必ず検証、ルールは守る**。困ったらプラットフォーム管理者に連絡してください。
