AI AllInOne 培訓手冊

版本 v0.1 · 面向管理員與一般使用者 · 涵蓋「簡介 → 設定 → 各工具管理 → 使用者」四個部分。

📌 本手冊為 v0.1 初版，連接埠與帳號以目前部署環境為準（範例 IP 192.168.31.117，實際請替換為你的內網 IP）。密碼等機密見管理員本機 credentials.html，不寫入本手冊。

第一章簡介

1.1 平台是什麼

「AI AllInOne」是一套部署在公司內網的企業 AI 平台，把大模型能力統一收口，員工一個帳號即可使用。它把十幾個開源產品用 Docker 編排成一個整體，由 Keycloak 提供統一身份認證。

核心能力：

  • 統一登入：一個帳號（可對接公司 AD 網域帳號）登入所有產品；
  • 統一模型閘道：所有模型呼叫經 NewAPI + LiteLLM 收口，自動稽核、計費、脫敏；
  • PII 脫敏：手機號/身分證/信箱等敏感資訊在發給大模型前自動打碼；
  • AI 應用：Dify 視覺化搭建智慧體、知識庫問答、工作流程；
  • 可觀測與維運：監控告警、LLM 呼叫追蹤、統一日誌、備份還原、可用性測試、報告產生。

1.4 統一帳號與 SSO

平台採用「一個帳號登入所有產品」策略：

  • 統一管理員帳號：ai_all_in_one_admin（密碼見 credentials.html，不在此列出）；
  • 該帳號透過 Keycloak 聯合到公司 AD 網域控制站（LDAP），也可用本機帳號兜底；
  • Grafana、Langfuse、NewAPI、AI 管理中心等均已接入 Keycloak SSO，部分支援自動登入（點連結直進，無需再點「用 Keycloak 登入」按鈕）；
  • 員工日常使用 DeepChat / Dify 時，用統一帳號（或 AD 網域帳號）登入。
📌 若 SSO 登入報 unknown_error，通常是宿主機 IP Helper 服務（iphlpsvc）未執行導致 AD 連接埠轉發（389）失效，而非 Keycloak 設定問題。以管理員身份執行：Start-Service iphlpsvc + 重掛 netsh interface portproxy 規則。

第二章設定

2.1 部署前準備

  1. 安裝 Docker Desktop（Windows）或 Docker Engine（Linux/線上），並啟動。
  2. 準備網路：確保能存取 Docker 映像倉庫（Docker Hub / quay.io，不通則配 DaoCloud 等映像加速）和 GitHub；確定對外服務的內網 IP。
  3. （可選）準備 AD 網域控制站：如需對接公司網域帳號，需網域控制站可達，並準備 bind DN、bind 密碼、LDAP base DN 等。
  4. 準備模型 API Key：DeepSeek / OpenAI / Claude 等，至少一個。

2.2 環境變數與金鑰

核心設定集中在 .env（範本為 .env.example）。關鍵變數：

變數作用
KEYCLOAK_ADMIN / KEYCLOAK_ADMIN_PASSWORDKeycloak 管理員帳號
KEYCLOAK_DB_PASSWORDKeycloak PostgreSQL 密碼
NEWAPI_DB_PASSWORD / NEWAPI_SESSION_SECRET / NEWAPI_CRYPTO_SECRETNewAPI 資料庫與會話金鑰
LITELLM_MASTER_KEYNewAPI 連 LiteLLM 的主金鑰
DEEPSEEK_API_KEY 等外部模型金鑰
GRAFANA_OAUTH_CLIENT_SECRETGrafana SSO 用戶端金鑰
LANGFUSE_KEYCLOAK_CLIENT_SECRETLangfuse SSO 用戶端金鑰
LANGFUSE_PUBLIC_KEY / SECRET_KEYLangfuse 專案金鑰（LiteLLM 上報用）
ALERT_WEBHOOK_URL告警通知 webhook（釘釘/企微/飛書或 AI 管理中心）
✅ 一鍵部署腳本 bootstrap.ps1 會自動替換 IP、產生隨機金鑰、起容器、初始化 Keycloak、配 NewAPI 渠道、註冊備份任務。推薦新機部署優先用它。

2.3 Keycloak 認證設定

Keycloak 是整個平台的認證中樞。目前為生產模式（start + PostgreSQL）。需要設定：

  • Realm：enterprise-ai；
  • 角色：ai-platform-admin（管理員角色）；
  • OIDC Client：AI-all-in-one-admin-portal、grafana、langfuse、newapi（均為 confidential）；
  • LDAP 聯合：vendor=AD，指向網域控制站，bind DN 用帶空格的 CN（CN=ai all in one admin,CN=Users,DC=chxia,DC=lab）。
📌 可用 scripts/keycloak-realm-init.ps1 一鍵建 realm + 用戶端 + 角色 + LDAP 聯合（替代手工點 UI）。注意：Keycloak realm 的內部 id 是 UUID，腳本裡 LDAP 元件的 parentId 要用真實 id。

2.4 LLM 渠道設定

鏈路：用戶端 → NewAPI（3000）→ LiteLLM（4001）→ 外部模型。

  1. 在 NewAPI 後台「渠道」頁新建渠道，指向 LiteLLM：Base URL http://IP:4001/v1，填入 LITELLM_MASTER_KEY；
  2. 在 litellm-config.yaml 中設定模型列表（deepseek-chat 等）與對應 API Key；
  3. NewAPI「令牌」頁為員工/應用發放 API Key（sk- 開頭）。

2.5 SSO 單一登入

GrafanaOAuth2 generic OIDCGF_AUTH_OAUTH_AUTO_LOGIN=true 自動登入

2.6 PII 脫敏設定

雙保險，均掛在 LiteLLM 代理上，default_on 全量生效：

  • LiteLLM 內建正則：脫敏中文手機號、身分證、銀行卡、信箱、統一信用代碼、護照、IP + 敏感詞攔截；
  • Presidio：識別英文人名/信箱/信用卡等（analyzer: 5002，anonymizer: 5001）。
⚠️ 邊界：只對「經 LiteLLM 的模型呼叫」生效，不脫敏其他產品資料庫裡已存的資料。

2.7 監控 / 日誌 / 告警

  • 監控：Prometheus（9091）抓 cadvisor + 各 exporter；Grafana（3030）展示大盤；
  • 告警：Alertmanager（9093）→ webhook（預設發到 AI 管理中心的告警接收端點，可改釘釘/企微/飛書）；
  • 日誌：Promtail 採集所有容器日誌 → Loki（3110），AI 管理中心「統一日誌」頁查詢；
  • 日誌輪轉：compose 全域 x-logging（單容器 10MB × 3 份），防止日誌無限增長。

2.8 備份與還原

備份腳本 scripts/backup.ps1 每日 02:00 計畫任務執行，涵蓋：NewAPI MySQL、Dify PG、Ghost/Gitea/Grafana SQLite、Keycloak（realm export JSON）、Langfuse PG、設定檔。還原用 scripts/restore.ps1 或 AI 管理中心「備份與還原」頁。

📌 Keycloak 必須用 realm export/import（JSON） 備份，不能只用 pg_dump（會丟 default role 關聯）。詳見第三章 3.13。

第三章管理（各工具使用說明）

本章逐節介紹每個管理工具「怎麼進、能做什麼、日常做什麼」。統一入口建議用 AI 管理中心（:10086），左側選單已內嵌大部分產品。

3.1 Keycloak 管理

入口：http://IP:9090 → Administration Console → 用 ai_all_in_one_admin 登入。

日常做什麼：

  • 管理使用者、重設密碼、分配 ai-platform-admin 角色；
  • 管理 OIDC 用戶端（新增產品接 SSO 時在此建 client）；
  • 查看/調整 LDAP 聯合（對接 AD 網域帳號）；
  • 查看登入會話、強制下線。

3.2 NewAPI 管理

入口：http://IP:3000，用統一帳號登入。

日常做什麼：

  • 渠道：管理上游模型渠道（指向 LiteLLM），增刪模型；
  • 令牌：為員工/應用發放、停用、設額度、設過期時間的 API Key；
  • 日誌：查每次呼叫的使用者/模型/token/額度/成本/來源 IP；
  • 使用者：充值額度、提額、封禁。
📌 用戶端 IP 記錄依賴使用者的「記錄 IP 日誌」設定（預設關閉）。如需按 IP 統計，請在「個人設定」開啟，或由管理員統一開啟。

3.3 LiteLLM 管理

入口：http://IP:4001（除錯用 /v1/models）。設定在 litellm-config.yaml。

日常做什麼：

  • 增刪模型與對應 API Key；
  • 調整 PII 脫敏 guardrail（正則 + Presidio）；
  • 設定 Langfuse 上報（success_callback）。

3.4 Dify 管理

入口：http://IP（80 連接埠），用統一帳號（信箱 admin@company.com）登入。

日常做什麼：

  • 「工作室」建立應用（聊天助手 / Agent / 工作流程）；
  • 「知識庫」上傳文件、建知識庫問答；
  • 模型供應商接入（可指向內部 NewAPI/LiteLLM）；
  • 成員與權限管理、應用發佈。
📌 Dify 是獨立的官方 compose（dify/docker/），升級/維護時需在 dify/docker 目錄單獨操作，不在主 compose 裡。

3.5 Ghost 管理

入口：內容頁 http://IP:8090；後台 http://IP:8090/ghost/。

日常做什麼：

  • 發佈公告、新聞（Posts）；
  • 維護首頁、導航、主題（Attila）；
  • 上傳 DeepChat 安裝包等下載資源；

3.6 Gitea 管理

3.7 MCP Gateway 管理

入口：http://IP:3100。設定在 mcp-gateway/mcp-servers.json。

日常做什麼：

  • 管理 MCP 伺服器 / Skill 市場（skills/ 目錄）；
  • 增刪 MCP 服務連接，供 DeepChat / Dify 呼叫。

3.8 DeepChat 更新伺服器

入口：http://IP:8091（下載頁）；資料在 deepchat-updates/。

日常做什麼：

  • 放置新版本 DeepChat 安裝包（.exe/.dmg），更新 version.txt；
  • 透過 Gitea Actions（deepchat-sync）自動拉取 DeepChat 官方版本；
  • 維護 sync-config.json（版本源、保留份數、市場 URL）。
📌 DeepChat 用戶端報「模型連接超時」，通常是用戶端走了掛掉的系統代理（ECONNREFUSED 127.0.0.1:33210）。讓使用者在 DeepChat「設定 → 網路/代理」改為「不使用代理/直連」。

3.10 監控告警（Prometheus / Grafana）

入口：Grafana http://IP:3030（SSO 自動登入）；Prometheus http://IP:9091。

日常做什麼：

  • Grafana 大盤看容器 CPU/記憶體/網路；
  • Prometheus 查 targets 狀態、告警規則；
  • 告警經 Alertmanager（9093）發 webhook（預設發 AI 管理中心，可改釘釘/企微/飛書）。

3.11 LLM 可觀測（Langfuse）

入口：http://IP:3010，SSO 自動登入。

日常做什麼：查看每次模型呼叫的 prompt、回應、延遲、token、成本，用於品質分析與故障定位。

⚠️ 若用 Keycloak SSO 登入後「看不到資料」，是 SSO 帳號未加入組織 ai-all-in-one。需執行 SQL 把 SSO 使用者加入組織（ADMIN 角色），詳見部署文件踩坑記錄。

3.12 統一日誌（Loki）

入口：AI 管理中心「統一日誌」頁（更便捷），或 Loki http://IP:3110。

日常做什麼：按容器 + 關鍵字 + 時間範圍檢索所有容器日誌，排查問題。

📌 Loki 的 label 是 container / project / service，沒有 job。查詢用 {container=~".+"} 而非 {job="docker"}。

3.13 備份與還原

入口：AI 管理中心「備份與還原」頁（一鍵備份/還原/看狀態），或命令列 scripts/backup.ps1 / restore.ps1。

涵蓋範圍：NewAPI MySQL、Dify PG、Ghost/Gitea/Grafana SQLite、Keycloak（realm JSON）、Langfuse PG、設定檔。

⚠️ 關鍵坑（演練已驗證）：
  • Keycloak 必須用 realm export/import（JSON），pg_dump 還原會丟 default role 關聯導致起不來；
  • SQLite 檔案還原後屬主是 root，需 chown 到對應 uid（grafana=472、gitea=1000）否則報 readonly；
  • pg_dump 需帶 --clean --if-exists，否則還原衝突。

第四章一般使用者說明

4.1 快速上手

方式 A：用 DeepChat（推薦，日常對話）

  1. 開啟下載中心 http://IP:8090/downloads/，下載對應系統安裝包並安裝；
  2. DeepChat → 設定 → 模型服務 → 新增「自訂 Provider / OpenAI 相容」：
    API Base URL：http://IP:3000/v1
    API Key：NewAPI 後台「API 金鑰」頁自助申請（見 4.2）
    模型：deepseek-chat
  3. 儲存後即可對話。

方式 B：用 Dify（搭建應用 / 知識庫）

  1. 瀏覽器開啟 http://IP，用統一帳號登入；
  2. 「工作室」→ 建立應用（聊天助手 / Agent / 工作流程）；
  3. 編排頁面寫提示詞、接知識庫，發佈使用。

4.2 API Key 申請

  1. 開啟 NewAPI http://IP:3000，用統一帳號登入（或 OIDC 一鍵登入）；
  2. 「API 金鑰」→ 新建令牌；
  3. 複製 sk- 開頭的 Key，填入 DeepChat / Dify 等用戶端。
📌 預設額度有限，不足請聯絡管理員申請提額。

4.3 資料安全規範

平台已自動對手機號、身分證、銀行卡、信箱等敏感資訊脫敏，並對敏感詞攔截，但請自覺遵守：

❌ 嚴禁傳送到 AI 的資料

  • 內部機密 / 商業機密（未公開的產品程式碼、定價、客戶名單、合約條款等）；
  • 個人隱私（身分證、銀行卡、密碼、健康資訊、他人隱私）；
  • 原始碼 / 未公開技術方案。

✅ 可以放心使用

  • 公開資料、通用知識、文件撰寫、翻譯、總結；
  • 脫敏後的業務資料（去掉具體人名/號碼/敏感欄位後）。
資料等級能否上外部大模型說明
公開資料✅ 可以已公開的資料、通用資訊
內部普通資料⚠️ 脫敏後可用去掉敏感欄位後可使用
內部機密 / 個人隱私❌ 禁止嚴禁傳送
判斷原則：「這段內容如果被外人看到會不會有問題？」會 → 別發。

4.4 常見問題

問題解決
登入不上某個產品確認用內網 IP（非 localhost）且用統一帳號，仍不行聯絡管理員
提示額度不足NewAPI 後台查餘額；額度用完聯絡管理員充值/提額
傳送內容被攔截命中了敏感詞或含敏感資訊，按 4.3 規範調整後重試
DeepChat 報連接超時設定 → 網路/代理 → 改為「不使用代理/直連」
模型回覆品質差換用不同模型，或最佳化提問（提供上下文、明確要求）
AI 的回答能信嗎不能全信，重要結論務必人工核實（AI 可能幻覺）

4.5 行為準則

  • 不用於違法違規用途，不產生違法、有害、侵權內容；
  • 不繞過平台安全限制，不批次刷額度；
  • 對外傳送 AI 產生內容時，核實事實並遵守公司資訊發佈規範。
