# AI AllInOne 用户手册

*v0.2 · 员工使用指南*

**快速开始**

## 1. 认识平台

> 📌 说明：本手册里的 `IP` 指公司内网服务器地址（示例 `192.168.31.117`，实际以管理员公布为准）。所有地址都用**内网 IP**，不要用 `localhost` 或 `127.0.0.1`。
### 1.1 平台是什么
「AI AllInOne」是公司内网部署的一套企业 AI 平台，把大模型（DeepSeek、GPT、Claude 等）的能力统一收口到内网，员工**一个账号**就能用。你不需要关心背后的服务器、模型、密钥——只需要记住三个入口。
### 1.2 我能用平台做什么
| 想做什么 | 用哪个 | 在哪打开 |
| --- | --- | --- |
| 像 ChatGPT 一样日常对话、写文档、翻译、改代码 | 💬 DeepChat | 桌面客户端（先从门户下载安装） |
| 用公司搭好的 AI 应用（客服问答、审批助手等） | 🤖 Dify | 浏览器 `http://IP` |
| 上传文档做「知识库问答」（问内部资料） | 🤖 Dify | 浏览器 `http://IP` |
| 看公司新闻、公告、下载软件 | 📰 门户（Hub） | 浏览器 `http://IP:8090` |
| 自己申请 API Key 接第三方工具 | 🔑 NewAPI | 浏览器 `http://IP:3000` |
### 1.3 三个入口怎么选
> ✅ **一句话记住**：**聊天/写作/翻译 → DeepChat**；**公司搭好的应用/知识库 → Dify**；**找东西/看公告/下软件 → 门户 Hub**。三个都用同一个账号登录。
登录方式：所有产品都走 **Keycloak 统一账号**（部分支持公司 AD 域账号，即你电脑开机那套账号）。点「登录」自动跳统一登录页，输一次账号，之后各产品无需重复登录。
### 1.4 本手册怎么用
- **新手**：按顺序读第 2~4 章，先装上 DeepChat 用起来；
- **要接第三方工具**：读第 5 章申请 Key；
- **有疑问**：先查第 7 章 FAQ，再问管理员；
- **必读**：第 6 章数据安全、第 8 章行为准则，人人都要遵守。

## 2. AI All In One Hub（门户）

### 2.1 门户是什么
Ghost**AI All In One Hub** 是公司的企业门户（基于开源软件 Ghost 搭建），地址 `http://IP:8090`。它是你进入 AI 平台的**起点**。
### 2.2 看新闻 / 公告
1. 浏览器打开 `http://IP:8090`；
2. 首页就是最新新闻、公告列表，点标题读全文。
### 2.3 下载中心（装 DeepChat）
1. 点门户顶部「**下载中心**」菜单，或直接打开 `http://IP:8090/downloads/`；
2. 按系统选 **Windows** / **macOS** 安装包，下载 **DeepChat**；
3. 安装：Windows 双击 .exe 按向导；macOS 打开 .dmg 拖进「应用程序」。
> ✅ 下载页顶部「首次使用先装技能管家」是给高级用户的技能包，普通用户可忽略。
### 2.4 跳转到 Dify / 帮助
- 点门户菜单「**AI 工作台**」→ 直接跳 Dify（AI 应用平台）；
- 点「**帮助文档**」→ 查看公司整理的帮助文章。
> 📖 原厂文档：门户由 Ghost 提供，官方文档 https://ghost.org/docs/

## 3. 工具一：DeepChat

### 3.1 下载与安装
1. 打开门户下载中心 `http://IP:8090/downloads/`；
2. 按系统下载安装包并安装；
3. 启动 DeepChat。
### 3.2 配置模型（连公司网关）
首次使用需要告诉 DeepChat 模型在哪。公司已把模型统一收口到网关 **NewAPI**，你只需填三个值：
1打开 DeepChat → 左下角 **设置（⚙️）** → **模型服务 / 模型提供商**。
2添加「**自定义 Provider**」或「**OpenAI 兼容**」。
3填入以下三项：
| 字段 | 填什么 |
| --- | --- |
| API Base URL | `http://IP:3000/v1` |
| API Key | 在 NewAPI 申请的 `sk-` 密钥（见第 5 章） |
| 模型 | `deepseek-chat`（公司默认，可选其它已开放模型） |
4保存。
> ⚠️ **关键**：API Base URL 必须用**内网 IP**（`http://IP:3000/v1`），不要用 `localhost`，否则连不上公司服务器。
### 3.3 开始对话
1. 点「**+ 新建对话**」；
2. 输入框打字，回车发送；
3. 收到回复即链路正常。
### 💡 **试一试**：发送「帮我写一封给客户的催款邮件，语气委婉」看 AI 如何回答。再试试「把下面这段话翻译成英文：……」。DeepChat 支持多轮对话，可继续追问、让 AI 修改。

    3.4 常用功能与技巧
| 功能 | 怎么用 |
| --- | --- |
| 多模型切换 | 对话顶部选不同模型（若公司开放多个） |
| 文件读写 / MCP 工具 | 设置 → MCP 启用公司工具（如文件系统），让 AI 读本地文件 |
| 深色/浅色主题 | 设置 → 外观 |
| 网络代理问题 | 报「连接超时」→ 设置 → 网络/代理 → 改为「不使用代理/直连」 |
### 3.5 提问技巧
> ✅ **越具体越好**——提供背景、说清要求、给示例，AI 回答质量更高。
- 💡 好例子：「你是资深文案，帮我写一段 200 字的产品介绍，面向 CTO 读者，风格专业克制」——比「写个介绍」好得多。
    
      **给角色**：「你是一名财务专家，帮我……」；
- **给约束**：「控制在 100 字以内 / 用表格 / 分三步」；
- **给示例**：「参照这个格式改写……」；
- **分步追问**：不满意就「再改改」「换个语气」。
> 📖 原厂文档：DeepChat 快速开始 https://deepchatai.cn/docs/guide/getting-started/ · 开源仓库 https://github.com/ThinkInAIXYZ/deepchat

## 4. 工具二：Dify

### 4.1 登录 Dify
1. 浏览器打开 `http://IP`（80 端口，无端口号；也可从门户「AI 工作台」点进来）；
2. 用统一账号登录（首次可能需管理员先开通账号）。
### 4.2 用现成的聊天应用
管理员会预先搭好一些应用（如「公司制度问答」「客服助手」），普通用户直接「用」即可：
1. 登录后进入「**工作室 / 应用**」列表；
2. 找到要用的应用，点「**运行 / 预览**」（右上角播放键）；
3. 在打开的对话页直接提问。
### 4.3 知识库问答
想把内部文档「喂」给 AI 让它回答，用 Dify 的**知识库**（需管理员给权限）：
1. 「**知识库**」→「创建知识库」；
2. 上传文档（支持 Word / PDF / Markdown / 网页链接等）；
3. 系统自动分段、建索引；
4. 在应用里「引用」这个知识库，AI 就能基于你的文档回答。
> 📌 知识库内容会被 AI 用于回答，请遵守第 6 章数据安全规范——**不要上传机密资料**。
### 4.4 自己搭一个简单应用（进阶）
1. 工作室 → 创建空白应用 → 选「聊天助手」；
2. 写一段「提示词」告诉 AI 它的角色（如「你是公司考勤制度答疑助手」）；
3. 加知识库 → 选模型 → 预览测试 → 发布。
> 📖 原厂文档：Dify 官方文档 https://docs.dify.ai

## 5. 申请 API Key

如果你要把公司的 AI 能力接入**第三方工具**（自己的脚本、其它支持 OpenAI 接口的软件），需要一个 API Key（`sk-` 开头的密钥）。
### 5.1 登录 NewAPI
1. 浏览器打开 `http://IP:3000`；
2. 用统一账号登录（或点「一键登录 / OIDC」用域账号）。
### 5.2 新建令牌
1. 左侧菜单「**API 密钥 / 令牌**」；
2. 点「**新建令牌**」，起名（如 `我的脚本`），可设额度、过期时间；
3. 保存后复制生成的 `sk-xxxx` 字符串。**只显示一次，务必立即保存**。
### 5.3 填入客户端
- **API Base URL**：`http://IP:3000/v1`
- **API Key**：刚才复制的 `sk-xxxx`
### 5.4 常见用法示例
> 💡 用 curl 测试：  
> 
>     `curl http://IP:3000/v1/chat/completions -H "Authorization: Bearer sk-xxxx" -H "Content-Type: application/json" -d '{"model":"deepseek-chat","messages":[{"role":"user","content":"你好"}]}'`
> 
>     ⚠️ 额度用完后报「余额不足」，联系管理员申请提额。Key 相当于你的账号密码，**不要发给别人、不要提交到代码仓库**。
> 📖 原厂文档：NewAPI 官方文档 https://docs.newapi.pro · 官网 https://www.newapi.ai

## 6. 数据安全规范

平台已自动对**手机号、身份证号、银行卡号、邮箱**等敏感信息做**脱敏**（发给大模型前自动打码），并对敏感词做拦截。但请自觉遵守下面的红线。
### 6.1 什么能发什么不能发
#### ❌ 严禁发送给 AI
- 内部机密 / 商业机密（未公开的产品代码、定价、客户名单、合同条款）；
- 个人隐私（身份证号、银行卡号、密码、健康信息、他人隐私）；
- 源代码 / 未公开技术方案。
#### ✅ 可以放心使用
- 公开资料、通用知识、文档撰写、翻译、总结；
- 脱敏后的业务数据（去掉具体人名/号码/敏感字段后）。
### 6.2 数据分级速查
| 数据等级 | 能否上外部大模型 | 说明 |
| --- | --- | --- |
| 公开数据 | ✅ 可以 | 已公开的资料、通用信息 |
| 内部普通数据 | ⚠️ 脱敏后可用 | 去掉敏感字段后可使用 |
| 内部机密 / 个人隐私 | ❌ 禁止 | 严禁发送 |
> > 判断原则：**「这段内容如果被外人看到会不会有问题？」**会 → 别发。
### 6.3 三个典型场景
| 场景 | 怎么做 |
| --- | --- |
| 写周报，涉及客户名 | 用「某客户」「A 客户」代替真实客户名 |
| 让 AI 分析数据表 | 先删掉姓名、电话、身份证号等列，只留汇总数据 |
| 翻译合同条款 | 先删掉金额、对方名称等敏感信息，或用「甲方/乙方」代替 |

## 7. 常见问题 FAQ

### 7.1 登录 / 访问类
| 问题 | 解决 |
| --- | --- |
| 登录不上某个产品？ | 确认用内网 IP（不是 localhost）且用统一账号；仍不行联系管理员 |
| 登录页面打不开 / 一直转圈？ | 确认连的是公司内网（WiFi/有线），地址用 `http://IP` 而非 localhost |
| 忘记统一账号密码？ | 联系管理员重置（或走域账号找回） |
### 7.2 使用类
| 问题 | 解决 |
| --- | --- |
| 提示额度不足？ | NewAPI 后台查余额；用完联系管理员充值/提额 |
| 发送内容被拦截？ | 命中了敏感词或含敏感信息，按第 6 章规范调整后重试 |
| DeepChat 报连接超时？ | 设置 → 网络/代理 → 改为「不使用代理/直连」 |
| 模型回复质量差？ | 换不同模型，或优化提问（提供上下文、明确要求、给示例） |
| 忘了在哪下 DeepChat？ | 门户下载中心 `http://IP:8090/downloads/` |
| Dify 创建应用一直转圈？ | 通常是网络/WebSocket 问题，联系管理员；浏览器 Ctrl+F5 强刷 |
### 7.3 认知类
| 问题 | 解决 |
| --- | --- |
| AI 的回答能信吗？ | 不能全信。AI 可能出错（幻觉），重要事实、数字、代码务必人工核实 |
| AI 会记住我说的话吗？ | 当前对话上下文会被保留用于多轮回答，请勿输入机密信息（见第 6 章） |

## 8. 行为准则

### 8.1 使用规范
- 不用于违法违规用途，不生成违法、有害、侵权内容；
- 不绕过平台安全限制，不批量刷额度；
- 对外发送 AI 生成内容时，核实事实并遵守公司信息发布规范；
- 妥善保管自己的 API Key，不转借他人、不提交到代码仓库；
- 发现异常（账号异常、内容异常）及时报告管理员。
### 8.2 一句话总结
> ✅ 善用 AI 提效，但**机密不发、事实必核、规矩要守**。有问题联系平台管理员。
