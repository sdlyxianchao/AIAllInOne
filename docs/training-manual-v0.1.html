Chapter 1Introduction

1.1 What is the platform

"AI AllInOne" is an enterprise AI platform deployed on the company intranet. It centralizes LLM capabilities so employees can use everything with a single account. It orchestrates more than a dozen open-source products with Docker into one integrated system, with Keycloak providing unified identity.

Core capabilities:

  • Unified login: one account (optionally federated to corporate AD) logs into every product;
  • Unified model gateway: all model calls go through NewAPI + LiteLLM, with automatic audit, billing, and redaction;
  • PII redaction: phone numbers / IDs / emails are masked before reaching the model;
  • AI apps: Dify for visually building agents, knowledge-base Q&A, and workflows;
  • Observability & ops: monitoring/alerting, LLM tracing, unified logging, backup/restore, availability tests, report generation.

1.4 Unified account & SSO

The platform uses a "one account for all products" policy:

  • Unified admin account: ai_all_in_one_admin (password in credentials.html);
  • This account is federated to the corporate AD domain (LDAP) via Keycloak, with a local account as fallback;
  • Grafana, Langfuse, NewAPI, and the AI Admin Center all use Keycloak SSO — some with auto-login (click a link and go straight in);
  • Employees use the unified account (or AD account) to log into DeepChat / Dify.
📌 If SSO login fails with unknown_error, it's usually because the host's IP Helper service (iphlpsvc) is not running, breaking AD port forwarding (389) — not a Keycloak config problem. Run as admin: Start-Service iphlpsvc and re-add the netsh interface portproxy rules.

Chapter 2Configuration

2.1 Pre-deployment

  1. Install Docker Desktop (Windows) or Docker Engine (Linux/online), and start it.
  2. Prepare networking: ensure access to Docker image registries (Docker Hub / quay.io — if unreachable, configure a mirror such as DaoCloud) and GitHub; decide the intranet IP to expose.
  3. (Optional) Prepare AD: if integrating corporate accounts, the domain controller must be reachable, with bind DN, bind password, and LDAP base DN ready.
  4. Prepare model API keys: DeepSeek / OpenAI / Claude, at least one.

2.2 Env vars & secrets

2.3 Keycloak

Keycloak is the auth hub, currently in production mode (start + PostgreSQL). Configure:

  • Realm: enterprise-ai;
  • Role: ai-platform-admin;
  • OIDC clients: AI-all-in-one-admin-portal, grafana, langfuse, newapi (all confidential);
  • LDAP federation: vendor=AD, pointing at the domain controller; bind DN uses the space-containing CN (CN=ai all in one admin,CN=Users,DC=chxia,DC=lab).
📌 Use scripts/keycloak-realm-init.ps1 to create the realm + clients + role + LDAP federation in one shot. Note: the realm's internal id is a UUID, and the LDAP component's parentId must use it.

2.4 LLM channels

Chain: client → NewAPI (3000) → LiteLLM (4001) → external model.

  1. In NewAPI "Channels", point a channel at LiteLLM: Base URL http://IP:4001/v1, with LITELLM_MASTER_KEY;
  2. Configure the model list (deepseek-chat, etc.) and keys in litellm-config.yaml;
  3. Issue API keys (sk-) to employees/apps in NewAPI "Tokens".

2.6 PII redaction

Two layers, both on the LiteLLM proxy with default_on:

  • LiteLLM built-in regex: masks Chinese phone numbers, IDs, bank cards, emails, credit codes, passports, IPs + sensitive-word blocking;
  • Presidio: detects English names/emails/credit cards (analyzer: 5002, anonymizer: 5001).
⚠️ Scope: applies only to model calls going through LiteLLM; it does not redact data already stored in other products' databases.

2.7 Monitoring / logging / alerting

  • Monitoring: Prometheus (9091) scrapes cadvisor + exporters; Grafana (3030) shows dashboards;
  • Alerting: Alertmanager (9093) → webhook (defaults to the AI Admin Center's alert endpoint; can point to DingTalk/WeCom/Feishu);
  • Logging: Promtail collects all container logs → Loki (3110), queried via the "Unified Logs" page;
  • Log rotation: global x-logging in compose (10 MB × 3 per container) prevents unbounded growth.

2.8 Backup & restore

scripts/backup.ps1 runs daily at 02:00, covering: NewAPI MySQL, Dify PG, Ghost/Gitea/Grafana SQLite, Keycloak (realm export JSON), Langfuse PG, and config files. Restore via scripts/restore.ps1 or the AI Admin Center's "Backup & Restore" page.

📌 Keycloak must be backed up via realm export/import (JSON), not pg_dump alone (which loses the default-role association). See 3.13.

Chapter 3Administration (per-tool guide)

Each section covers "how to enter, what you can do, what you do daily". Recommended single entry: the AI Admin Center (:10086).

3.1 Keycloak

Entry: http://IP:9090 → Administration Console → log in as ai_all_in_one_admin.

Daily tasks:

  • Manage users, reset passwords, assign the ai-platform-admin role;
  • Manage OIDC clients (create a client when onboarding a new product to SSO);
  • View/adjust LDAP federation (AD accounts);
  • View sessions and force logout.

3.2 NewAPI

Entry: http://IP:3000, unified account.

Daily tasks:

  • Channels: manage upstream model channels (pointing to LiteLLM);
  • Tokens: issue/disable API keys, set quotas and expiry;
  • Logs: inspect user/model/tokens/quota/cost/source IP per call;
  • Users: top up quota, raise limits, ban.
📌 Client IP recording depends on the user's "Record IP log" setting (off by default). Enable it in Personal Settings, or have an admin enable it globally.

3.3 LiteLLM

Entry: http://IP:4001 (debug with /v1/models). Config in litellm-config.yaml.

Daily tasks:

  • Add/remove models and their API keys;
  • Adjust PII guardrails (regex + Presidio);
  • Configure Langfuse reporting (success_callback).

3.4 Dify

Daily tasks:

3.10 Monitoring (Prometheus / Grafana)

Entry: Grafana http://IP:3030 (SSO auto-login); Prometheus http://IP:9091.

Daily tasks:

  • Check targets and alert rules in Prometheus;

3.11 LLM observability (Langfuse)

Entry: http://IP:3010, SSO auto-login.

Daily tasks: inspect prompt, response, latency, tokens, and cost of every model call for quality analysis and debugging.

⚠️ If you "see no data" after Keycloak SSO login, the SSO account isn't in the ai-all-in-one org. Run SQL to add the SSO user to the org (ADMIN role) — see the deployment guide gotchas.

3.12 Unified logs (Loki)

Entry: AI Admin Center "Unified Logs" page (easier), or Loki http://IP:3110.

Daily tasks: search all container logs by container + keyword + time range.

📌 Loki labels are container / project / service — there's no job label. Query {container=~".+"} instead of {job="docker"}.

3.13 Backup & restore

Entry: AI Admin Center "Backup & Restore" page (one-click backup/restore/status), or scripts/backup.ps1 / restore.ps1.

Coverage: NewAPI MySQL, Dify PG, Ghost/Gitea/Grafana SQLite, Keycloak (realm JSON), Langfuse PG, config files.

⚠️ Critical gotchas (verified in drills):
  • Keycloak must use realm export/import (JSON); pg_dump restore loses the default-role association and won't boot;
  • SQLite files restored via docker cp end up owned by root — chown to the correct uid (grafana=472, gitea=1000) or they report readonly;
  • pg_dump needs --clean --if-exists or restores conflict.

Chapter 4End-user guide

4.1 Getting started

Option A: DeepChat (recommended for daily chat)

  1. Open the download center http://IP:8090/downloads/ and install the client for your OS;
  2. DeepChat → Settings → Model service → add "Custom Provider / OpenAI-compatible":
    API Base URL: http://IP:3000/v1
    API Key: self-service from NewAPI "API Keys" (see 4.2)
    Model: deepseek-chat
  3. Save and start chatting.

Option B: Dify (build apps / knowledge base)

  1. Open http://IP and log in with the unified account;
  2. "Studio" → create an app (chat assistant / agent / workflow);
  3. Write prompts, attach a knowledge base, and publish.

4.2 API key request

  1. Open NewAPI http://IP:3000 and log in (or one-click OIDC);
  2. "API Keys" → create a token;
  3. Copy the sk- key into DeepChat / Dify.
📌 Default quota is limited; contact an admin to raise it if needed.

4.3 Data safety rules

The platform auto-masks phone numbers, IDs, bank cards, emails, and blocks sensitive words, but please comply:

❌ Never send to AI

  • Internal/confidential secrets (unreleased code, pricing, customer lists, contracts);
  • Personal privacy (IDs, bank cards, passwords, health info, others' privacy);
  • Source code / unreleased technical designs.

✅ Safe to use

  • Public material, general knowledge, document writing, translation, summarization;
  • Redacted business data (after removing names/numbers/sensitive fields).
Data levelExternal model?Notes
Public✅ OKAlready-public material, general info
Internal ordinary⚠️ after redactionOK once sensitive fields are removed
Internal confidential / personal❌ ForbiddenNever send
Rule of thumb: "Would it be a problem if an outsider saw this?" If yes → don't send it.

4.5 Code of conduct

  • No illegal or harmful use; don't generate illegal, harmful, or infringing content;
  • Don't bypass platform security or bulk-drain quota;
  • When sharing AI-generated content externally, verify facts and follow company publishing rules.

Contact the platform admin if you have questions.
