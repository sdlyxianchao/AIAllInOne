Keycloak AD 集成 — 本地 Active Directory 账号导入

本文档是 windows-deploy-guide.html 的附加文档，涵盖将本地 Active Directory 域控接入 Keycloak，使员工用域账号登录所有 AI 平台应用。适用于 Hyper-V 本地 DC 测试环境。

1. 前置条件

  • Keycloak 容器能访问 AD 域控的 LDAP 端口（默认 389 或 636（LDAPS））
  • 有一个 AD 服务账号（格式：CN=svc_keycloak,OU=ServiceAccounts,DC=company,DC=com）
  • 已按主文档完成 Keycloak 部署和 Realm 创建

2. Hyper-V 本地 DC 测试环境搭建

2.1 场景说明

网络隔离：Docker Desktop (WSL2) 和 Hyper-V Default Switch 处于不同虚拟网络，容器无法直接访问 DC VM。必须通过 Windows 宿主机做端口转发。以下内容适用于 Windows 11 + Docker Desktop + Hyper-V 本地测试。

2.2 启用 Hyper-V 并创建 DC 虚拟机

# 管理员 PowerShell — 启用 Hyper-V（需重启）
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V-All

# 下载 Windows Server 评估版 ISO（180 天免费）
# https://www.microsoft.com/en-us/evalcenter/evaluate-windows-server
  1. Hyper-V 管理器 → 新建虚拟机 → 名称 test-dc，第二代
  2. 内存：2048 MB，关闭动态内存
  3. 网络：暂时选择 Default Switch（先完成系统安装，后续再切换到 Internal Switch）
  4. 硬盘：40 GB，挂载 Windows Server ISO

2.3 安装 AD DS 并提升为域控

先用 Default Switch 完成 Windows Server 安装和 AD DS 部署；网络固定 IP 在 下一节 中配置。

# VM 内部 — 安装完成后，先设置临时静态 IP（Default Switch NAT 网段，ipconfig 查看）
netsh interface ip set address "Ethernet" static 172.25.80.100 255.255.240.0 172.25.80.1
netsh interface ip set dns "Ethernet" static 127.0.0.1

# 安装 AD DS 角色并提升为域控
Install-WindowsFeature -Name AD-Domain-Services -IncludeManagementTools
Install-ADDSForest -DomainName "testcompany.local"   -SafeModeAdministratorPassword (ConvertTo-SecureString "Passw0rd!" -AsPlainText -Force)   -InstallDNS -Force
# VM 自动重启

2.4 配置 Docker 与 Hyper-V DC 网络互通

当前网络结构下，Docker Desktop (WSL2) 和 Hyper-V DC 位于两个隔离的虚拟网络。要让 Keycloak 容器访问 DC，需要在 Windows 宿主机上建立一条稳定的转发路径。

一键检测 + 修复脚本

推荐使用统一脚本：setup-hyperv-dc-network.ps1
  • 用法 1：.\setup-hyperv-dc-network.ps1 — 检测 + 自动修复 + 连通性验证
  • 用法 2：.\setup-hyperv-dc-network.ps1 -Detect — 仅检测当前状态，不做任何修改

脚本覆盖：虚拟交换机创建 / 宿主机 IP 配置 / DC VM 网卡添加 / NAT 规则 / portproxy 端口转发 / 防火墙规则 / 三层连通性验证。管理员 PowerShell 运行。

方案对比

方案适用场景优点缺点
Default Switch + portproxy临时测试无需新建交换机DC IP 由 DHCP 分配，重启后可能变化，需重新配置转发
Internal Switch + 静态 IP + portproxy长期稳定运行（推荐）DC 和宿主机 IP 固定，转发规则长期有效需要新建 Hyper-V 虚拟交换机并手动配 IP
External Switch 绑定物理网卡有独立有线网卡DC 与宿主机同网段USB WiFi 通常不支持；会导致宿主机网络中断或不稳定
针对你的适配器情况：截图显示当前活动网卡是 WLAN 8（TP-LINK USB WiFi），以太网口未启用。不建议把 External Switch 绑定到 USB WiFi 上，推荐直接使用下面的 Internal Switch 方案。

手动步骤（参考）

如果不想用脚本，手动执行以下三条命令链。脚本内部也是做同样的事。

  1. 创建 Internal 虚拟交换机 + 宿主机 IP + NAT 
    # 管理员 PowerShell
New-VMSwitch -Name "DockerDCBridge" -SwitchType Internal

# 给宿主机侧的虚拟网卡配固定 IP
$ifAlias = (Get-NetAdapter | Where-Object { $_.Name -like "*DockerDCBridge*" }).InterfaceAlias
New-NetIPAddress -InterfaceAlias $ifAlias -IPAddress 192.168.99.1 -PrefixLength 24

# （可选）给 DC 提供上网能力
New-NetNat -Name "DockerDC-NAT" -InternalIPInterfaceAddressPrefix 192.168.99.0/24
  2. 给 DC VM 添加网卡连接新交换机（不中断 DC 运行，保留原有 Default Switch NIC） 
    Add-VMNetworkAdapter -VMName DC -SwitchName "DockerDCBridge"
  3. 在 DC VM 内部给新 NIC 设置静态 IP

    进入 DC VM 控制台，管理员 CMD/PowerShell（先用 ipconfig 找到新增的网卡名）：

    netsh interface ip set address "Ethernet 3" static 192.168.99.10 255.255.255.0 192.168.99.1
netsh interface ip set dns "Ethernet 3" static 127.0.0.1

    如果网卡名称不是 Ethernet 3，先用 Get-NetAdapter 查看。

临时：Default Switch 方案

如果不想创建 Internal Switch，可以继续使用 Default Switch，但建议把 DC IP 改成该 NAT 网段内的固定地址，或在 Hyper-V NAT 中做 MAC 地址保留。每次 DC IP 变化后，都需要重新执行下一节的 portproxy 命令。

# 查看 DC 当前 IP（进 VM 里执行 ipconfig 最准）
ipconfig

# 或者从宿主机查看 ARP 表
arp -a | findstr "DC-MAC-address"

2.5 创建测试用户和服务账号

至少需要以下账号，Keycloak 导入时用服务账号做 LDAP 绑定：

账号类型说明
svc_keycloak服务账号（必须）Keycloak LDAP 绑定用的只读账号，密码见 .env.windows
2 个普通域用户测试用任意域账号（如 zhangsan / lisi），用于验证 Keycloak 同步和域账号登录
密码策略：服务账号 svc_keycloak 应设为"密码永不过期"，避免 LDAP 绑定中断。生产环境建议用 Group Managed Service Account (gMSA)。
# DC VM 内，以 Administrator@testcompany.local 登录后执行
New-ADUser -Name "svc_keycloak" -SamAccountName "svc_keycloak" `
  -AccountPassword (ConvertTo-SecureString "Service@1234" -AsPlainText -Force) -Enabled $true

Get-ADUser -Filter * | Select-Object Name, SamAccountName, Enabled

3. Docker 容器访问 Hyper-V DC（端口转发）

3.1 为什么需要端口转发

网络拓扑：
  • Docker Desktop 容器网络：WSL2 虚拟网络（独立于 Hyper-V）
  • Hyper-V DC VM：位于 Internal Switch 私网（推荐：192.168.99.0/24）或 Default Switch NAT 网段
  • 两者互通方案：通过 Windows 宿主机 netsh portproxy 将宿主机端口转发到 Hyper-V VM
  • 容器通过 host.docker.internal 访问宿主机，再由端口转发到达 DC VM

3.2 配置端口转发

以下命令假设已按 2.4 节 使用 Internal Switch，DC VM 固定 IP 为 192.168.99.10。如果继续使用 Default Switch，把 connectaddress 换成 DC 当前的动态 IP。

脚本已覆盖此步骤：setup-hyperv-dc-network.ps1 会自动完成 portproxy + 防火墙配置，无需手动执行。

手动配置（参考）

# 管理员 PowerShell
# 先删除旧规则（避免重复添加）
netsh interface portproxy delete v4tov4 listenport=389
netsh interface portproxy delete v4tov4 listenport=636

# 添加 LDAP/LDAPS 端口转发；listenaddress=0.0.0.0 保证 host.docker.internal 也能命中
netsh interface portproxy add v4tov4 listenport=389 listenaddress=0.0.0.0 connectport=389 connectaddress=192.168.99.10
netsh interface portproxy add v4tov4 listenport=636 listenaddress=0.0.0.0 connectport=636 connectaddress=192.168.99.10

# 开放防火墙
netsh advfirewall firewall add rule name="DC-LDAP" dir=in protocol=tcp localport=389 action=allow
netsh advfirewall firewall add rule name="DC-LDAPS" dir=in protocol=tcp localport=636 action=allow

# 验证转发
netsh interface portproxy show all
Test-NetConnection -ComputerName 127.0.0.1 -Port 389
Test-NetConnection -ComputerName 192.168.99.10 -Port 389

3.3 验证 Docker 容器可连接 DC

Keycloak 官方镜像是 RHEL UBI 9（非 Alpine），不含 apk。用 bash TCP 重定向验证：

# 快速 TCP 连通性验证
docker exec keycloak bash -c 'exec 3<>/dev/tcp/host.docker.internal/389 && echo "LDAP reachable" && exec 3>&-'

# 如需完整 LDAP 查询，用 ldapsearch（需先在容器内安装）
docker exec keycloak sh -c "microdnf install -y openldap-clients 2>/dev/null; ldapsearch -H ldap://host.docker.internal:389 -D 'CN=svc_keycloak,CN=Users,DC=testcompany,DC=local' -w <密码> -b 'CN=Users,DC=testcompany,DC=local' '(objectClass=user)'"
# 预期：返回 zhangsan、lisi、svc_keycloak 等用户

脚本中的 Phase 3 也会自动执行连通性验证。

4. Keycloak 连接 AD 并同步用户

4.1 创建 LDAP 用户联合

  1. Keycloak 管理后台 → 选择 enterprise-ai Realm
  2. 左侧 User Federation → Add provider → 选择 ldap
  3. 填写配置：

General options（通用选项）

配置项值说明
UI display nameCompany ADKeycloak 管理界面的显示名称，随意填
VendorActive Directory选 AD（不要选 Other，否则 objectGUID 等 AD 特定属性无法识别）

Connection and authentication settings（连接与认证）

配置项值说明
Connection URLldap://host.docker.internal:389Hyper-V 测试环境经宿主机端口转发。生产环境直接填域控 FQDN 如 ldap://dc.company.local:389
Enable StartTLSOffAD 用 LDAP 端口 389（明文）或 LDAPS 端口 636（TLS），StartTLS 是另一种升级加密方式，一般不启用
Use Truststore SPIAlways仅 LDAPS 有用；使用 LDAP 明文时不影响，保持 Always 即可
Connection poolingOff默认关。大量并发时可按需开启
Connection timeout留空使用 Keycloak 默认超时值
Bind typesimple标准用户名+密码认证
Bind DNCN=svc_keycloak,CN=Users,DC=testcompany,DC=local必须是 LDAP Distinguished Name 格式！不要用 NetBIOS 格式（DOMAIN\用户）。完整路径见下方说明
Bind credentials服务账号密码svc_keycloak 的密码，见 .env.windows

LDAP searching and updating（搜索与更新）

配置项值说明
Edit modeREAD_ONLY只读。Keycloak 不会向 AD 写入任何数据
Users DNCN=Users,DC=testcompany,DC=local用户所在的目录容器。如果有子 OU 需要一起搜，改为更靠上的 DN（如 DC=testcompany,DC=local）
Username LDAP attributesAMAccountName关键：这是 AD 的登录名属性，不要填 cn。用户登录时用 zhangsan 而非 张三
RDN LDAP attributecn条目的命名属性。AD 中每个对象的 RDN 通常是 cn
UUID LDAP attributeobjectGUIDAD 中不可变的唯一标识。即使改用户名、移动 OU，objectGUID 不变
User object classesperson, organizationalPerson, userAD 用户对象的所有类。顺序不用特别在意，用逗号分隔
User LDAP filter留空如需过滤（如只要某个部门的用户），可填 (department=IT)。留空 = 所有对象类匹配的用户
Search scopeSubtree关键：递归搜索 Users DN 下的所有子 OU。不要选 One Level，否则子 OU 中的用户搜不到
Read timeout留空默认值
PaginationOn推荐开启。如果 AD 用户很多（>1000），分批拉取避免超时
ReferralignoreAD 有时会返回其他域控的引用。选 ignore 避免 Keycloak 跟到不存在的域控上

Synchronization settings（同步设置）

配置项值说明
Import usersOn手动触发全量同步时导入新用户
Sync RegistrationsOn用户首次登录时，Keycloak 实时查询 AD 并即时创建本地用户记录
Batch size留空每批导入用户数，默认 1000
Periodic full syncOff测试阶段手动同步。生产环境可以开（如每天凌晨一次）
Periodic changed users syncOffAD 增量同步需 AD 启用 USNChanged 轮询，一般不需要

Kerberos integration（Kerberos 集成）

配置项值说明
Allow Kerberos authenticationOff不用 Kerberos。Keycloak 直接用 LDAP simple bind 验证密码
Use Kerberos for password authenticationOff同上

Cache settings（缓存）

配置项值说明
Cache policyDEFAULTKeycloak 默认缓存策略，平衡性能与一致性

Advanced settings（高级设置）

配置项值说明
Enable LDAPv3 password modifyOffREAD_ONLY 模式下无需修改 AD 密码
Validate password policyOff让 AD 自身管理密码策略
Trust EmailOnAD 导入的用户邮箱自动标记为已验证，避免 "email not verified" 状态。关闭则每个用户在 Keycloak 中显示邮箱未验证
  1. 点击 Save
  2. 保存成功后点击 Synchronize all users — 等待同步完成
  3. 去 Users 页面确认域用户已出现
常见填错：
  • Bind DN 格式：必须用 LDAP 格式 CN=账号,CN=Users,DC=xxx,DC=local，不要用 NetBIOS 格式 DOMAIN\账号
  • Username LDAP attribute ≠ cn：填 sAMAccountName，这是 AD 登录名。填 cn 会导致用户无法用短账号登录
  • Search scope：如果域用户分散在多个 OU 中（例如 OU=IT,OU=Hangzhou,...），必须选 Subtree

4.2 配置 LDAP 组映射（可选）

将 AD 组映射为 Keycloak 角色：

  1. 在 User Federation 列表点击刚创建的 LDAP Provider
  2. Mappers 标签 → 添加 group-ldap-mapper
  3. 设置 Groups DN：CN=Users,DC=testcompany,DC=local
  4. 保存后会自动将 AD 组映射到 Keycloak

4.3 验证

  1. 确认用户已导入：Keycloak 管理后台 → Users → 应能看到 AD 同步过来的域用户列表。如果是第二次同步，Console 会显示 0 imported users, N updated users — "0 imported" 只表示没有新用户，不代表失败。

方式 A：通过 Keycloak Account Console 测试（推荐，最简单）

Keycloak 自带账号自助页面，无需配置任何下游应用，可直接测试 AD 域账号是否能完成登录。

  1. 打开浏览器（推荐隐私/无痕窗口，避免 Session 缓存干扰）
  2. 访问 http://127.0.0.1:9090/realms/enterprise-ai/account
  3. 在登录页面输入 AD 域用户的凭证：
    • 用户名：aitest1（sAMAccountName）或 aitest1@<公司域名>（UPN），两种格式均可
    • 密码：该域用户在 AD 中设置的密码
  4. 点击 Sign In
  5. 预期结果：页面跳转到 Account Console，右上角显示用户名，可看到个人信息、安全设置
如果登录失败：
  • Invalid username or password → 密码错误或用户不在 Users DN 范围内。在 DC 上确认密码，检查 Keycloak 的 Users DN 是否正确
  • Account is disabled → 该 AD 用户在域控中被禁用（Enabled = False）
  • 无反应 / 白屏 → 按 F12 打开开发者工具 → Console + Network 面板查看错误详情

方式 B：通过 Keycloak Admin Console 验证用户状态

  1. Keycloak 管理后台 → Users
  2. 搜索域用户名（如 aitest1）
  3. 点击用户 → Attributes 标签：应能看到 LDAP_ID、LDAP_ENTRY_DN 等属性，说明用户来源是 LDAP 同步而非本地创建
  4. Sessions 标签：如果已用方式 A 登录成功，这里会有一条活跃会话记录

方式 C：接入下游应用后测试（后续步骤）

Keycloak AD 登录链路打通后，任何接入 Keycloak OIDC SSO 的应用都会在登录页展示 Keycloak 登录表单，直接输入域账号即可。例如 Dify 配置完 SSO 后，浏览器打开 http://127.0.0.1/apps → 自动跳转到 Keycloak 登录页 → 输入 aitest1 + 域密码 → 登录成功进入 Dify 工作台。

三种验证方式任一通过即表示 AD → Keycloak 链路正常。方式 A 最直接，推荐优先使用。

6. 清理（测试完成后）

# 停止并删除 DC VM
Stop-VM DC -Force
Remove-VM DC

# 删除端口转发
netsh interface portproxy delete v4tov4 listenport=389
netsh interface portproxy delete v4tov4 listenport=636

# 删除防火墙规则
netsh advfirewall firewall delete rule name="DC-LDAP"
netsh advfirewall firewall delete rule name="DC-LDAPS"

# 删除 NAT 和 Internal Switch
Remove-NetNat -Name "DockerDC-NAT" -Confirm:$false
Remove-VMSwitch -Name "DockerDCBridge" -Force

# 如果还有旧 InternalSwitch（Private 类型，仅 VM 间通信），一并清理
Remove-VMSwitch -Name "InternalSwitch" -Force
