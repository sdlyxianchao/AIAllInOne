> **خادم واحد. حساب واحد. حزمة ذكاء اصطناعي مؤسسية متكاملة — مفتوحة المصدر ومجانية، والبيانات لا تغادر الإنترانت.**

AI AllInOne هي منصة ذكاء اصطناعي **مفتوحة المصدر ومجانية** وجاهزة للاستخدام داخل إنترانت المؤسسة: دخول موحّد (SSO)، توجيه نماذج LLM، تطبيقات ذكاء اصطناعي، بوابة المؤسسة، الشيفرة المصدرية/CI، إدارة موحّدة، مراقبة وتنبيهات، قابلية الملاحظة، سجلات، ونسخ احتياطي واستعادة — كل ذلك مُنسّق معًا بواسطة Docker في حزمة واحدة. **يستطيع الموظف تسجيل الدخول مرة واحدة بحساب واحد لاستخدام جميع أدوات الذكاء الاصطناعي.**

## ✨ لماذا تختار AI AllInOne

| | |
|---|---|
| 🧩 **حزمة متكاملة بلا تجميع** | أكثر من 8 مكونات مفتوحة المصدر مدمجة مسبقًا: المصادقة، البوابة، التطبيقات، بوابة المؤسسة، Git، المراقبة، السجلات، النسخ الاحتياطي. لا حاجة إلى "تجميع" يدوي. |
| 🔐 **دخول موحّد (SSO)** | حساب واحد في Keycloak (يدعم الاتحاد مع AD/LDAP) يسجّل الدخول تلقائيًا إلى جميع المنتجات دون الحاجة إلى كلمة مرور إضافية. |
| 🔒 **البيانات لا تغادر الإنترانت** | استضافة ذاتية بالكامل — استدعاءات النماذج والوعود والوثائق وبيانات المستخدمين تبقى داخل المؤسسة. |
| ⚡ **نشر في نحو 30 دقيقة** | `docker compose` + نصوص برمجية آلية، أو دع وكيل الذكاء الاصطناعي ينشر لك البيئة كاملة. |
| 🛡️ **إخفاء PII** | المعلومات الحساسة مثل رقم الهاتف/رقم الهوية/البريد الإلكتروني تُخفى تلقائيًا قبل استدعاء النماذج الخارجية (Presidio). |
| 📊 **قابلية ملاحظة على كامل المسار** | مراقبة عبر Prometheus + Grafana، تتبّع LLM عبر Langfuse، سجلات موحّدة عبر Loki، وتنبيهات عبر تراسل المؤسسة (DingTalk/WeCom/Feishu). |
| 💾 **نسخ احتياطي واستعادة** | نسخ احتياطي كامل يومي واستعادة بنقرة واحدة من لوحة الإدارة. |
| 🌐 **9 لغات** | الأدلة وواجهة الإدارة متعددة اللغات (صينية مبسطة/صينية تقليدية/إنجليزية/فرنسية/إسبانية/برتغالية/يابانية/كورية/عربية). |

## 📦 قائمة المكونات

| الطبقة | المكوّن | الوظيفة |
|---|---|---|
| المصادقة | Keycloak | SSO / OIDC، اتحاد AD/LDAP أو حسابات محلية |
| توجيه LLM | NewAPI | القنوات والمفاتيح والحصص والتدقيق والتكاليف |
| إخفاء PII | LiteLLM + Presidio | إخفاء المعلومات الحساسة تلقائيًا قبل استدعاء النماذج |
| تطبيقات الذكاء الاصطناعي | Dify | تطبيقات ذكاء اصطناعي مرئية / منصة وكلاء + قاعدة معرفة موحّدة (RAG) |
| بوابة المؤسسة | Ghost | بوابة إعلانات وأخبار الشركة (تتضمن قالب Corp Portal مخصصًا مدمجًا) |
| الشيفرة المصدرية / CI | Gitea + Runner | Git داخلي + أتمتة Actions |
| العميل | DeepChat | عميل ذكاء اصطناعي محلي لسطح المكتب (Windows / macOS / Linux) |
| توزيع العميل | Update Server | استضافة حزم تثبيت DeepChat وتحديثها تلقائيًا |
| الإدارة الموحّدة | AI Admin Center | نقطة دخول موحّدة: لوحة تحكم + منتجات مدمجة + تدقيق/تكاليف/تقارير + تفويض إداري متدرج + مزامنة/أدوار Keycloak |
| البوابة | MCP Gateway | سوق المهارات/MCP + استرجاع معرفة Dify (RAG) |
| المراقبة | Prometheus + Grafana + Alertmanager | مراقبة موارد الحاويات + إشعارات التنبيه |
| قابلية ملاحظة LLM | Langfuse | تتبّع زمن الاستجابة والرموز (tokens) وتكلفة كل استدعاء للنموذج |
| السجلات الموحّدة | Loki + Promtail | تجميع سجلات جميع الحاويات، قابلة للبحث حسب الحاوية/الكلمة المفتاحية/الوقت |
| النسخ الاحتياطي والاستعادة | نصوص برمجية + صفحة إدارة | نسخ احتياطي كامل يومي + استعادة بنقرة واحدة |

## 🚀 البداية السريعة

**المتطلبات المسبقة**: جهاز مثبّت عليه Docker (Windows 11 + Docker Desktop، أو Linux) مع إمكانية الوصول إلى مستودع صور Docker.

```bash
git clone https://github.com/sdlyxianchao/AIAllInOne AIAllInOne
cd AIAllInOne/windows
# شغّل الخدمات الأساسية، ثم ابدأ تهيئة المصادقة / قنوات LLM / المنتجات وفق دليل النشر
docker compose up -d
```

بعد ذلك لديك خياران:

1. **النشر التلقائي (موصى به)** — فوّض النشر إلى وكيل الذكاء الاصطناعي (WorkBuddy / OpenClaw / Microsoft Scout). سيقرأ وثائق النشر وملفات الإعدادات، ويجمع منك المعاملات (عنوان IP الخادم، مصدر الهوية، حساب المسؤول، مفاتيح LLM)، ثم يُنجز جميع الإعدادات خطوة بخطوة. 1. اسألني أولًا: ما هو المسار المحلي لفك الضغط/الاستنساخ لهذا المشروع؟ (مثلًا C:\AIAllInOne أو /opt/AIAllInOne)
2. بعد الدخول إلى هذا الدليل، حدد دليل المنصة المستهدفة وفقًا لنظام تشغيل الجهاز الحالي:

3. قبل البدء، اقرأ ملف README.md في الدليل الجذر وملف README داخل دليل المنصة لفهم البنية وطريقة النشر.

## الخطوة 2: جمع المعاملات المطلوبة واحدًا تلو الآخر (اسألني عن كل بند ولا تتخطَّ أو تخمّن)
1. عنوان IP للإنترانت (أو اسم النطاق) الذي تُعرَّض به المنصة، أي العنوان الذي تصل إليه الأجهزة الأخرى (مثل 192.168.1.100 أو portal.company.com).
2. مصدر الهوية (Identity Provider):
   - نطاق تحكم AD للشركة: اسألني عن اسم النطاق وعنوان IP لوحدة التحكم بالمجال (DC) وLDAP base DN وbind DN وكلمة مرور حساب bind وsAMAccountName وغيرها.
   - موفرو الهوية الآخرون (LDAP/OpenLDAP/OIDC/Feishu/WeCom/DingTalk وغيرها): اسألني عن الإعدادات المقابلة ومعلومات الحساب.
   - لا يوجد مصدر هوية خارجي (حسابات محلية فقط): تخطَّ بعد تأكيدي.
3. حساب المسؤول الموحّد: اسم المستخدم وكلمة المرور والبريد الإلكتروني (لتسجيل الدخول عبر SSO في Keycloak وحسابات إدارة المنتجات).
4. مفاتيح LLM API: ما هي مزوّدو النماذج والمفاتيح المتاحة لدي فعليًا (DeepSeek / OpenAI / Claude / Qwen / Tongyi / ERNIE وغيرها)؛ وتخطَّ ما ليس متاحًا.
5. لغة المحتوى النموذجي لبوابة Ghost: الصينية، أو ترجمتها إلى لغة أخرى قبل الاستيراد.
6. أسئلة أخرى حسب الحاجة: اسم مضيف سوق مهارات MCP (Windows)، وقنوات إشعارات التنبيه (webhook لـ DingTalk/WeCom/Feishu)، وشهادات HTTPS، وسياسة الاحتفاظ بالنسخ الاحتياطي، وغيرها.

## الخطوة 3: إنشاء ملف تقدم محلي
1. ابحث عن وثيقة «قائمة التقدم» داخل دليل المنصة (*-checklist*.html) ودليل «ربط مصدر الهوية» (مثل *-ad-integration*.html أو الوثائق ذات الصلة بـ IdP).
2. استنادًا إلى محتوى القائمة، أنشئ ملف تقدم في دليل المشروع باسم مثل "deployment-progress-<platform>-<date>.md"، وانسخ كل بند في القائمة كبند غير مكتمل (- [ ]).
3. بعد ذلك، كلما أكملت بندًا أو حللت مشكلة، حدّث ملف التقدم فورًا وأبلغني بملخص التقدم في المحادثة.

## الخطوة 4: الإعداد خطوة بخطوة وفق دليل النشر
1. اقرأ وثيقة «دليل النشر» للمنصة (مثل *-deploy-guide*.html) بعناية والتزم بها بدقة، مع إيلاء اهتمام خاص للعناصر الموسومة بـ«⚠️ المخاطر الحاسمة».
2. الترتيب التقريبي: تجهيز متغيرات البيئة ← تشغيل الحاويات ← تهيئة المصادقة/IdP ← إعداد توجيه LLM وقنوات النماذج ← تهيئة المنتجات (بوابة Ghost: نشر قالب Corp Portal المدمج واستيراد المحتوى النموذجي) ← إعداد المراقبة/قابلية الملاحظة/السجلات/إخفاء الهوية ← إعداد النسخ الاحتياطي والاستعادة.
3. استخدم أولًا النصوص البرمجية الآلية داخل الدليل (مثل bootstrap.ps1 وkeycloak-realm-init.ps1 وghost-setup.ps1 وghost-theme-setup.ps1 وghost-content-import.ps1 وhealth-check.ps1 وغيرها)، ولا تُنجز يدويًا عبر الواجهة الخطوات التي يمكن أتمتتها بنص برمجي.

## الخطوة 5: الاختبار التكراري وحل المشكلات معًا
1. عند فشل خطوة ما أو عدم مطابقتها للتوقعات، افحص السجلات أولًا (docker logs ونقاط فحص الحالة للخدمات وملفات الإعدادات) لتحديد السبب الجذري قبل الإصلاح، ولا تُعد المحاولة دون تشخيص.
2. عندما تحتاج مشاركتي (مثلًا لتنفيذ أوامر تتطلب صلاحيات المسؤول أو تأكيد تسجيل الدخول أو تزويد معلومات إضافية)، أخبرني بوضوح «ماذا ستفعل ولماذا».
3. بعد الحل، سجّل السبب الجذري والإصلاح في ملف التقدم وأبلغني بملخص موجز.

## الخطوة 6: تحقق كامل من طرف إلى طرف
بعد اكتمال جميع بنود القائمة، نفّذ اختبارًا كاملًا من طرف إلى طرف يغطي على الأقل:
- صحة الخدمات (جميع الحاويات في حالة Up ونقاط فحص الحالة تعمل بشكل طبيعي);
- تسجيل الدخول الموحّد (SSO) (تسجيل الدخول في Keycloak ← الدخول التلقائي/SSO في المنتجات);
- مسار LLM (إرسال محادثة حقيقية عبر NewAPI/LiteLLM للتحقق من الاستجابة وتفعيل إخفاء PII);
- تسجيل الدخول عبر مصدر الهوية (إذا كان AD/مزوّد هوية آخر مربوطًا، اختبر تسجيل الدخول بالحساب المقابل);
- المراقبة/قابلية الملاحظة/السجلات/التنبيهات (تأكد من وجود البيانات وإمكانية تفعيل التنبيهات);
- النسخ الاحتياطي والاستعادة (نفّذ نسخة احتياطية وتحقق من إمكانية الاستعادة).

في النهاية، لخّص نتائج الاختبار بندًا بندًا مع وسم واضح ✅ نجح / ❌ فشل؛ وللعناصر الفاشلة اذكر السبب الجذري والتوصيات اللاحقة.

## 🔒 ملاحظات الأمان

- لا يحتوي هذا المستودع على **أي مفاتيح حقيقية**؛ القيم الحقيقية موجودة فقط في ملف `.env` لكل بيئة تشغيل (لا يُرفع في المستودع سوى قالب `.env.example`).
- HTTP نصي افتراضيًا داخل الإنترانت؛ راجع أدلة نشر كل منصة لإعداد HTTPS.
- المخاطر وجداول المنافذ وتدفق البيانات لكل منصة موجودة في وثائق `*-deploy-guide*.html` المقابلة.
