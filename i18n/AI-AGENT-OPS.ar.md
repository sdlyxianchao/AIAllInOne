# دليل تشغيل المنصة عبر وكيل الذكاء الاصطناعي

> 📖 **اللغات**: [English](../AI-AGENT-OPS.md) · [简体中文](AI-AGENT-OPS.zh.md) · [繁體中文](AI-AGENT-OPS.zh-TW.md) · [Français](AI-AGENT-OPS.fr.md) · [Español](AI-AGENT-OPS.es.md) · [Português](AI-AGENT-OPS.pt.md) · [日本語](AI-AGENT-OPS.ja.md) · [한국어](AI-AGENT-OPS.ko.md) · [العربية](AI-AGENT-OPS.ar.md)

صُمّمت هذه المنصة لتُدار وتُصان **عبر وكيل ذكاء اصطناعي** — مثل WorkBuddy أو OpenClaw أو Microsoft Scout أو أي أداة مماثلة. فبدلاً من تسجيل الدخول إلى عشرات لوحات الإدارة والنقر عبر الواجهات، تخبر الوكيل بما تريده بلغة طبيعية، فيقرأ الملفات وينفّذ الأوامر ويتواصل مع الخدمات نيابةً عنك.

يشرح هذا الدليل كيفية استخدام وكيل الذكاء الاصطناعي في التشغيل اليومي: فحوصات السلامة، وإدارة الحاويات، وتعديل الإعدادات، ومركز إدارة الذكاء الاصطناعي، وGitea/المزامنة، وبوابة Ghost، والنسخ الاحتياطي، والإصدارات، وحلّ المشكلات.

---

## 1. كيف يعمل الأمر

كل ما يجعل المنصة تعمل موجود على جهازك المحلي بصيغة **كود وإعدادات وبيانات**:

- **Docker Compose** يحدّد جميع الحاويات.
- **ملفات `.env`** (مثل `windows/.env.windows`) تحفظ بيانات الاعتماد التي تستخدمها الخدمات.
- **واجهات الإدارة (Admin APIs)** تكشف نقاط الإدارة (Keycloak وGitea وNewAPI وغيرها).
- **الملفات وقواعد البيانات** (قاعدة SQLite الخاصة بـ Ghost، وملفات تثبيت DSH Desktop، وملف JSON لسجلّ المزامنة، إلخ) هي الحالة الفعلية.

يستطيع الوكيل:

- **قراءة وتعديل** أي ملف — الإعدادات، والسكربتات، وملفَّي `index.html` / `server.js` في مركز إدارة الذكاء الاصطناعي، والمستندات.
- **تنفيذ الأوامر** — `docker` و`docker compose` و`git` وPowerShell وNode.js وPython.
- **استدعاء الخدمات عبر HTTP** — واجهات الإدارة، ونقاط التحقق من السلامة، وروابط التحميل.
- **البحث في الويب** عن وثائق المنتجات عند الحاجة.

ولأن كل شيء هو مجرد ملفات + أوامر + واجهات، فإن الوكيل يستطيع رؤيتها كلها وتغييرها كلها — ولهذا يمكنك تشغيل المنصة بأكملها عبره.

---

## 2. التحضير (مرة واحدة)

1. **افتح مجلد المشروع في الوكيل.** وجّه دليل عمل الوكيل إلى جذر المشروع (مثل `C:\AIAllInOne`). هناك يقرأ `docker-compose.yml` وملفات `.env` والسكربتات والمستندات.
2. **تأكد من أن Docker Desktop يعمل.** معظم العمليات هي أوامر `docker` / `docker compose`. إذا كان Docker Desktop متوقفًا، فعادةً ما تكون أول خطوة للوكيل هي التحقق منه وتشغيله.
3. **ضع بيانات الاعتماد في `.env` وليس في المحادثة.** يقرأ الوكيل كلمات مرور الخدمات من `windows/.env.windows`. لا تلصق كلمات مرور حقيقية في المحادثة أو في ملفات مخزّنة في المستودع.
4. **أخبره بمجلد المنصة الذي سيستخدمه** إذا لم يكن واضحًا (`windows/` في معظم حالات الجهاز الواحد).

## 3. ما الذي يستطيع الوكيل فعله

| المهمة | كيف يقوم بها الوكيل |
|---|---|
| فحص السلامة / نظرة عامة على الحالة | `docker ps` + نقاط التحقق من السلامة + واجهات الإدارة |
| تشغيل / إعادة تشغيل / إيقاف الخدمات | `docker compose up -d <svc>` / `docker restart <svc>` |
| الاطلاع على السجلات والأخطاء | `docker logs <svc> --tail N`، وقراءة ملفات السجل |
| تغيير الإعدادات | تعديل الملفات ثم إعادة تشغيل الحاوية المتأثرة |
| تعديل مركز إدارة الذكاء الاصطناعي | تعديل `admin-portal/public/index.html` (الواجهة) أو `admin-portal/server.js` (الواجهة البرمجية) |
| إدارة Gitea والمزامنة | واجهة Gitea: تشغيل مسارات العمل، وقراءة حالة التشغيل/السجلات، وتعديل ملفات المستودع |
| إدارة بوابة Ghost | قراءة/كتابة قاعدة SQLite الخاصة بـ Ghost، وتعديل قوالب القالب، واستيراد المحتوى النموذجي |
| النسخ الاحتياطي والاستعادة | `scripts/backup.ps1` / `scripts/restore.ps1` |
| نشر إصدار | `publish.ps1` (بناء + إيداع + دفع إلى GitHub) |
| التنظيف | `docker image prune`، وحذف النسخ القديمة، إلخ (بعد تأكيدك) |
| حلّ المشكلات | تعارض المنافذ، ومشكلات Docker Desktop، وDNS/البروكسي، إلخ |

## 4. المهام الشائعة وأمثلة الأوامر

فيما يلي المهام التي ستكررها كثيرًا، مع مثال لكل واحدة. يمكنك قولها بلغتك — سيفهمها الوكيل. استبدل `<…>` بالقيم الفعلية.

### 4.1 فحص سلامة كل شيء

> «تحقق من أن جميع الخدمات تعمل وبصحة جيدة. اذكر أي حاوية متوقفة أو تعيد التشغيل بشكل متكرر، وأخبرني بالسبب.»

ينفّذ الوكيل `docker ps` ويستدعي كل نقطة تحقق من السلامة ويبلّغ بالحالة.

### 4.2 التحقيق في خدمة متوقفة أو بها خطأ

> «LiteLLM متوقفة. اكتشف السبب وأصلحه، ثم أكّد أنها عادت للعمل.»

يفحص الوكيل حالة الحاوية ويقرأ السجلات ويجد السبب الجذري (مثل تعارض منفذ) ويصلحه.

### 4.3 إعادة تشغيل خدمة

> «أعد تشغيل بوابة الإدارة لكي يسري التعديل على server.js.»

ينفّذ الوكيل `docker restart admin-portal`. ملاحظة: تعديل الكود **الخلفي** (`server.js`) يتطلب إعادة تشغيل الحاوية؛ أما تعديل **الواجهة** (`index.html`) فلا يتطلب سوى تحديث المتصفح.

### 4.4 الاطلاع على السجلات

> «أرني آخر 50 سطرًا من سجل Gitea runner وأخبرني إن كانت هناك أخطاء.»

### 4.5 إدارة مزامنة DSH Desktop (Gitea)

> «شغّل مسار عمل dsh-sync وأرني تقدّمه — المرحلة، وعدد الملفات المنزّلة، والميجابايت، والوقت المتبقي.»

يستدعي الوكيل واجهة Gitea لتشغيل مسار العمل، ثم يستقصي حالة التشغيل ويقرأ `sync-progress.json`.

### 4.6 تغيير مركز إدارة الذكاء الاصطناعي

> «أضف ترقيم الصفحات إلى قائمة مستودعات Gitea — 10 عناصر في الصفحة، قابلة للتعديل.»

يعدّل الوكيل `index.html` ويتحقق من JavaScript و(عند تعديلات الخلفية) يعيد تشغيل الحاوية. ثم تقوم أنت بالتحديث القسري للمتصفح (Ctrl+F5).

### 4.7 إدارة بوابة Ghost

> «استورد المحتوى النموذجي إلى البوابة، باستخدام العنوان 192.168.1.100 وباللغة الصينية.»

يسأل الوكيل عن عنوان النشر واللغة، ثم ينفّذ `ghost-content-import.ps1`. ويمكنه أيضًا إصلاح القوالب وتعديل الصفحات وتغيير قائمة التنقل مباشرة في قاعدة البيانات.

### 4.8 النسخ الاحتياطي والاستعادة

> «نفّذ نسخة احتياطية كاملة الآن وأكّد نجاحها.»

### 4.9 نشر إصدار على GitHub

> «انشر إصدارًا جديدًا v0.7 برسالة 'feat: …'.»

ينفّذ الوكيل `publish.ps1 -Version v0.7 -CommitMessage "…"`. ملاحظة: يتطلب `git push` توفر البروكسي أو بيانات اعتماد GitHub — إذا فشل الدفع بسبب الشبكة، سيطلب منك الوكيل فتح البروكسي.

### 4.10 تنظيف مساحة القرص

> «أرني ما الذي يستهلك مساحة قرص Docker وما الذي يمكن حذفه بأمان.»

يمسح الوكيل (`docker system df` والصور غير المستخدمة والأحجام والنسخ القديمة) ويعرض المرشحين — **ولا يحذف إلا بعد أن تؤكد أيّها تريد حذفه.**

## 5. أفضل الممارسات والمزالق

- **تحديث الواجهة مقابل الخلفية.** في مركز إدارة الذكاء الاصطناعي، تسري تعديلات `index.html` بمجرد تحديث المتصفح (الملف مُثبّت كحجم)؛ بينما تتطلب تعديلات `server.js` تنفيذ `docker restart admin-portal` — فالأمر العادي `docker compose up -d` **لا** يعيد تحميل الكود المُثبّت كحجم.
- **حدّث المتصفح قسريًا** (Ctrl+F5) عندما تبدو الواجهة بلا تغيير — فغالبًا ما يكون JavaScript القديم مخزّنًا في الذاكرة المؤقتة.
- **لا تخزّن أبدًا أسرارًا أو عناوين IP حقيقية.** استخدم عناصر نائبة (مثل `<服务器IP>` و`CHANGE_ME_*`). يقوم `publish.ps1` تلقائيًا بتنظيف كلمات مرور `server.js`.
- **تحقّق ولا تصدّق عمياءً.** اطلب من الوكيل إثبات النتائج بالأوامر (أكواد HTTP و`ls` وأسطر السجل)، خاصة عند ادعاء «تم الإصلاح».
- **اعمل نسخة احتياطية قبل التغييرات الهدّامة.** يجب أن ينسخ الوكيل قاعدة Ghost أو الإعدادات احتياطيًا قبل تعديلها، ويؤكد معك قبل حذف أي شيء.
- **اسأل عن اللغة والعنوان قبل استيراد المحتوى.** عند استيراد محتوى البوابة، يجب أن يسأل الوكيل أولًا عن عنوان النشر واللغة المستهدفة.
- **الشبكة والبروكسي.** تحتاج بعض الخطوات (الدفع إلى GitHub، والبحث في الويب) إلى البروكسي (مثل `127.0.0.1:33210`) أو اتصال خارجي. إذا فشلت خطوة شبكية، افتح البروكسي وأعد المحاولة.

## 6. مرجع سريع للأوامر

| الإجراء | الأمر |
|---|---|
| عرض الحاويات | `docker ps -a` |
| سجلات حاوية | `docker logs <الاسم> --tail 100` |
| إعادة تشغيل خدمة | `docker restart <الاسم>` |
| تشغيل جميع الخدمات | `docker compose up -d` |
| حالة Compose | `docker compose ps` |
| تشغيل مزامنة Gitea | `POST /api/v1/repos/<user>/dsh-sync/actions/workflows/sync.yml/dispatches` |
| تنفيذ نسخة احتياطية | `powershell .\scripts\backup.ps1` |
| نشر إصدار | `powershell .\publish.ps1 -Version v0.x -CommitMessage "…"` |
