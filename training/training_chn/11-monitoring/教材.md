# 监控告警 教材（M13 · Prometheus + Grafana + Alertmanager）

> 端口：cadvisor `8080`（内部）、Prometheus `9091`、Grafana `3030`；告警规则 `monitoring/alerts.yml`，Alertmanager 配置 `monitoring/alertmanager.yml`。

## 1. 架构与数据流

```
容器 → cadvisor(采集 CPU/内存/网络/磁盘) → Prometheus(汇聚+告警规则)
       → Grafana(:3030 大盘「AI All In One — 容器监控」)
       → Alertmanager → AI 管理中心(/api/alert-webhook) → 企业 IM(钉钉/企微/飞书)
```

## 2. 登录与常用操作

- Grafana：`http://<服务器IP>:3030`，账号 `ai_all_in_one_admin` / 统一密码（OAuth 自动登录）。
- 大盘：左侧 → Dashboards →「AI All In One — 容器监控」。
- 常用筛选：按容器名（`container` 标签）、按指标（CPU/内存/网络）。
- Prometheus：`http://127.0.0.1:9091` → Targets（抓取状态）、Alerts（告警规则）、Graph（PromQL）。

## 3. 预置告警规则（alerts.yml）

| 规则 | 级别 |
|---|---|
| 容器宕机 | critical |
| 容器内存 > 90% | warning |
| 容器 CPU > 80% | warning |

**⚠️ 两个防误报过滤（务必理解，改规则时保留）**：
1. `{name!=""}`：cadvisor 会上报宿主机所有 cgroup（systemd 服务等，无 name 标签），不过滤会对系统服务误报。
2. `container_spec_memory_limit_bytes > 0`：limit=0 的容器除零产生 `+Inf` 恒触发，需排除。

## 4. IM 告警配置（AI 管理中心）

路径：AI 管理中心 → **系统运维 → 企业 IM 告警**（配置存 Redis，重启不丢）：

- **多接收人**：群机器人（钉钉/企微/飞书，填 webhook 地址）或企业应用（钉钉/企微发个人：AppKey/AppSecret/AgentId/userid 或 corpId/secret/agentid/userid）。
- **发送规则**：总开关、最低告警级别（严重/警告/信息）、是否发送 firing/resolved 通知。
- **发送历史**：时间/接收人/类型/告警名/级别/结果，可检索筛选。
- 兼容 `.env` 的 `ALERT_IM_WEBHOOK_URL` 作为默认接收人。

## 5. 常见问题

| 问题 | 解决 |
|---|---|
| Prometheus 9090 被占用 | 平台用 **9091**（Keycloak 占 9090）；Grafana 用 **3030**（3000 被 NewAPI 占） |
| 告警误报 systemd 服务 | 规则需带 `{name!=""}` 过滤 |
| 内存告警恒触发 | 加 `container_spec_memory_limit_bytes > 0` |
| IM 收不到告警 | 检查 webhook 地址、级别过滤、发送规则开关；看发送历史 |
| 群机器人收不到 | webhook 只能发群聊；发个人需用企业应用 |
