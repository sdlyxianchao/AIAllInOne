# Keycloak 教材（M03 · 统一认证）

> 本教材以 AI AllInOne 平台内的实际用法为主线，官方通用概念为辅。平台内 Keycloak 端口 `9090`，Realm 名为 `enterprise-ai`。

## 1. Keycloak 是什么

Keycloak 是 Red Hat 开源的**身份与访问管理（IAM）**方案，提供：

- **SSO 单点登录**：一次登录，所有接入应用免登录。
- **协议支持**：OIDC（OpenID Connect）/ OAuth 2.0 / SAML 2.0。
- **用户联邦（User Federation）**：对接 AD/LDAP/Entra ID/Google 等外部身份源，无需在 Keycloak 重复建号。
- **管理控制台**：Web UI 管理 Realm、用户、客户端、角色、会话。

在本平台中，Keycloak 是**统一认证入口（SSO）**：**已接入 SSO 的产品**（AI 管理中心、NewAPI、Dify、Gitea、Grafana、Langfuse、LiteLLM，共 7 个）点「登录」→ 跳转 Keycloak（`http://<服务器IP>:9090`）→ 登录成功自动跳回原产品。**并非所有产品都接 SSO**：Ghost 走本地账号 + 邮箱验证码、DeepChat 桌面端直连 API Key、MCP Gateway 用 `X-Admin-Token`、Update Server / MailHog / Ollama 无登录或按 API Key 认证（完整清单见 §5 对照表）。

## 2. 平台内关键约定

| 约定 | 值 |
|---|---|
| 访问地址 | `http://127.0.0.1:9090`（本机）/ `http://<服务器IP>:9090`（内网） |
| Realm | `enterprise-ai`（平台所有产品共用） |
| 管理员账号 | `KEYCLOAK_ADMIN`（见 .env） |
| 统一管理员 | `ai_all_in_one_admin`，邮箱统一 `ai_all_in_one_admin@<公司域名>`（**所有产品一致，否则 SSO 串号**） |
| 统一管理角色 | Realm Role `ai-platform-admin` |
| 数据持久化 | H2 数据库，卷 `keycloak-data`，容器重建不丢配置 |
| 关键环境变量 | `KC_HOSTNAME=<服务器IP>`、`KC_HOSTNAME_STRICT=false`（两种地址都能跳转） |

## 3. 核心概念速查

| 概念 | 说明 | 平台内示例 |
|---|---|---|
| **Realm（领域）** | 相互隔离的用户/客户端/角色空间 | `enterprise-ai` |
| **Client（客户端）** | 接入 Keycloak 的应用 | `newapi`、`AI-all-in-one-admin-portal`、`grafana`、`langfuse`、`gitea` |
| **User（用户）** | 登录主体 | 本地账号 / AD 同步账号 |
| **Role（角色）** | 权限标识 | `ai-platform-admin`、`admin:<产品>` 分模块角色 |
| **Group（组）** | 用户分组 | `ai-admin`、`ai-user` |
| **User Federation（用户联合）** | 对接外部目录 | AD LDAP Provider |
| **Identity Provider（IdP）** | 对接外部登录源 | Entra ID / Google / GitHub / SAML |

**Client 访问类型（旧版 Access Type，了解即可）**：`public`（前端 SPA）、`confidential`（服务端应用，有 Secret）、`bearer-only`（纯 API）。

## 4. 标准操作流程

### 4.1 创建 Realm 与本地用户（方式 A）
1. 打开 `http://127.0.0.1:9090`，用 `.env` 中 `KEYCLOAK_ADMIN` / `KEYCLOAK_ADMIN_PASSWORD` 登录。
2. 左上角下拉 → **Create Realm** → 名称 `enterprise-ai` → Create。
3. **Groups** → 创建 `ai-admin`、`ai-user` 两个组。
4. **Users** → Add user → 填用户名 → **Credentials** 标签设置密码（Temporary 关掉）→ **Groups** 标签加入对应组。
5. ✅ 验证：用该用户在 Keycloak 登录页能登录。

### 4.2 创建 OIDC Client（平台内各产品接入标准步骤）
以 NewAPI 为例（其他产品同理，改 Client ID 与 redirect URI）：
1. `enterprise-ai` Realm → **Clients** → Create client。
2. Client ID：`newapi`，类型 **OpenID Connect** → Next。
3. **Client authentication：On**（⚠️ 必开，否则没有 Credentials 标签）；**Standard flow：On**；Direct access grants：按需 On。
4. **Valid redirect URIs**：`http://<服务器IP>:3000/*` 和 `http://127.0.0.1:3000/*` 都要加。
5. **Web origins**：同上两个地址 → Save。
6. **Credentials** 标签 → 复制 **Client secret**（填入各产品或 .env）。

> ⚠️ 保存后若产品侧生成了授权回调 URL，必须回 Keycloak 把回调 URL 加进 Valid redirect URIs，否则回调失败。

### 4.3 AD/LDAP 用户联合（方式 B，重点）
前置：容器到 DC 域控网络互通（见 `windows-ad-integration.html`）；AD 中建服务账号 `svc_keycloak`（密码永不过期）。

1. `enterprise-ai` Realm → **User Federation** → Add provider → **ldap**。
2. 关键配置（**常见填错项**已标注）：

| 配置项 | 值 | ⚠️ 注意 |
|---|---|---|
| Vendor | **Active Directory** | 选 AD，不要 Other |
| Connection URL | `ldap://host.docker.internal:389` | 经端口转发；生产用 `ldap://dc.company.com:389` |
| Bind DN | `CN=svc_keycloak,CN=Users,DC=testcompany,DC=local` | **必须 LDAP DN 格式**，不要 `DOMAIN\用户`；CN 带空格原样保留 |
| Edit mode | **READ_ONLY** | 不写回 AD |
| Users DN | `CN=Users,DC=testcompany,DC=local` | 有子 OU 时改上层 |
| Username LDAP attribute | **`sAMAccountName`** | 不要填 cn |
| RDN / UUID | `cn` / `objectGUID` | objectGUID 是 AD 不可变 ID |
| User object classes | `person, organizationalPerson, user` | |
| Search scope | **Subtree** | 不要 One Level，否则子 OU 搜不到 |
| Import users | On；Sync Registrations On | 首登即时同步 |

3. Save → **Synchronize all users** → 等待同步。
4. （可选）**Mappers** → 添加 `group-ldap-mapper`，映射 AD 组到 Keycloak 角色。

**✅ 三种验证方式**：
- A：无痕窗口访问 `http://127.0.0.1:9090/realms/enterprise-ai/account`，用 AD 账号登录（sAMAccountName 或 UPN 均可）。
- B：Admin Console → Users 搜索该用户 → Attributes 有 `LDAP_ID` / `LDAP_ENTRY_DN`。
- C：下游应用 SSO 登录（配好 Dify 等 OIDC 后）。

### 4.4 多身份源共存（了解）
Keycloak 可同时配置多个 IdP（AD + Entra ID + Google + GitHub + SAML）。最佳实践：Browser flow 中加 **Identity Provider Redirector**，按邮箱域名自动选择 IdP（如 `@company.com` → AD；`@company.onmicrosoft.com` → Entra ID；外部合作方 → 低权限角色）。

## 5. 平台内各产品 SSO 接入对照表

| 产品 | Keycloak Client | 接入方式 | 登录方式 |
|---|---|---|---|
| AI 管理中心 | `AI-all-in-one-admin-portal` | keycloak-connect (OIDC) | 强制 SSO（未登录自动跳 Keycloak） |
| NewAPI | `newapi` | OIDC | 登录页点「Keycloak/OIDC 登录」 |
| Dify | `dify`（部署时命名） | OIDC | Dify 设置 → 登录方式 → OIDC（已配置）；登录页走 Keycloak |
| Gitea | `gitea`（OIDC） | OIDC + 自动注册 | 登录页「Sign in with keycloak」 |
| Grafana | `grafana` | OAuth2 generic OIDC | 自动登录（`GF_AUTH_OAUTH_AUTO_LOGIN=true`） |
| Langfuse | `langfuse` | Keycloak provider | IdP 发起式 SSO（`/auth/sso-initiate?provider=KEYCLOAK`） |
| LiteLLM | `LITELLM_UI_CLIENT_ID`（.env） | 通用 OIDC | 统一账号基础认证；可开 `AUTO_REDIRECT_UI_LOGIN_TO_SSO` 自动跳转 |
| Ghost | —（本地账号） | 不接 SSO | 统一账号 `ai_all_in_one_admin@<公司域名>` + 邮箱验证码（MailHog 收码） |

> **不接 SSO 的产品**（无需在 Keycloak 配 Client）：**DeepChat**（桌面客户端，直连 API Base + Key）、**MCP Gateway**（`X-Admin-Token` 头认证，值见 `.env` 的 `MCP_ADMIN_TOKEN`）、**Update Server**（nginx 静态托管，无登录）、**MailHog**（邮件测试工具，无登录）、**Ollama**（本机推理，无登录）。

## 6. 常见问题与排错

| 症状 | 根因与解决 |
|---|---|
| `Invalid username or password` | 密码错误 / 用户不在 Users DN 范围 |
| `Account is disabled` | AD 用户被禁用 |
| `invalid_grant - Incorrect redirect_uri` | ① redirect URI 未加入 Client；② NewAPI「服务器地址」未设为内网地址（授权阶段取浏览器地址、换 token 取服务器地址，两者必须一致）；③ 用了 127.0.0.1 而服务器地址是内网 IP |
| `Client not found` | Client ID 大小写/Realm 不对 |
| 登录返回 429 | NewAPI CriticalRateLimit（默认 20 次/20 分钟）。临时清：`docker exec new-api-redis redis-cli --scan --pattern "rateLimit:*" \| xargs -r docker exec new-api-redis redis-cli DEL`；永久：`.env` 设 `CRITICAL_RATE_LIMIT_ENABLE=false` 等 4 个变量后重建容器 |
| SSO 登录后访问管理页 403 | OIDC 用户是 common 角色（role=1），需提权 root：`UPDATE users SET role=100 WHERE id=<user_id>;`（user_id 从 `user_oauth_bindings` 查） |
| 登录报 `unknown_error` | Keycloak 经 LDAP 联合到 AD，AD 域控 VM 未开机/不可达 |
| 无反应 | F12 看 Console/Network；换隐私窗口；清缓存 |

## 7. 安全要点
- 管理员密码 ≥8 位；统一账号邮箱与 AD 全局管理员一致。
- `KEYCLOAK_ADMIN_PASSWORD` 可在后台修改，改后同步 .env（仅备忘）。
- Client Secret 属敏感信息，只存在于 .env / credentials.html，不外传。
- 生产环境建议启用 HTTPS 与更严格的 token 生命周期（Realm Settings → Tokens）。
