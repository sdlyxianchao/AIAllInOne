# Gitea + Runner 教材（M08 · 源码与 CI/CD）

> 平台内 Gitea 端口 `3002`（Web）/ `2222`（Git SSH），容器 `gitea`、`gitea-runner`。Runner 用 `gitea/act_runner`（兼容 GitHub Actions 语法）。

## 1. Gitea 是什么

Gitea 是轻量自托管 Git 服务，提供仓库、Issue、PR、Wiki、**内置 CI/CD（Actions）**。本平台用途：

| 用途 | 说明 |
|---|---|
| 源码管理 | DSH Desktop 源码镜像（审计/二次开发用，可选） |
| **dsh-sync** | 每天自动检查 GitHub 新版本 → 下载安装包 → 更新 Ghost 下载页（核心用途） |
| 构建发布 | 工作流构建 DSH Desktop 安装包并上传 Update Server（可选） |
| 公告联动 | Actions 调 Ghost Admin API 发版本公告 |

## 2. 初始化与 Runner

### 2.1 初始化
1. 打开 `http://<服务器IP>:3002` → 安装向导（数据库选 SQLite，已预配）→ 创建管理员（统一账号 `ai_all_in_one_admin`）。
2. ⚠️ **ROOT_URL 必须设为内网地址**（compose 里 `GITEA__server__ROOT_URL=http://<服务器IP>:3002/`），否则生成的仓库链接/API 的 html_url 是 localhost，内网员工打不开。

### 2.2 启用 Actions 并注册 Runner
1. 右上角头像 → **Site Administration → Actions** → 确认 Enabled Actions。
2. **Runners → Create new Runner** → 复制 Registration Token。
3. 填入 `.env` 的 `GITEA_RUNNER_TOKEN` → **重新创建容器**（⚠️ 必须 `up -d`，不能用 `restart`——restart 不会重读 .env）：
   ```
   docker compose -f docker-compose.yml up -d gitea-runner
   docker logs gitea-runner 2>&1 | findstr "Runner registered"
   ```
4. ✅ Gitea → Runners 页面显示 **Idle**（绿色）。

### 2.3 Runner 配置的关键坑（gitea-runner-config.yaml）
| 坑 | 说明 |
|---|---|
| `container.network: ai-platform` | 必须经 config.yaml（+ `CONFIG_FILE` 环境变量）配置，否则 job 容器解析不了 `gitea` 主机名 |
| docker.sock | 由 act_runner 自动挂载，**不要在 options 里重复挂**（报 Duplicate mount point） |
| `force_pull: false` | 内网 Docker daemon 常访问不了 Docker Hub；设 false 并在宿主机先 `docker pull node:20` 预置 job 镜像（或配镜像加速器） |
| GitHub 网络 | 下载 docker CLI 偶发 HTTP/2 瞬断，工作流加 `--http1.1 --retry 5` |

## 3. dsh-sync 自动同步工作流（核心）

- 仓库：`dsh-sync`（**普通仓库**，mirror 只读不行），含 `.gitea/workflows/sync.yml` + `update_ghost.py` + `version_cmp.py` + `sync-config.json`。
- 触发：`schedule`（每天 UTC 2 点）+ `workflow_dispatch`（手动）。
- 逻辑：查 GitHub API 最新 tag → 对比 `version.txt` → **仅当最新版 > 本地版**才下载安装包 + 更新 Ghost 下载页 + 写版本。
- 手动触发：
  ```
  curl -X POST "http://<服务器IP>:3002/api/v1/repos/ai_all_in_one_admin/dsh-sync/actions/workflows/sync.yml/dispatches" \
    -u "ai_all_in_one_admin:<密码>" -H "Content-Type: application/json" -d '{"ref":"main"}'
  ```
  或 Gitea Web UI：dsh-sync → Actions → 运行工作流。

### sync-config.json 三个开关
| 字段 | 作用 | 默认 |
|---|---|---|
| `version_source` | `github`（最准）/ `official`（官网 download-cache.json，国内可达但滞后） | github |
| `download_prefix` | 下载加速前缀（如 `https://ghproxy.com/`），留空直连 | "" |
| `keep_releases` | 下载页版本历史最多保留几个 | 5 |
| `market_url` | 下载页「技能管家」市场地址 | `http://<服务器IP>:3100` |

> 只有「最新版 > 本地已部署版」才下载——官网缓存滞后，若按"版本不同就下载"会把客户端**回退到旧版**。

## 4. Gitea Actions 语法速查

```yaml
# .gitea/workflows/demo.yml
name: Demo
on: [push]                        # 触发事件：push/pull_request/schedule/workflow_dispatch/release
jobs:
  build:
    runs-on: ubuntu-latest
    container: node:20            # 在隔离容器里跑（需 runner 能拉镜像）
    steps:
      - uses: actions/checkout@v4
      - run: npm ci
      - run: echo "构建完成"
```
与 GitHub Actions 兼容；用 `gitea.*` 上下文（如 `${{ gitea.repository }}`）。

## 5. Keycloak SSO 自动注册（v0.91）
- Gitea 登录页有「Sign in with keycloak」；`app.ini` 的 `[oauth2_client]` 段（compose 已配环境变量）：`ENABLE_AUTO_REGISTRATION=true`、`ACCOUNT_LINKING=auto`、`USERNAME=preferred_username`。
- ⚠️ 本地管理员邮箱必须与 Keycloak/AD 一致（`@<公司域名>`），否则按邮箱匹配不到会「串号」或生成重复账号。

## 6. 常见问题

| 问题 | 解决 |
|---|---|
| 报 `readonly database` / 页面打不开 | `gitea-data` 卷里的 `gitea.db` 被 root 创建；停 Gitea 删掉 root 属主的空 db 再重建 |
| 仓库链接是 localhost | ROOT_URL 未改内网地址 |
| Runner 不显示 / 状态异常 | 检查 token 是否用 `up -d` 重新创建容器；看 `docker logs gitea-runner` |
| job 跑不起来就失败 | force_pull 问题（见 2.3），宿主机预置 node:20 镜像 |
| 同步工作流下载旧版 | version_cmp 只升不降的机制被绕过？检查 sync-config.json version_source |
| SSO 登录串号 | 邮箱不一致，统一为 `ai_all_in_one_admin@<公司域名>` |
