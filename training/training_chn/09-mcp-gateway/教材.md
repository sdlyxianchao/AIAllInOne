# MCP Gateway 教材（M10 · 工具与技能网关）

> 平台内 MCP Gateway 端口 `3100`（容器 `mcp-gateway`），源码 `../../windows/mcp-gateway/`（gateway.js + mcp-servers.json + skills/）。基于官方 `@modelcontextprotocol/sdk`，暴露标准 **Streamable HTTP `/mcp`** 端点。

## 1. MCP 是什么

MCP（Model Context Protocol）是 Anthropic 提出的开放协议，为 LLM 与外部数据源/工具提供统一接口（"AI 的 USB-C"）。核心架构：

- **Host**：AI 应用（DSH Desktop、Dify）。
- **Client**：Host 内与服务器一对一连接。
- **Server**：提供工具（tools）、资源（resources）、提示（prompts）。

本平台的 MCP Gateway 就是**一个统一 MCP Server**：聚合内置工具 + 外部 MCP Server，供 DSH Desktop/Dify 单点接入。

## 2. 内置平台工具

| 工具 | 用途 |
|---|---|
| `platform_time` | 返回服务器当前时间 |
| `platform_echo` | 回显文本（连通性测试） |
| `platform_services` | 列出平台服务清单 |
| `search_knowledge` | 检索 Dify 统一知识库（RAG，见第 5 节） |

## 3. 验证与使用

```
# 健康检查
curl http://<服务器IP>:3100/health   # → {"status":"ok"}

# 工具列表（MCP 协议）
curl -X POST http://<服务器IP>:3100/mcp -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
```

客户端接入：
- **DSH Desktop**：手动配置 → 可流式传输 HTTP → `http://<服务器IP>:3100/mcp`（见 M09）。
- **Dify**：工作流 → 自定义工具 / MCP 工具配置 → 同一地址。

## 4. 聚合外部 MCP Server 与自定义工具

### 4.1 mcp-servers.json（外部 Server 聚合）
```json
{
  "servers": [
    { "name": "filesystem", "type": "stdio", "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/data"] },
    { "name": "github", "type": "http", "url": "https://api.githubcopilot.com/mcp" }
  ]
}
```
- 类型支持 `stdio` / `http`；聚合工具自动加 `{serverName}_` 前缀防重名。
- 修改后重启：`docker compose restart mcp-gateway`。

### 4.2 自定义内置工具（gateway.js）
1. `builtinTools` 数组加工具定义（name/description/inputSchema）。
2. `callBuiltin` 函数加执行分支。
3. `docker compose restart mcp-gateway`，DSH Desktop 重连即可见新工具。

## 5. RAG 统一知识库检索（search_knowledge，重点）

### 链路
```
DSH Desktop ──MCP──> MCP Gateway(:3100/mcp) ──HTTP──> Dify Knowledge API
                                                      POST /v1/datasets/{id}/hit-testing
```

### 第 1 步：Dify 侧准备（M06 已完成）
embedding 模型设为默认 → 创建知识库（High quality）→ 建 Knowledge API Key（记下 key 与 dataset_id）。

### 第 2 步：.env 配置（Key 进 .env，不硬编码）
```
DIFY_API_BASE=http://<服务器IP>/v1
DIFY_KNOWLEDGE_API_KEY=dataset-xxxxx
DIFY_DEFAULT_DATASET_ID=<知识库 UUID>
```

### 第 3 步：重启并验证
```
docker compose up -d mcp-gateway
# DSH Desktop 对话里调 search_knowledge，传 query（可选 dataset_id、top_k）→ 返回片段（content + score）
# 或 AI 管理中心 →「Dify」页 →「🔍 RAG 知识库检索」卡片
```

### ⚠️ 三个关键坑
| 坑 | 说明 |
|---|---|
| 网络打通 | MCP Gateway 在 `ai-platform` 网络，Dify 在自己的 `dify_default` 网络，默认不通；用宿主机内网 IP `http://<服务器IP>/v1` 访问 |
| Knowledge Key 账号级 | 一个 key 可访问该账号所有知识库；按用户分库需在工具层做 user→dataset_id 映射 |
| 请求细节 | 必须用完整路径 `/v1/datasets/{id}/hit-testing`（只写 /v1 会 308）；中文 query 用 curl -d 直传会 400，用 `--data-binary @文件` 或脚本发 UTF-8 |

### 备选：DSH Desktop 内置 difyKnowledge（不经网关）
DSH Desktop 设置 → MCP 设置 → 内置 `difyKnowledge` → 编辑 → 添加 Dify 配置（endpoint 带 /v1、apiKey、datasetId）。⚠️ 密钥存客户端本地、账号级、散落难管控，**企业统一发布建议走网关**。

## 6. Skill 市场（内网技能包分发）

| 端点 | 作用 |
|---|---|
| `/market` | 技能市场页面（卡片浏览 + 下载 ZIP + 复制安装地址） |
| `/skills` | 技能清单 JSON |
| `/skills/<名称>.zip` | 技能包下载（adm-zip 动态打包） |

- 技能放 `mcp-gateway/skills/`（含 SKILL.md 的子目录），**每次请求自动扫描，无需重启**。
- 内置示例：`platform-report`（生成平台状态报告）、`skill-market`（技能管家）。
- DSH Desktop 装技能：`从 URL 安装` → `http://<服务器IP>:3100/skills/<名称>.zip`。
- 上传/删除技能：AI 管理中心 MCP 页（走管理 API）或直接放文件。

## 7. 管理 API（供 AI 管理中心调用）

| 端点 | 作用 |
|---|---|
| `GET/POST /api/servers`、`PUT/DELETE /api/servers/:name` | MCP Server 增删改查（写回 mcp-servers.json + 自动重连） |
| `POST /api/skills/upload` | 上传技能 zip（校验含 SKILL.md、防路径穿越） |
| `DELETE /api/skills/:name` | 删除技能 |

需 `X-Admin-Token` 头（`.env` 的 `MCP_ADMIN_TOKEN`）；未配返回 503、错 token 401。管理员在 AI 管理中心「MCP Gateway」页操作（Keycloak `ai-platform-admin` 角色保护）。

## 8. 常见问题

| 问题 | 解决 |
|---|---|
| /health 无响应 | 容器是否运行；端口 3100 是否映射 |
| tools/list 空 | 检查 gateway.js 启动日志；npm install 是否执行过 |
| search_knowledge 无结果 | DIFY_* 三项 .env 是否正确；网络（内网 IP 访问 Dify）；dataset_id 是否正确 |
| DSH Desktop 工具列表看不到新工具 | 重连 MCP 服务器（断开重连） |
| 上传技能失败 | zip 需含 SKILL.md；防路径穿越校验 |
| 技能管家读不到市场 | market_url 用主机名（IP 会被 DSH Desktop 脱敏） |
