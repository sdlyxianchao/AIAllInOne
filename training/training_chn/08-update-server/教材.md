# Update Server 教材（M12 · 安装包分发）

> 平台内 Update Server 端口 `8091`（容器 `update-server`，nginx:alpine），目录挂载 `dsh-updates/`。

## 1. 分发链路

```
GitHub Releases ──> dsh-sync(Gitea Actions) ──> Update Server(:8091/dsh/)
      └── 写 version.txt / 更新 Ghost 下载页(/dsh/) ──> 员工浏览器下载 / DSH Desktop 自动更新
```

## 2. 手工上传与验证

```
mkdir -p dsh-updates/dsh
curl -L -o dsh-updates/dsh/dsh-desktop-windows-x64-setup.exe \
  https://github.com/dataelement/dsh-desktop/releases/download/v0.5.0/dsh-desktop-windows-x64-setup.exe

# 验证下载链接
curl -I http://<服务器IP>:8091/dsh/dsh-desktop-windows-x64-setup.exe   # 200/206
```

- 支持 Windows (.exe) / macOS (.dmg) / Linux 多平台包。
- 若用 electron-builder 构建自定义版，产物（.exe + latest.yml）同样放此目录。

## 3. 自动更新机制

- DSH Desktop 的 `package.json` 中 `build.publish.url = http://<服务器IP>:8091/dsh/`（generic provider）。
- 客户端启动时读取 `latest.yml`（含最新版本号与安装包地址）→ 对比本地版本 → 自动下载安装。
- `version.txt` 由 dsh-sync 维护，供同步工作流判断「是否已同步最新版」。

## 4. 常见问题

| 问题 | 解决 |
|---|---|
| 访问 :8091 返回 403 | 正常（空目录无 index.html），服务在运行 |
| 员工下载 404 | 文件名/路径不对；安装包未上传 |
| 客户端不自动更新 | latest.yml 是否最新且格式正确；publish.url 是否可达 |
| 版本回退 | dsh-sync 只升不降；检查 version_source 与 keep_releases |
| 国内下载慢 | sync-config.json 配 download_prefix（如 ghproxy） |
