# Dify 教材（M06 · AI 应用平台）

> 平台内 Dify **独立部署**（官方 docker-compose，约 15 容器），端口 80（`http://<服务器IP>`），不走主 compose。Dify 通过 `host.docker.internal:3000` 访问 NewAPI。

## 1. Dify 是什么

Dify 是开源 **LLM 应用开发平台**（低代码）：可视化构建聊天助手、文本生成、Agent、工作流、知识库应用；内置 RAG 管道、提示词编排、模型管理。平台内五类应用：

| 应用类型 | 适用 | 平台内典型场景 |
|---|---|---|
| 聊天助手 Chatbot | 交互式对话 | 智能客服、内部问答 |
| 文本生成 Text Generator | 一次性生成 | 总结、写作、报告 |
| Agent | 工具调用/自主规划 | 查数据库、调 API 的智能体 |
| 工作流 Workflow | 固定流程编排 | 文档处理流水线、数据查询 |
| Chatflow | 对话+流程混合 | 带知识库的客服机器人 |

## 2. 部署与排错要点（独立部署）

### 2.1 部署步骤（已在 M02 实操）
1. 克隆 Dify（GitHub tag 或 Gitee 官方镜像）。
2. 修复 compose 兼容性 + 复制所有 `.env`（主 + envs/ 子模板）。
3. **必需修复**：`shared.env` 中 `GRAPH_ENGINE_SCALE_UP_THRESHOLD=0` → `=50`（1.16.1 把字段升级为 PositiveInt，不改 4 个容器一直 Restarting）。
4. `docker compose up -d` → 15 容器 Up（`init_permissions` Exited 正常）。

### 2.2 三个必知坑
| 坑 | 现象 | 修复 |
|---|---|---|
| WebSocket 地址 | 创建应用/工作流调试卡住，反复连 `ws://localhost` | `.env` 设 `NEXT_PUBLIC_SOCKET_URL=ws://<服务器IP>`，compose 里 web 服务同步改，`docker compose up -d web` + 强刷（Ctrl+F5） |
| 登录密码 base64 | 脚本/接口登录失败；前端"点了没反应" | `POST /console/api/login` 的 password 字段是 **base64 编码**（非加密，混淆用） |
| 忘记管理员密码 | 无法登录 | `docker exec docker-api-1 flask reset-password --email ai_all_in_one_admin@<公司域名> --new-password '<新密码>' --password-confirm '<新密码>'`（≥8 位；PBKDF2 迭代 10000，无法反解） |

> `GET /console/api/account/profile 401` 是未登录时的正常现象，不代表后端坏。

## 3. 模型供应商配置

1. **设置 → 模型供应商** → 找到 **OpenAI-API-compatible** → 添加模型：
   - 模型名称：`deepseek-chat`（与你 NewAPI 渠道的模型名一致）
   - API Key：`dify-key` 的 sk-xxx（NewAPI 里创建）
   - API endpoint：`http://host.docker.internal:3000/v1`
2. 需要 RAG 时再加 **embedding 模型**（如本地 Ollama bge-m3 或 OpenAI-API-compatible 的 embedding），并设为**默认 text-embedding 模型**（否则报 "Default model not found"）。
3. 测试模型 → 收到回复即链路通（Dify → NewAPI → LiteLLM → DeepSeek）。

## 4. 知识库（统一 RAG）

### 4.1 创建知识库
1. **知识库 → 创建知识库** → 上传文档（md/txt/pdf/docx 等）。
2. **索引方式选「高质量 High quality」**（需要 embedding 模型）。
3. 分段与检索：默认分段；可按需配混合检索、top_k、score_threshold。

### 4.2 知识库 API Key（供 MCP Gateway 检索）
1. 知识库 → **API 访问** → 创建 **Knowledge API Key**。
2. 记下：
   - `key`：`dataset-...` 前缀的 Bearer token
   - `dataset_id`：知识库 URL 中 `/datasets/<uuid>/documents` 的 uuid
3. 在 `.env` 填写 `DIFY_API_BASE=http://<服务器IP>/v1`、`DIFY_KNOWLEDGE_API_KEY=dataset-xxxxx`、`DIFY_DEFAULT_DATASET_ID=<uuid>`，重启 `mcp-gateway` → DSH Desktop 就能用 `search_knowledge` 检索（详见 M10 教材 8.9）。

### 4.3 RAG 应用搭建（综合练习主线）
1. 新建 **Chatflow**（或聊天助手）→ 添加 **知识检索节点** → 选知识库。
2. LLM 节点引用检索结果 → 调试（测试对话框发送问题）→ 发布。

## 5. Agent 与工作流

- **Agent**：选模型后配置工具（内置工具 + 自定义工具 + MCP 工具），系统自动规划调用。
- **Workflow**：拖拽节点连线（开始 → 知识检索 → LLM → 条件分支 → 直接回复/HTTP 请求），适合固定流程。
- **MCP 工具接入**（M10 详述）：自定义工具/MCP 工具指向 `http://<服务器IP>:3100/mcp`，即可在工作流里调用平台 MCP 工具（含 search_knowledge）。

## 6. 发布与应用管理
- 应用内点**发布**后，可：
  - 生成 WebApp 链接（员工直接访问）；
  - 嵌入网站（iframe/script，Ghost 门户可嵌入）；
  - 调 API（Service API，凭 API Key 调用 `POST /v1/chat-messages` 等）。
- **成员权限**：设置 → 成员 → 邀请/角色（admin/editor/viewer）。
- **使用统计**：控制台/应用内查看调用量、token 消耗（与 NewAPI 日志互相印证）。

## 7. 常见问题

| 问题 | 解决 |
|---|---|
| 创建应用时一直转圈/无响应 | WebSocket 地址问题（见 2.2），改 .env 后强刷 |
| 知识库搜不到内容 | 检查 embedding 模型是否设为默认；索引是否完成（High quality 需处理中→完成） |
| 报 Default model not found for text-embedding | 未设默认 embedding 模型 |
| 模型报错/无回复 | 看 NewAPI 渠道测试；Dify 模型供应商 API endpoint 是否 `host.docker.internal:3000/v1` |
| 登录没反应 | base64 密码/缓存问题；清缓存重试；查 profile 401 属正常 |
| 忘记密码 | 容器内 reset-password 命令（≥8 位） |
| 多个容器 Restarting | 查 `docker logs docker-api-1` 的 ValidationError → GRAPH_ENGINE 修复 |

## 8. 安全要点
- Knowledge API Key 是**账号级**（可访问该账号所有知识库）；企业统一发布建议走 MCP Gateway（密钥只留服务器）。
- 知识库内容遵循数据分级：机密资料不放入可被外部模型检索的知识库。
- 管理员账号与平台统一（邮箱一致），成员权限最小化。
