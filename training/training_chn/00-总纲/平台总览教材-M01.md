# 平台总览与架构 教材（M01）

> 对应部署指南第 1 章。目标：让学员在动手前建立完整的平台地图——组件、端口、数据流、安全模型。

## 1. 一句话定位

**一台服务器 + Docker 编排，8+ 开源组件预集成：统一 SSO、LLM 路由、AI 应用、企业门户、Git/CI、统一管理、监控告警、可观测、日志、备份——员工登录一次，用上全部 AI 工具，数据不出内网。**

## 2. 分层架构（6 层）

| 层 | 组件 | 说明 |
|---|---|---|
| 用户层 | DeepChat 桌面客户端 / 浏览器 | 员工入口 |
| 门户与应用层 | Ghost 企业门户 / Dify AI 应用平台 | 内容与 AI 应用 |
| LLM 路由层 | NewAPI → LiteLLM(+Presidio) → 外部大模型 | 路由/计费/脱敏 |
| 可观测层 | Langfuse | 每次调用的 trace/token/成本 |
| 基础设施层 | Keycloak / MCP Gateway / Gitea+Runner / Update Server / 监控日志 | 认证/工具/源码/分发/运维 |
| 统一管理层 | AI 管理中心（:10086） | Dashboard + 产品入口 + 审计/成本/备份/日志 |

## 4. 核心数据流（必会讲）

### 4.1 LLM 请求流（核心链路）
```
DeepChat / Dify → ① NewAPI(:3000) → ② LiteLLM(PII 脱敏) → ③ 外部大模型
                 ← ⑤ 返回还原 ← ④ 响应
旁路：LiteLLM success_callback → Langfuse 追踪（提示词/响应/延迟/token/成本）
```

### 4.2 用户访问流
- 浏览器 → Ghost(:8090) → 门户 → Dify / 下载中心
- 浏览器 → AI 管理中心(:10086) → 管理所有 Docker 容器
- 浏览器 → Grafana(:3030) / Langfuse(:3010) → 监控/可观测

### 4.3 其他链路
- 自动更新：GitHub → Gitea Actions → Update Server(:8091) → DeepChat 自动下载安装
- RAG：DeepChat → MCP Gateway(:3100/mcp) → Dify Knowledge API → 知识库
- 认证：Keycloak OIDC SSO → 接入 SSO 的 Web 产品（AI 管理中心/NewAPI/Dify/Gitea/Grafana/Langfuse/LiteLLM；Ghost 走本地账号+邮箱验证码，其余工具按 API Key/Token）
- 日志：Promtail 采集 → Loki 聚合 → AI 管理中心查询

## 5. 16 个开源组件清单

Keycloak / NewAPI / LiteLLM+Presidio / Dify / Ghost / Gitea+Runner / DeepChat / Update Server(nginx) / MCP Gateway / AI Admin Center(自研) / Prometheus+Grafana+Alertmanager+cadvisor / Langfuse / Loki+Promtail / MailHog / MySQL+Redis+PostgreSQL(底座) / Ollama(可选)

## 6. 安全模型（3 个要点）

1. **数据不出内网**：模型调用出网前经 LiteLLM 脱敏（PII/敏感词）；数据分级：公开/内部/机密。
2. **统一认证**：Keycloak SSO；管理员角色 `ai-platform-admin` + 分模块 `admin:<产品>`。
3. **密钥管理**：真实值只在运行时 `.env`；仓库只提交 `.env.example`；默认 HTTP 内网，生产建议 HTTPS。

## 7. 部署形态（了解）

- **Windows（当前主力）**：Windows 11 + Docker Desktop（WSL2），`windows/` 目录，41 容器。
- **Linux / 在线服务器（规划中）**：`linux/`、`docker/` 目录。
