# LiteLLM + Presidio 培训大纲（M05 · 安全网关）

## 1. 课程定位
LiteLLM 是平台的 **LLM 代理网关**（统一 100+ 模型接口、PII 脱敏、Redis 语义缓存、成本统计、Langfuse 上报）；Presidio 是 Microsoft 的 **PII 识别/脱敏引擎**。二者共同保证「发给外部大模型的数据在出内网前已被脱敏」。

## 2. 教学目标
学完本模块，学员应能：
1. 解释 LLM 请求链路中 LiteLLM 的位置（NewAPI → LiteLLM → 外部模型 → 还原返回）。
2. 理解 `litellm-config.yaml` 结构（model_list / litellm_settings / general_settings），会增删模型。
3. 理解 PII 脱敏双机制：内置正则内容过滤器（中文手机号/身份证/邮箱等）+ Presidio 实体识别。
4. 配置并验证 **Redis 语义缓存**（redis-semantic，bge-m3 本地向量化，相似度阈值调优）。
5. 配置 Langfuse 上报（success_callback）与成本统计。
6. 排查 LiteLLM 常见故障（密钥、模型未注册、guardrail 未全局生效、Presidio 端点 404）。

## 3. 先修要求
- 完成 M02（核心服务启动）、M04（NewAPI 渠道）。
- 了解 OpenAI 兼容 API 格式。

## 4. 课程内容与学时（共 3 学时，D4 下午）

| 节 | 内容 | 学时 | 类型 |
|---|---|---|---|
| 1 | LiteLLM 概述：端口 4000（容器内 4000）、与 NewAPI 的关系、平台内角色 | 0.5 | 讲授 |
| 2 | `litellm-config.yaml` 详解：model_list、master_key、guardrails、blocked_words | 0.5 | 讲授+实操 |
| 3 | PII 脱敏：内置正则过滤器 + Presidio（analyzer/anonymizer），验证脱敏效果 | 0.5 | 实操 |
| 4 | Redis 语义缓存：前置 3 步（redis-stack、Ollama bge-m3、REDIS_PASSWORD 变量）、阈值调优、验证命中 | 0.75 | 讲授+实操 |
| 5 | Langfuse 上报（success_callback）+ 成本统计 | 0.25 | 讲授 |
| 6 | 排错：No connected db / 模型 404 / guardrail 不生效 / Presidio /analyze/analyze 404 | 0.5 | 实操 |

## 5. 达标标准（A 级）
- 独立在 litellm-config.yaml 中新增一个模型并重启生效。
- 发一条含手机号/邮箱的请求，验证响应被脱敏（或还原后原文返回）。
- 连续两条语义相近请求，验证第二次命中语义缓存（x-litellm-semantic-similarity 头）。
- 能解释 guardrails 需 `default_on: true` 才全局生效的坑。
