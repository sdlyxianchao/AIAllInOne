# LiteLLM + Presidio 教材（M05 · 安全网关）

> 平台内 LiteLLM 容器 `litellm`，内部端口 4000，宿主机映射 4001；容器 `presidio-analyzer` / `presidio-anonymizer`；`litellm-redis`（redis-stack-server，带向量检索）。

## 1. LiteLLM 是什么

LiteLLM 是开源的 **LLM 网关**：一个 OpenAI 兼容接口调用 100+ 模型（OpenAI/Claude/DeepSeek/Ollama…），并提供鉴权（master key）、虚拟密钥、预算、guardrails（脱敏/内容安全）、缓存、可观测回调。

本平台中 LiteLLM **只被 NewAPI 调用**（渠道 Base URL = `http://litellm:4000`），员工不直接访问。链路：

```
请求: NewAPI ──> LiteLLM ──(脱敏)──> 外部大模型
响应: NewAPI <── LiteLLM <──(还原PII)── 外部大模型
旁路: LiteLLM success_callback ──> Langfuse
```

## 2. litellm-config.yaml 结构

| 段 | 作用 | 平台内要点 |
|---|---|---|
| `model_list` | 可用模型清单 | 默认仅启用 `deepseek-chat`；加 OpenAI/Claude 需取消注释 + 在 .env 配 Key |
| `litellm_settings` | 缓存/回调 | `cache: true`、`cache_params`（redis-semantic）、`success_callback: ["langfuse"]` |
| `general_settings` | 全局设置 | `master_key` 读 `.env` 的 `LITELLM_MASTER_KEY` |
| guardrails（注释状态） | 脱敏规则 | 当前版本 guardrail 配置格式变更，已注释；后启用参考官方文档 |

> ⚠️ 当前使用稳定版 `v1.95.1`（`main-latest` 有已知 bug，勿升级）。

### 2.1 添加模型步骤
1. `.env` 取消对应 Key 注释（如 `OPENAI_API_KEY`）。
2. `litellm-config.yaml` 取消对应 model 块注释。
3. `docker compose up -d litellm` 重启。
4. 在 NewAPI 渠道「获取模型」里能看到新模型。

## 3. PII 脱敏（数据不出内网的关键）

### 3.1 内置内容过滤器（默认启用，无需外部服务）
`litellm_content_filter`，正则脱敏（命中替换为 `[xxx_REDACTED]`）：

| 规则 | 示例 | 类型 |
|---|---|---|
| 中国手机号 | `\b1[3-9]\d{9}\b` | cn_mobile |
| 身份证号 | `\b\d{17}[\dXx]\b` | cn_id |
| 银行卡号 | `\b\d{16,19}\b` | bank_card |
| 邮箱 | prebuilt `email` | email |
| 统一社会信用代码 | `\b[0-9A-HJ-NPQRTUWXY]{18}\b` | cn_credit_code |
| 护照号 | `\b[EG]\d{8}\b` | cn_passport |
| IPv4 | `\b\d{1,3}(\.\d{1,3}){3}\b` | ip_address |

另有敏感词黑名单（命中即 **BLOCK** 拒绝请求）：`内部机密`、`商业机密` 等，在 `blocked_words` 增删。

> ⚠️ **关键坑**：guardrails 注册后默认不全局生效，必须加 `default_on: true`，否则只有请求体显式传 `guardrails` 字段才触发。

### 3.2 Presidio 高级实体识别（增强，可后配）
- `presidio-analyzer`（识别：人名、邮箱等细粒度实体）+ `presidio-anonymizer`（替换）。
- ⚠️ **端点格式坑**：LiteLLM 会自动拼 `/analyze`、`/anonymize`，所以环境变量必须填 **base URL**（如 `http://presidio-analyzer:3000`），不能带 `/analyze`，否则变 `/analyze/analyze` 返回 404。
- ⚠️ 镜像约 965MB，国内拉取慢（约 1 小时）；拉不动可先用内置正则（已覆盖中文核心 PII）。

### 3.3 验证脱敏
```
curl -X POST http://<服务器IP>:4001/v1/chat/completions \
  -H "Authorization: Bearer <LITELLM_MASTER_KEY>" -H "Content-Type: application/json" \
  -d '{"model":"deepseek-chat","messages":[{"role":"user","content":"我的邮箱是 test@example.com，手机号 13812345678"}]}'
```
期望：模型回复中原始值被替换为 `[REDACTED]`；发含「内部机密」→ 返回 `Content blocked`。

## 4. Redis 语义缓存（省钱利器）

启用 `type: redis-semantic`：请求先由本地 `bge-m3` 向量化，与历史请求相似度比对，**意思相近即命中**（跨用户共享），命中请求 `Key-Spend: 0.0`。

**前置 3 步**：
1. compose 中 `litellm-redis` 镜像换 `redis/redis-stack-server`（自带 RediSearch 向量检索）。
2. 宿主机装 Ollama 并 `ollama pull bge-m3`；`.env` 设 `OLLAMA_API_BASE=http://host.docker.internal:11434`。
3. litellm 容器环境变量补 `REDIS_PASSWORD=${LITELLM_REDIS_PASSWORD:-}`（RedisSemanticCache 强制要求该变量，可空）。

**配置示例**：
```yaml
litellm_settings:
  cache: true
  cache_params:
    type: redis-semantic
    host: litellm-redis
    port: 6379
    ttl: 3600
    similarity_threshold: 0.8   # 0.9+ 精确；0.7~0.8 平衡；0.6~0.7 激进省钱
    redis_semantic_cache_embedding_model: bge-m3
    redis_semantic_cache_index_name: litellm_semantic_cache_index
```

**验证命中**：连续两次语义相近但措辞不同的请求，第二次响应带 `X-Litellm-Cache-Key` + `X-Litellm-Semantic-Similarity`（实测 0.92），耗时从十几秒降到 <0.5 秒。
**适用建议**：确定性任务（知识库问答/temperature=0）收益最大；实时内容用请求头 `no-cache` 绕过。
**关闭缓存**：`cache: false` 或注释整块，重启 litellm。

## 5. Langfuse 可观测上报

`.env` 配 `LANGFUSE_PUBLIC_KEY` / `LANGFUSE_SECRET_KEY` / `LANGFUSE_HOST`，LiteLLM `success_callback: ["langfuse"]` 自动上报每次调用的提示词/响应/延迟/token/成本。验证：Langfuse 项目里能看到 trace（见 M14）。

## 6. 常见问题

| 症状 | 根因与解决 |
|---|---|
| NewAPI 渠道测试报 `No connected db` | 渠道密钥不是 LITELLM_MASTER_KEY 实际值 |
| 请求模型 404 | model_list 未启用该模型 / 未重启 litellm / 未配上游 Key |
| guardrail 不触发 | 缺 `default_on: true` |
| Presidio 404 `/analyze/analyze` | 环境变量带了 /analyze 路径，应只填 base URL |
| 语义缓存启动报 Missing REDIS_PASSWORD | 未补 `REDIS_PASSWORD` 环境变量 |
| 宿主机访问 4001 不通 | WSL2 端口转发问题：**必须用内网 IP** `<服务器IP>:4001`，不要用 127.0.0.1 |

## 7. 安全要点
- 所有出网请求都过 LiteLLM 脱敏层；敏感词黑名单按公司实际维护。
- master key 等同管理员权限，只存 .env，不分发。
- 理解数据分级：公开信息可直接用外部模型；内部信息需脱敏；机密信息禁止上传外部模型。
