# AI Agent 运维 教材（M17 · 智能运维）

> 平台内文档：`../../AI-AGENT-OPS.md`（含完整提示词与命令参考，9 语言）。本教材为其培训化提炼。

## 1. 工作原理

平台的一切以**代码、配置、数据**形式存在于本机：
- Docker Compose 定义全部容器；
- `.env` 文件存凭据；
- Admin API 暴露管理端点（Keycloak/Gitea/NewAPI 等）；
- 文件与数据库（Ghost SQLite、DSH Desktop 安装包、sync-history JSON）即实际状态。

因此 AI Agent 可以：读写任何文件、执行命令（docker/git/PowerShell/Node/Python）、HTTP 调 API、联网查文档——**整个平台都能通过 Agent 运维**。

## 2. 使用准备（一次性）
1. 把 Agent 工作目录指向项目根（如 `C:\AIAllInOne`）。
2. 确保 Docker Desktop 运行。
3. 凭据留在 `.env`，不要贴到对话/仓库。
4. 告诉 Agent 用哪个平台目录（单机默认 `windows/`）。

## 4. Best Practices（必记）

- **前端 vs 后端重载**：AI 管理中心 `index.html` 改完刷新浏览器即可（卷挂载）；`server.js` 需 `docker restart admin-portal`（`up -d` 不重载卷挂载代码）。
- **硬刷新** Ctrl+F5（旧 JS 常被缓存）。
- **密钥不落地**：用占位符（`<服务器IP>`、CHANGE_ME_*）；publish.ps1 会自动脱敏 server.js 密码。
- **验证不轻信**：要求 Agent 用命令证明结果（HTTP 状态码、ls、日志行），尤其"已修复"的结论。
- **破坏性操作先备份**：改 Ghost DB/配置前先备份；删除前确认。
- **内容导入先问参数**：发布地址与语言。
- **网络/代理**：git push、联网检索可能需要代理；失败时开代理重试。

## 6. 平台自带一键健康检查（health-check.ps1）

- `C:\AIAllInOne\windows\scripts\health-check.ps1` → 输出 `health_check_<时间戳>.log`，末尾 `ALL CLEAR` + `Fail: 0` 即全绿。
- 覆盖 41 容器、9 阶段（Docker 守护 → 容器状态 → HTTP 端点 → LiteLLM/模型注册 → LLM 全链路真实请求 → AD 认证链路 → MCP/Skill → 登录前置 → 磁盘空间）。
- 可注册开机自检计划任务（登录后延迟 2 分钟运行）。
- ⚠️ 凭据从同目录 .env 读取，脚本不硬编码密码；`dify-init_permissions-1` Exited(0) 正常；Update Server 403 正常。

## 7. 常见问题

| 问题 | 解决 |
|---|---|
| Agent 说修好了但不信 | 要求用命令证明（curl 状态码、日志行） |
| 改 UI 不生效 | Ctrl+F5 硬刷新；确认是前端而非后端改动 |
| 发布失败 | 检查代理/GitHub 凭据；`git push` 需网络 |
| 备份失败 | 检查 backups/ 目录权限；配置文件用 -LiteralPath 复制 |
| 清理误删风险 | 只删确认过的项；先备份 |
