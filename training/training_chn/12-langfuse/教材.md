# Langfuse 教材（M14 · LLM 可观测）

> 端口 `3010`（容器 langfuse + langfuse-worker），依赖 langfuse-postgres / langfuse-clickhouse / langfuse-minio / langfuse-redis。v4 自托管。

## 1. 数据流

```
LiteLLM success_callback: ["langfuse"] ──> Langfuse
（每次调用的提示词/响应/模型/延迟/token/成本 自动上报）
```

## 2. 登录与使用

- AI 管理中心 →「🔍 LLM 可观测」→ 打开按钮指向 `http://<服务器IP>:3010/auth/sso-initiate?provider=KEYCLOAK`（IdP 发起式 SSO，自动登录）。
- 账号：`ai_all_in_one_admin@<公司域名>` / 统一密码。
- 首次启动已 headless 初始化组织 `AI All In One` 和项目 `AI Platform`。
- 核心页面：
  - **Traces**：每次请求/会话的完整调用链（含工具调用子 span）。
  - 单条 trace 详情：prompt、response、model、latency、tokens、cost。
  - **Metrics / Cost**：按模型/日期/用户的用量与成本分析。
  - **Prompt Management / Datasets**（进阶）：版本化提示词与评测集。

## 3. 两个关键坑

| 坑 | 现象 | 修复 |
|---|---|---|
| `LANGFUSE_MIGRATION_V4_WRITE_MODE` | 旧客户端（LiteLLM SDK）上报 trace-create 失败，看不到任何 trace | 设 `events_only` → **`dual`**（web 和 worker 都要设），重启 |
| SSO 组织绑定 | SSO 登录后自动新建独立账号且不属于任何组织，看不到数据 | 统一邮箱后不再发生；已发生则把用户加入组织：`INSERT INTO organization_memberships ... SELECT ... WHERE email='ai_all_in_one_admin@<公司域名>'` |

## 4. 常见问题

| 问题 | 解决 |
|---|---|
| 看不到任何 trace | 查 V4_WRITE_MODE 是否为 dual；LiteLLM .env 三个 LANGFUSE_* 变量；`docker logs litellm` 有无上报报错 |
| SSO 登录无数据 | 邮箱与初始化账号不一致 → 统一邮箱 / 手动加入组织 |
| `/auth/sso-initiate` 返回 HTTP 200 壳 | 正常，重定向在浏览器端完成，curl 看不到 302 |
| 数据量大占磁盘 | clickhouse/minio 数据卷规划容量；定期清理/归档 |
