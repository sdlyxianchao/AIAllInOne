# Docker + Docker Compose + Ollama 教材（M02 · 基础设施）

> 平台内所有容器在 Docker Desktop（WSL2 后端）中运行，通过 `ai-platform` 网络互访，使用容器名作为主机名（如 `http://litellm:4000`）。

## 1. Docker 核心概念与常用命令

| 概念 | 说明 |
|---|---|
| 镜像 Image | 只读模板（如 `quay.io/keycloak/keycloak:25.0`） |
| 容器 Container | 镜像的运行实例 |
| 卷 Volume | 持久化数据（如 `keycloak-data`、`ghost-data`） |
| 网络 Network | 容器通信（`ai-platform`） |

常用命令：
```bash
docker ps -a                          # 所有容器状态
docker logs <容器名> --tail 100       # 查日志
docker exec -it <容器名> <命令>       # 进容器执行
docker restart <容器名>               # 重启
docker inspect <容器名>               # 详情（健康状态/挂载）
docker volume ls / docker network ls  # 卷/网络
docker system df                      # 磁盘占用
docker compose -f docker-compose.yml up -d <服务>   # 启动/重建服务（重读 .env）
```

## 2. Windows 部署前置（平台专用）

### 2.1 Docker Desktop 资源分配（%UserProfile%\.wslconfig）
```
[wsl2]
memory=24GB        # 最低 16GB，推荐 24~32GB（宿主机内存一半左右）
processors=8
swap=4GB
```
保存后 `wsl --shutdown` 重启 Docker Desktop。✅ 状态栏 "Engine running"。

### 2.2 目录与配置
| 文件 | 说明 |
|---|---|
| `docker-compose.yml` | 核心服务编排（25 容器） |
| `.env.windows` → 复制为 `.env` | 所有密码与外部 API Key（🔴 首次启动前必填：DEEPSEEK_API_KEY、LITELLM_MASTER_KEY、NEWAPI_DB_PASSWORD、KEYCLOAK_ADMIN_PASSWORD、NEWAPI_SESSION_SECRET、NEWAPI_CRYPTO_SECRET、ADMIN_PASSWORD、SESSION_SECRET） |
| `litellm-config.yaml` | LiteLLM 模型 + 脱敏规则 |

### 2.3 网络与 IP
- `docker network create ai-platform`（创建共享网络）。
- **固定内网 IP**：路由器 DHCP 保留（MAC 绑定），否则重启后员工访问地址全失效。

### 2.4 启动与验证
```bash
docker compose -f docker-compose.yml up -d     # 首次拉镜像 5-10 分钟
docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"
```
预期 10 个核心容器 Up。✅ 验证：Keycloak 302 / NewAPI 200 / Gitea 200 / Admin Center 200。

## 3. Docker Compose 语法速查（会读会改）

```yaml
services:
  new-api:
    image: calciumion/new-api:latest
    container_name: new-api
    restart: always
    ports:
      - "3000:3000"            # 宿主机端口:容器端口
    environment:               # 环境变量（可引用 .env 的 ${VAR}）
      - SQL_DSN=root:${NEWAPI_DB_PASSWORD}@tcp(new-api-db:3306)/new-api
    volumes:
      - new-api-data:/data      # 命名卷持久化
    networks:
      - ai-platform
    depends_on:
      - new-api-db
```

**平台内 8 个"必须知道"的端口冲突**：Prometheus 9091（9090 被 Keycloak 占）、Grafana 3030（3000 被 NewAPI 占）、LiteLLM 宿主机 4001（容器内 4000）、cadvisor 8080 内部、Loki 3110 内部、MailHog 8025、MCP Gateway 3100、Admin Center 10086。

## 4. Dify 独立部署要点（D2 下午）

- Dify 用官方 compose 独立部署（约 15 容器，网络 `docker_default`），不与主 compose 混用。
- 必需修复：`shared.env` 的 `GRAPH_ENGINE_SCALE_UP_THRESHOLD=0 → 50`（1.16.1 升级 PositiveInt，否则 4 个容器 Restarting）。
- WebSocket：`.env` 设 `NEXT_PUBLIC_SOCKET_URL=ws://<服务器IP>` + compose web 服务同步 + `docker compose up -d web` + 强刷。
- 完整细节见 M06 教材。

## 5. Ollama（本地模型运行时，可选但推荐）

| 用途 | 说明 |
|---|---|
| bge-m3 embedding | 语义缓存向量化（LiteLLM redis-semantic）+ Dify 本地 embedding（1024 维中文） |
| 本地推理（可选） | 内网无外网时跑本地模型 |

- 安装：`irm https://ollama.com/install.ps1 | iex`（Windows）；或官网下载。
- 拉模型：`ollama pull bge-m3`（embedding 模型）。
- 容器访问宿主机：`http://host.docker.internal:11434`（Docker Desktop 自动解析）。
- 平台内 `OLLAMA_API_BASE` 默认 `http://host.docker.internal:11434`。

## 6. 常见部署故障

| 问题 | 解决 |
|---|---|
| 容器一直 Restarting | `docker logs <容器名>` 看根因（常见：Ghost SQLite、Dify GRAPH_ENGINE、端口冲突） |
| 镜像拉取慢/失败 | 配置镜像加速器；GitHub 资源用代理/镜像；presidio 约 965MB 需耐心 |
| WSL2 IPv6 问题 | 一律用 `<服务器IP>` 或 127.0.0.1，不用 localhost（LiteLLM 用内网 IP） |
| `docker compose up -d` 不生效 | 改 .env 后必须 `up -d`（不是 restart），restart 不重读环境变量 |
| 端口被占用 | `netstat -ano | findstr 端口` 定位占用进程；改 compose 端口映射 |
