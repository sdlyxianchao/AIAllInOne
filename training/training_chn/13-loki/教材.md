# Loki + Promtail 教材（M15 · 统一日志）

> 端口：Loki `3110`（内部，经 AI 管理中心查询）；Promtail 无对外端口（docker.sock 发现容器 + 采集 `/var/lib/docker/containers/*/*-json.log` 推给 Loki）。

## 1. 架构

```
各容器日志(json-file driver) ──> Promtail(docker_sd 发现 + 打标签) ──> Loki(:3110 存储查询)
       └── AI 管理中心「📜 统一日志」页（LogQL 查询）
```

Loki 设计哲学：**只索引标签（labels），不索引日志内容**，资源占用远低于 ELK（实测三组件内存约 135MB 量级）。单机用 `store: tsdb` + filesystem 对象存储（2.9.x 稳定）。

## 2. 统一日志查询（AI 管理中心）

路径：AI 管理中心 → **📜 统一日志**：
- 容器下拉选择 → 关键字 → 时间范围 → 查询。
- 后端 `/api/logs/query` 用 LogQL 查 Loki。
- 典型场景：某容器报错、按关键字搜"error"、按时间段回溯故障。

## 3. LogQL 基础

```
{container="new-api"}                # 按标签筛选
{service="litellm"} |= "error"      # 再按关键字过滤
{job="docker"} != "healthcheck"      # 排除
rate({container="new-api"}[1m])      # 日志速率（可画图）
```

## 4. 关键配置（monitoring/promtail.yml）

- `docker_sd_configs`：经 docker.sock 发现容器，自动打 `container` / `service` / `project` 标签。
- ⚠️ **Docker Desktop 挂载坑**：Promtail 需挂 `/var/run/docker.sock` 和 `/var/lib/docker/containers`（WSL2 虚拟机内路径，正好是容器日志所在）；**不要**用宿主机 Windows 的 `C:\...\containers` 路径映射。
- Loki 单机 `loki.yml`：filesystem 存储、`replication_factor: 1`、inmemory ring。

## 5. 常见问题

| 问题 | 解决 |
|---|---|
| 统一日志页查不到某容器 | 检查 Promtail 是否采集该容器（docker_sd 标签）；时间范围；关键字 |
| Promtail 启动报挂载错误 | 检查挂载路径是否为 Docker 虚拟机内路径 |
| 日志查询慢 | 缩小时间范围；用标签而非全文匹配 |
| 磁盘增长快 | Loki 单机 filesystem 数据卷规划；配置 retention |
