# AI 管理中心 教材（M11 · 统一管理门户）

> 平台内 AI 管理中心端口 `10086`（容器 `admin-portal`），源码 `../../windows/admin-portal/`（`server.js` 后端 + `public/index.html` 前端），会话存 Redis（`admin-session-redis`）。

## 1. 定位：不是 Docker 管理平台

调研过 Organizr / Dashy / Homarr / Heimdall 等面板后自研，核心差异：

| 需求 | Organizr | Dashy | AI Admin Center |
|---|---|---|---|
| Keycloak OIDC 登录 | 插件（非原生） | 支持 | ☑ 原生 |
| 侧边栏 + iframe 嵌入 | ☑ | 部分 | ☑ |
| Docker 容器状态监控 | 不支持 | Widget | ☑ 实时 |
| 统一管理 Keycloak 管理员账号 | 不支持 | 不支持 | ☑ |
| Global Admin 初始配置 | 不支持 | 不支持 | ☑ |

## 2. 初始化（Global Admin）

1. `.env` 配置：`ADMIN_USERNAME=ai_all_in_one_admin`、`ADMIN_PASSWORD`、`ADMIN_EMAIL=ai_all_in_one_admin@<公司域名>`。
2. 启动后自动在 Keycloak 创建该用户（有则跳过）并分配 `ai-platform-admin` Realm Role。
3. Keycloak 创建 OIDC Client：`AI-all-in-one-admin-portal`（Client authentication On、Standard flow On、redirect URIs 含 127.0.0.1 与内网 IP）→ 复制 Secret → 填 `.env` 的 `KEYCLOAK_CLIENT_SECRET` → `docker compose up -d admin-portal`。
4. 在 Dify、Ghost、NewAPI 也创建同名 `ai-platform-admin` 角色，实现跨平台统一管理员。
5. ✅ 验证：未登录访问 `http://<服务器IP>:10086` → 302 到 Keycloak 登录页（**不应**显示空看板）。

## 4. 管理员分模块授权（重点）

全局管理员（ai-platform-admin）在「管理员账号管理」页：

1. **添加管理员**：从 Keycloak 关联 IdP 搜索账号（AD 用户无需建号/密码）→ 勾选模块 → 确定。
2. 系统自动做两件事：
   - 加 `admin:<产品>` Realm Role（控制其在 AI 管理中心能看/能操作哪些模块）；
   - **真实开通到产品**（SSO 优先、API 兜底）：Gitea / NewAPI / Dify / Ghost / Grafana / LiteLLM / Keycloak / Langfuse 逐个 provision，失败不阻塞其他产品。
3. **撤销/删除**：撤销 `admin:<产品>` 角色 + 从产品删除账号（SSO 产品撤销授权、API 产品删账号）。
4. 无 SSO 产品建号时生成临时密码，列表 🔑 图标可回看（仅全局管理员）。
5. 非管理员登录 → 直接弹「你不是管理员」并退出。

**产品侧授权/撤销对照表**（了解）：
| 产品 | 授权方式 | 撤销 |
|---|---|---|
| Gitea | SSO 自动建号设管理员 | 删 Gitea 账号 |
| NewAPI | SSO 自动建号 + role=10 | 删账号 |
| Dify | Console API 邀请 admin | 删成员 |
| Ghost | Admin API 邀请 staff(Administrator) | 删 staff |
| Grafana | 建全局号 + org Admin(SSO) | 删账号 |
| LiteLLM | master key 建 proxy_admin | 删账号 |
| Keycloak | realm-admin 复合角色 | 撤销角色（不删账号） |
| Langfuse | 写 Postgres memberships=ADMIN | 删 membership |

## 5. 备份与恢复

- 页面「💾 备份与恢复」：备份列表 → 立即备份 → 恢复（后端经 docker.sock + 挂载 `C:\AIAllInOne\backups`）。
- 与脚本 `backup.ps1` 同格式（NewAPI MySQL / Dify PostgreSQL / Ghost SQLite / Gitea SQLite / 配置文件）。
- ⚠️ 二进制安全：AI 管理中心备份用 base64 中转 + tar-fs/putArchive（`docker exec` stdout 走 utf8 会损坏 SQLite .db）。
- ⚠️ 恢复脚本需 `yes` 确认（-Force 跳过）；建议定期把 backups/ 同步到其他盘/对象存储（异地容灾）。

## 6. 可用性测试（16 项）

默认每 10 分钟（`AVAILABILITY_INTERVAL_MIN` 可调）+ 手动「测试所有」+ 单项测试。覆盖：Keycloak 认证 / NewAPI / LiteLLM / DSH Desktop·Dify 聊天（经 NewAPI 发真实对话）/ Ghost / Gitea / MCP / Prometheus / Grafana / Langfuse / Loki / Presidio / SSO / 更新服务器 / 备份 / Docker / Redis。每项卡片下方输出结果与关键日志。

## 7. Ghost 免登录（了解）

点「Ghost 后台」的「打开」时，后端 `/api/ghost/auto-login`：密码登录 → 读 `admin_session_secret` + userId 本地算 TOTP（HMAC-SHA1，与邮件码一致）→ `/session/verify` → 写 cookie → 跳转后台，全程无感。⚠️ 别短时间反复刷（/session/verify 有 brute 限流）。

## 8. 常见问题

| 问题 | 解决 |
|---|---|
| 打开首页没有登录界面、接口全 401 | 首页必须走 Keycloak 保护：`express.static(..., {index:false})` + `app.get('/', keycloak.protect())` |
| 重启容器登录会话丢失 | 会话在 admin-session-redis，不应丢；检查 Redis 容器 |
| 统计 Dify 数据为空 | 邮箱必须用 Dify 实际管理员邮箱（`ai_all_in_one_admin@<公司域名>`） |
| 某产品统计页失败 | 单个产品失败不影响整体；看对应数据源（API/sqlite/容器） |
| 管理员看不到某模块 | 缺 `admin:<产品>` 角色 |
| 界面改前端不生效 | index.html 改完刷新即可；server.js 需 `docker restart admin-portal` |
